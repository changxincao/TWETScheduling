# 第二机内存128降至64的只读核查

主要结论：DESKTOP-42976CD / 100.68.243.192以前确实可见约128GiB，不再只是依据Java默认堆推测。当前固件仅上报DIMM1、DIMM2各32GiB，DIMM3、DIMM4均报告未安装，总计64GiB；Windows可见63.6941GiB与其吻合。问题应优先定位到插装/固件枚举层，而不是Java分配上限。尚未确认两条内存被移走、接触/硬件故障或BIOS内存训练/识别问题中的具体一种，不能远程直接认定“内存坏了”。

## 1. 历史128GiB的直接证据

只读取该机既有实验根目录hs_err原始日志，没有重新运行旧算例。同一D:\ccx工作树、i9-14900K和Windows11环境在多个日期均记录`Host: ... 127G`和`system-wide physical 130758M`，即约127.69GiB总物理内存，而非可用内存或虚拟堆。

| 原日志路径（D:\ccx\work1\experiments下） | 日志内部时间 | 系统总物理内存 |
| --- | --- | --- |
| `20260907-formal-n80-n100\hs_err_pid21464.log` | 2026-09-08 13:18:16 | 130758MiB |
| `20260913-ng-fixing-cutset-le50\hs_err_pid15996.log` | 2026-09-21 15:25:25 | 130758MiB |
| `20260914-balanced-family-ng-n50\hs_err_pid39528.log` | 2026-09-24 19:04:12 | 130758MiB |

因此至少到9月24日仍识别128GiB；11月4日本批原始hs_err已记录63G，且本次两种Windows接口独立确认64GiB。变化发生的具体重启/日期尚未确定，不能归因于本次启动或代码更新。9月日志中已有JVM崩溃，即使当时识别128GiB也会发生，因此不能反过来把本次C2崩溃简单解释为丢失内存造成。

## 2. 当前固件识别结果

常规CIM查询Win32_PhysicalMemory等被SSH账户权限拒绝，改用内存中的Reflection.Emit调用Windows GetSystemFirmwareTable读取RSMB。没有Add-Type落盘编译、驱动安装、注册表写入、服务修改或系统目录写入。原始SMBIOS按DMTF Type17的Size/Extended Size和字符串索引解析，包含长度及边界检查；Size=0按规范解释为该槽未安装/未识别，不能当成实地观察到空槽。

| 槽位 | 固件上报容量 | 模块型号 | 标称/配置速率MT/s |
| --- | ---: | --- | --- |
| DIMM1 | 32GiB | 99P5782-080.A00G | 5600 / 4400 |
| DIMM2 | 32GiB | 99P5782-080.A00G | 5600 / 4400 |
| DIMM3 | 0，报告未安装 | 空 | 0 / 0 |
| DIMM4 | 0，报告未安装 | 空 | 0 / 0 |

SMBIOS物理数组报告4槽、最大支持128GiB；最大支持容量不是当前已安装容量。当前机型Dell OptiPlex Tower Plus 7020，主板0Y7V6M/A00，BIOS 1.24.0，日期01/27/2026。只读注册表信息与固件表一致。结构化解析结果保存在`docs/logs/data/20261104-second-host-smbios-memory.json`，未保存或发布不必要的机器序列号。

另一个原生接口GetPhysicallyInstalledSystemMemory返回67108864KiB，即64GiB；ComputerInfo返回68391063552字节，即Windows可见63.6941GiB，两者仅差正常保留域。当前启动选项字符串未出现MAXMEM，但bcdedit只读枚举被拒绝，不能声称完整检查了所有BCD设置。即便BCD暂未读到，固件本身只枚举64GiB，仍不支持“只是Java或Windows将完整128GiB限为64GiB”的简单解释。

方法依据：[Microsoft GetSystemFirmwareTable](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemfirmwaretable)、[DMTF SMBIOS Type17规范](https://www.dmtf.org/sites/default/files/standards/documents/DSP0134_3.2.0.pdf)。

## 3. 已知边界与后续

目前可以确认“曾识别128GiB，现在固件只枚举2×32GiB”；不能确认内存实际是否仍插着4条32GiB。若实物仍有4条，则两条没有被固件正常枚举；原因还需在允许停机时检查插装、BIOS槽位识别及硬件诊断。此时不应直接改Java参数、解除Windows限制或执行在线内存压力测试来冒充修复。

全部操作只读。最后回读第二机SOLVE_RUNNING，scheduler9064及5个solver仍在；没有终止、重启、清理任务或修改BIOS/系统。第一台未连接，第三台不做硬件改动。
