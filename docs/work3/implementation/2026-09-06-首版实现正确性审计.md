# Work 3 首版实现正确性审计

日期：2026-09-06

## 1. 结论

本次按 `implementation/` 下三份 2026-09-06 规格逐式核对独立工程 `D:\软件\eclipse\workspace\StochasticDueWindowScheduling`。两个基础模型的核心数学语义正确：2-index 的路径、紧 \(M\) 时间传播、窗口和 ET 目标与规格一致；P-W 的任务—位置分配、连续 \(u,z\)、wide dummy、无条件时间递推、绝对窗口和目标展开也一致。2-index SEC、P-W 聚合 SEC、显式 \(C\) 上下界和显式 \(c\) 上界均未进入基础模型。

当前实现对应的是 README 明确指定的“共同 \(\rho,\lambda,\alpha,\beta\) 首轮双模型比较”，不是较早文档中的 W3-FullHet。该口径由 2026-09-06 实现规格覆盖 2026-08-31 的一般化方案，因此标量费率在当前原型中不是漏实现；若以后恢复 FullHet，需要另行修改数据结构和 position 表示，不能把当前 P-W 直接称为全异质模型。

审计没有发现基础模型的阻断性建模错误，但发现一处必须在正式实验前修正的有效不等式系数边界问题，以及三处验证完整性缺口。当前代码适合继续做小规模联调，不应直接作为正式实验版本冻结。

## 2. 必须修正的问题

`InstanceData.minimumWindowAndTardinessCost` 在判断固定 \(b\) 后应采用哪个左端点时使用了

```java
locationRate >= widthRate - EPS
```

而数学规格要求精确区分 \(\rho\ge\lambda\) 与 \(\rho<\lambda\)。当 \(\lambda-\mathrm{EPS}<\rho<\lambda\) 时，代码会错误进入 \(\rho\ge\lambda\) 分支，选择较小的 \(a\)，从而可能把真实的最小费用算高。该值随后用于 A-VI、VI-1 和 VI-2；费用“下界”一旦被高估，就可能切掉合法整数解或最优解。

这是数值边界问题，不影响当前随机生成器使用的 \((\rho,\lambda)=(1,1.5)\)，但对以后读取任意算例不安全。修复时不应简单扩大容差，建议同时评价固定 \(b\) 下的两个合法端点并取较小目标值，或使用精确符号分支；场景折点和窗口拐点也应直接裁剪到合法区间后加入候选集合，重复候选无害，不应通过模糊排除牺牲下界方向的可靠性。

## 3. 验证与防回归缺口

### 3.1 预处理断言未完整实现

任务—位置最短/最长 walk、不同任务加工量界、前缀 \(H_{k\omega}\)、跨场景 \(H_k\)、任务级聚合界和弧 \(M\) 的实现方向均正确。当前代码只检查了 \(\underline C_{jk\omega}\le\overline C_{jk\omega}\)，尚未实现规格要求的以下自动断言：

\[
H_{k\omega},H_k\text{ 随 }k\text{ 非降},\qquad
\overline C_{jk\omega}\le H_{k\omega}\le H_k,
\]

\[
H_{k\omega}\le H^{\mathrm{coarse}}_{k\omega},
\]

以及小规模枚举排程对任务—位置界的核验。现有公式静态核对没有发现错误，但这些断言决定紧 \(M\) 和 wide dummy 是否安全，应在正式算例读取前补齐。

### 3.2 解验证器不完全独立

现有验证器使用求解器返回的 \(E,T\) 重算目标，并检查

\[
E\ge a-C,\qquad T\ge C-b,
\]

但没有独立重算

\[
E=(a-C)^+,qquad T=(C-b)^+.
\]

同时，它主要通过路径中的任务总数检查覆盖，没有完整核对任务唯一性、机器数、原始 \(x/y/z\) 与提取序列的一致性。正 ET 费率下的最优解通常会自动令 \(E,T\) 取紧，因此目前小算例没有暴露问题；但 `solutionValidated=true` 尚不能解释为完全独立的原模型验证。

### 3.3 Runner 的“一致”判定需要区分求解状态

`RandomInstanceRunner` 只要求四个模型都有 incumbent、现有验证器通过且 incumbent 目标相同，随后输出 `All formulations agree`。若将来较大算例全部在时限处停止，相同 incumbent 不能证明最优值等价，不同 incumbent 也不能证明模型不等价。正式对拍应要求至少一个已证最优参考值，并检查其他模型的 bound/gap；没有证优时只能记录“当前 incumbent 一致”或“验证未完成”。

## 4. 已核对正确的实现

1. 2-index 中每个任务恰有一条进入和离开弧，源路径数等于终点路径数且不超过 \(M\)。严格正加工时间与激活时间传播排除整数任务环，因此当前不加 SEC 不改变整数可行集。
2. 2-index 的首任务与任务弧时间约束代数符号正确；任务完成时钟只有非负下界，预处理界没有被设置成显式变量界。
3. P-W 的 prefix occupancy 与 \(z\) 连接保证整数 \(y\) 下的 \(u,z\) 自动取 0/1；空位置被唯一封闭为 \([0,H_k]\)，dummy 时间可以继承最后一个真实时钟且存在零 dummy ET 的最优代表解。
4. P-W 窗口成本的展开在真实位置恢复 \(\rho(A-L_j)+\lambda(B-A-D_j^{\min})\)，在 dummy 位置严格为 0。
5. A-S2、A-S3、A-VI、VI-1、VI-2、TLB-1、TLB-2、简单迟到下界、机器负载/位置排序和 P-U2/P-U3 的代码符号与当前规格一致。
6. 随机生成器产生场景相关加工时间、随机序列相关 setup 时间和确定 setup 金额；默认费率避开当前已记录的充分退化条件，但这只排除参数导致的必然边界结构，不保证每个随机实例都出现内部正长度窗口。

## 5. 动态验证

当前源码使用 Java 22、CPLEX 22.1.1 和 `-Xlint:all` 重新编译通过。在原有 7 组联调实例基础上，本次增加 10 组 \(n=4\) 至 8、单机至 4 机、1 至 5 场景的随机对拍，并增加 4 组定向算例，覆盖非均匀场景概率、\(\rho\ge\lambda\)、\(D_j^{\min}=0\)、单机和每任务一台机器。最后又从当前源码重新编译并运行 1 组独立随机算例。共核对 22 组实例；每组的 2-index 基础/强化和 P-W 基础/强化 incumbent 目标一致，现有验证器均返回 `true`。

该结果是较强的一致性证据，但不是数学等价性的替代证明，也不能覆盖上述 EPS 边界和验证器自身的盲区。
