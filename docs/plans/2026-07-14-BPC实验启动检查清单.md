# BPC 实验启动检查清单

本文档记录 2026-07-14 启动 60-2 实验时暴露的问题。后续启动 BPC、ng-DSSR、time-indexed、SRI 或对比实验前，先读本文件，再按固定流程执行。目的不是多加防御，而是避免因为 classpath、编译产物、重定向、重复启动造成无效实验。

## 1. 本次启动中犯的错误

1.1 classpath 没有先验，导致旧 `.class` 被加载。

60-2 的旧命令使用了 `-cp src;...`。`src` 下残留了大量旧 `.class`，其中 `GCNGBBStyleBidirectionalNgDssr.class` 是 7 月 2 日的旧版本，不包含后续实现的 `joinEnvelopePrefilter` 和 `IncrementalSourcedDominanceGraph`。因此当时虽然以为在跑最新 ng-DSSR，实际加载的是旧类。

正确做法是先检查命令文件，确认 classpath 为：

```text
-cp target\classes;src;...
```

`target\classes` 必须排在 `src` 前面。`src` 只作为源码路径保留，不应承担运行时 class 输出目录。当前已经删除 `src` 下残留 `.class`，但以后仍然要检查 classpath，不能依赖“刚好没有旧文件”。

1.2 生成命令后没有先 dry-run 检查关键开关。

从 50-2 命令迁移到 60-2 时，必须先检查这些关键项是否符合本次实验口径：

```text
data\60-2
wet060_001_2m
target\classes;src
incrementalSourcedDominance=true
ngDssrJoinEnvelopePrefilter=true
timeIndexedPreHeuristicPricing=false
timeIndexedPreHeuristicInStrongBranchingPhase2=false
```

不能只看目录名和实验名。尤其是 `timeIndexedPreHeuristicPricing` 曾经在若干命令中被显式打开，而当前“最好 ng-DSSR 配置”默认不应打开它。

1.3 启动入口混乱，导致同一个输出目录被多个进程并发写入。

本次先用 `run.cmd` 启动失败后，又直接拼 `cmd /c "<java ... > log"` 启动；后来发现实际存在 4 个 Java 进程，说明旧启动并没有完全失败。两个启动口径可能同时写同一目录，导致该目录结果不可用。

以后同一轮实验只允许一个启动入口：写好 `run.cmd`，再用 `Start-Process cmd.exe /c run.cmd` 启动。不要在不确认旧进程已经停止的情况下换另一种方式再启动同一目录。

1.4 `Join-Path` 写法错误后仍继续启动。

PowerShell 的 `Join-Path` 不能写成 `Join-Path $base $dir 'run.cmd'`。这会报：

```text
Join-Path : A positional parameter cannot be found that accepts argument 'run.cmd'.
```

正确写法是嵌套：

```powershell
$run = Join-Path (Join-Path $base $dir) 'run.cmd'
```

如果启动脚本生成或启动命令报错，本轮目录必须视为不干净；不要继续在同一目录上补启动。

1.5 stdout/stderr 路径没固定为绝对路径。

先前 `run.cmd` 中使用相对重定向，导致日志位置判断混乱。以后 `run.cmd` 必须写绝对日志路径：

```cmd
java ... > "D:\软件\eclipse\workspace\TWETScheduling\test-results\bpc\...\stdout.log" 2> "D:\软件\eclipse\workspace\TWETScheduling\test-results\bpc\...\stderr.log"
```

这样无论 `WorkingDirectory` 如何，日志位置都唯一。

1.6 编译 argfile 处理不规范。

用 `javac @sources.txt` 时踩了两个坑：

第一，`Set-Content -Encoding UTF8` 在 Windows PowerShell 5 里会写 BOM，`javac @argfile` 可能把第一行识别成带 BOM 的非法文件名。

第二，`-Encoding ASCII` 写绝对路径时，仓库路径中的中文会被替换成 `??`，同样无法编译。

正确做法是使用相对路径写 ASCII argfile：

```powershell
$srcList = 'target\codex-sources.txt'
$root = (Get-Location).Path
Get-ChildItem src -Recurse -Filter '*.java' |
  ForEach-Object { $_.FullName.Substring($root.Length + 1) } |
  Set-Content -Encoding ASCII $srcList

javac -encoding UTF-8 `
  -cp "target\classes;D:\软件\cplex\ILOG\CPLEX_Studio2211\cplex\lib\cplex.jar;D:\软件\cplex\ILOG\CPLEX_Studio2211\cpoptimizer\lib\ILOG.CP.jar" `
  -d target\classes "@$srcList"
```

如果只是确认运行最新类，优先检查 `target\classes` 的时间戳和关键字符串；不要在启动前临时反复试编译，除非确实修改了源码并需要重新编译。

1.7 进程停止方式过粗。

本次为了止损直接停掉了所有 Java 进程。以后不应这么做，除非已经确认机器上没有其他 Java 任务。启动时必须保存 `cmd.exe` 的 PID；停止时用进程树杀掉该启动入口：

```powershell
taskkill /PID <cmdPid> /T /F
```

这样只停止本次实验的 cmd 和其 Java 子进程，不误杀其他任务。

## 2. 标准启动流程

2.1 启动前检查

先确认没有残留 Java 或同名实验目录正在运行：

```powershell
Get-Process java -ErrorAction SilentlyContinue |
  Select-Object Id,CPU,StartTime,ProcessName
```

如果需要停止上一次实验，优先用保存的 cmd PID：

```powershell
taskkill /PID <cmdPid> /T /F
```

不要直接 `Stop-Process java`，除非已经明确要清空全部 Java 求解。

2.2 确认 classpath 和关键类

命令文件必须包含：

```text
-cp target\classes;src;...
```

启动前至少检查：

```powershell
cmd /c findstr /m /c:joinEnvelopePrefilter target\classes\TWETBPC\GC\GCNGBBStyleBidirectionalNgDssr.class
cmd /c findstr /m /c:IncrementalSourcedDominanceGraph target\classes\TWETBPC\GC\GCNGBBStyleBidirectionalNgDssr.class
```

如果查不到，说明没有编进最新实现，不能启动实验。

2.3 生成新目录

每次失败启动后都换新目录，不复用已被写过的目录。例如：

```text
test-results\bpc\exp-60-2-ng-best-latest-001-20260714c
test-results\bpc\exp-60-2-ti-best-latest-001-20260714c
```

如果某目录发生过重复启动、classpath 错误、Java 报错或日志混乱，该目录只保留为故障证据，不作为实验结果。

2.4 写入 command.txt 和 run.cmd

`command.txt` 保存完整 Java 命令，便于复核。`run.cmd` 只负责进入仓库根目录并执行该命令，stdout/stderr 使用绝对路径。

`run.cmd` 的形态应固定为：

```cmd
chcp 65001 >nul
cd /d "D:\软件\eclipse\workspace\TWETScheduling"
java ... -cp target\classes;src;... HEU.GCBBFullDomainComparisonTest > "...\stdout.log" 2> "...\stderr.log"
```

2.5 启动

只用一个入口启动：

```powershell
$proc = Start-Process -FilePath 'cmd.exe' `
  -ArgumentList @('/c', '"D:\...\run.cmd"') `
  -WorkingDirectory 'D:\软件\eclipse\workspace\TWETScheduling' `
  -WindowStyle Hidden `
  -PassThru

$proc.Id
```

启动后立刻记录 cmd PID。后续停止使用：

```powershell
taskkill /PID <cmdPid> /T /F
```

2.6 启动后 30 秒内验证

启动后必须检查三件事：

第一，日志文件正在增长：

```powershell
Get-Item "...stdout.log","...stderr.log" |
  Select-Object FullName,Length,LastWriteTime
```

第二，ng-DSSR 日志里能看到新实现字段：

```text
config.useIncrementalSourcedDominanceGraph=true
joinEnvelopePrefilter ...
incrementalSourcedGraph ...
```

第三，pricing engine 与实验口径一致。当前 no-SRI ng-DSSR 最好配置应看到：

```text
GCNGBBStyleNgDssrPricing
HeuristicPricing
```

不应看到 `TimeIndexedPreHeuristicPricing`，除非本轮明确测试该组件。

纯 time-indexed 配置应看到：

```text
TimeIndexedGraphPricing
ngDssr=false
enableHeuristicPricing=false
```

## 4. 结论

本次问题不是算法配置本身，而是启动流程没有工程化：旧 `.class`、错误 classpath、重复启动、相对日志路径和编译 argfile 编码问题叠加，导致实验状态不可复现。后续任何正式实验都必须先读本检查清单，按“检查 classpath -> 新目录 -> 单一 run.cmd -> 记录 cmd PID -> 30 秒验证日志字段”的顺序执行。

## 4. 2026-07-14 追加：不要用 ASCII 写含中文路径的 run.cmd

50-3 原始算例第一次启动 `20260714a` 时，虽然命令逻辑正确，但 `run.cmd` 使用 `Set-Content -Encoding ASCII` 写出，导致 `D:\软件\...` 被替换成 `D:\??\...`，两个进程立即失败且没有有效 stdout/stderr。该目录不能作为实验结果。

因此，后续如果继续使用 `run.cmd`，不能用 ASCII 保存含中文绝对路径的脚本。更稳妥的方式是直接从 PowerShell 调用 `Start-Process java.exe`，用参数数组传入 classpath、library path 和所有 `-D` 配置，并用 `-RedirectStandardOutput` / `-RedirectStandardError` 写日志。这样可以避免 cmd 文件编码、BOM 和中文路径三类问题。若必须保留 `run.cmd`，需要单独验证 UTF-8 文件在当前 `cmd` 入口下能正确识别中文路径，不能只看文件生成成功。

## 5. 2026-07-15 追加：PowerShell 参数数组不能合并成一个 quoted 字符串

本轮 50-3 timeX10 实验复盘时再次确认，不能把多个 `-D` 属性先拼成一个长字符串再传给 Java。`command.txt` 中如果出现类似下面的形态，就说明记录口径已经不干净，不能作为后续复用模板：

```text
"java.exe" "-Djava.library.path=... -Dtwet.xxx=... -Dtwet.yyy=..." "-Dtwet.zzz=..." -cp ...
```

正确方式是让每一个 `-Dkey=value` 都是独立 `ArgumentList` 元素，并把实际数组逐行写入 `args.txt`。直接启动时还必须显式带 native CPLEX 路径，例如当前工作区优先使用：

```text
-Djava.library.path=D:\软件\eclipse\workspace\TWETScheduling\tmp_lib
-cp target\classes;src;tmp_lib\cplex12.jar
```

如果使用系统 CPLEX 安装路径，也必须确认 `cplex1263.dll` 可被找到。缺少 native path 会直接报 `UnsatisfiedLinkError: no cplex1263`，这种 run 不是算法结果。正式实验目录中至少应包含 `args.txt`、`stdout.log`、`stderr.log` 和 case log；启动 30 秒内需要检查日志中是否出现预期的关键开关，例如 `incrementalSourcedGraph`、`joinEnvelopePrefilter`、`TimeIndexedGraphPricing` 或 `GCNGBBStyleNgDssrPricing`。
## 6. 2026-07-15 追加：短 A/B 也必须复用已验证的多机 case 与 run.cmd

本次硬窗预判 A/B 首次直接从 PowerShell 拼接 Java 命令时，`-Dfile.encoding=UTF-8` 被错误拆成主类参数，Java 实际未启动；随后误用 `data/40-1/wet040_001`，又在多机 loader 中于求解前失败。这两次都不是算法结果。正式短实验仍应先生成唯一 `run.cmd/command.txt`，再使用已经被 `GCBBFullDomainComparisonTest` 验证过的多机 case，例如 `data/40-2/wet040_001_2m`。启动后必须先确认 case log 已出现 node/pricing 内容，不能只根据进程存在判断实验有效。
