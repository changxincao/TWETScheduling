## 3. fixing与更早主线的关系

旧NG-DSSR借鉴TI做scalar arc-fixing，用当前dual和UB扫描时间域，安全删除不可能改进的时空弧。其旧实现按整个CmaxH建数组并递推，而任务窗口实际结束后的一大段尾部没有新的任务加工弧，仍发生初始化、等待递推及扫描；子节点反复运行进一步累积开销。有效horizon裁剪、dual快照、热循环合并和删除graph fixing后的重复scalar调用，属于同一次fixing内部的等价性能优化，已对拍禁弧集合/窗口一致。例如两个旧random/high/wide实例的累计fixing约75→17.92秒、49.26→13.24秒，这两组不是靠开启root-only取得的。

root-only是另一个策略轴：根节点已有的禁弧继续继承，但不再在每个子节点按新dual运行额外scalar强化。它减少开销，也可能少删一些子节点弧，所以需要A/B比较，而不是把它描述成完全无代价的等价提速。NG自身completion bound和正常exact certificate并未关闭。

第二机A--D均在上述优化后的v8之下：A/C仍在各节点做优化后的fixing，B/D仅根节点；C/D另外开supernode CutSet。与之对比，更早已经有正式NG主线：第一机Arc638项、第三机Cluster166项、第二机n80 Arc47场景，使用旧v5/v6和旧fixing，后来暂停继续扩展以先确定新配置。旧模型/elementary定价不是因此全部作废，但旧完整时间含冗余辅助开销，且n50/n60 family数据后来换过F3，不能把旧主线时间直接拼成当前新版B结果。807项来自优化后的第二机B，并非从638/166/47中挑选旧时间。

## 4. 纯调度、fixing开销和版本的进一步说明

本批不含外包。正式清单未传outsourcingModel，正式输入为纯调度文件。Data未读到外包报价时将outsourcingCost设为big_M，LP相应y变量上界为0；因此保留通用类/seed格式中的外包字段并不表示存在外包选择，也不引入外包列定价。此前验收中提及outsourced只是检查通用seed内容，不应把它描述成这批实验的另一个模型因素。

scalar fixing是辅助剪枝，不是NG的PWLF exact labeling。它在离散状态(lastJob,t)上计算乐观前缀/后缀成本，用UB与当前节点下界的余量判断时空弧能否排除。旧实现用完整CmaxH分配两方向距离数组、罚函数表，并在t=0..CmaxH逐层扫描。任务不能在有效完成窗口以外加工，并不等于循环停止：computeForwardDistances仍可把有限前缀通过等待边传向t+1，然后逐任务尝试next并拒绝越窗加工；backward也先扫描层和等待传播，再尝试并拒绝加工转移。即使部分状态不可达而跳过，数组初始化和外层时间/任务扫描仍存在。

现在effectiveHorizon取请求horizon与所有任务有效完成窗口上界最大值的较小值（按整数时间取整）。最后任务可以立即连sink，全部任务窗口结束后继续等待不产生更好的可行排程，因此无需保留该尾部。这是从辅助DP删掉无用等待域，不是砍掉合法任务加工时间，也不是修改原始数据CmaxH。

每个子节点重复做的准确含义是：主树节点完成CG且未被整数解或incumbent剪掉时，every-node设置允许在该节点用新的dual重新构建上述scalar前后向表并fixing；不是每次pricing、每轮DSSR都做。父节点禁弧会继承，但父节点的dual距离表不能直接冒充当前节点表。故单次耗时乘许多待分支节点后累积很大。root-only仅将这项额外强化限制在根；正常NG completion bound仍保留。

优化分开两层：同一次调用的等价实现优化包括有效时间域裁剪、对偶值快照、合并窗口扫描、避免已知未设置禁弧的重复查询，以及删除临时root在graph fixing后没有新增作用的scalar调用；是否在子节点再次运行则是A/C与B/D比较的策略差异。前者已对拍同一禁弧/窗口结果，后者允许子节点少做额外强化，不能当作完全相同的剪枝集合。
