## 1. 已确认的问题

### 1.1 NG：小数 horizon 最后一格的 scalar CB 误剪（P1）

`GCNGBBStyleBidirectionalNgDssr.java:6295` 仅在后向 frontier 尾端等于本轮 H 时使用 `forwardUMin`，其余情况查询 `forwardUBeforeCeil(P)`。`CompletionBoundCalculator.java:1027` 的缓存只填写函数实际覆盖的整数时刻。当 `floor(H)<P<H` 时，`ceil(P)>H`，查询得到未填的 BigM；调用方却直接按不可补全剪枝，没有再做函数查询。

`ReviewDiagnostics.naturalFractionalPricing()` 使用正常三任务纯调度输入：加工时长均 1，due 为 17、17、8，权重均 1；setup/setup-cost 在输入块中提供，Data 自然得到 H=22。固定实际 LP 字段中的合法符号对偶快照 `pi=(0.4,0.5,0.5)`、machine/arc dual=0；不是从完整 RMP 求出的对偶。NG 的 clean-root dual window 自然生成窗口右端 17.4、17.5、8.5，本轮 H=17.5、Tmid=12.5。两组只切换 scalar pruning：

| scalar pruning | 返回列数 | 最小 RC 证书 | 独立评价合法列 `[1]` 的 RC |
| --- | ---: | ---: | ---: |
| 关 | 1 | -0.4 | -0.4 |
| 开 | 0 | 0 | -0.4 |

另外直接缓存对照确认 H=17.5 时查询 17.4 得 BigM 并误剪，H=18 时同一查询得到 0 且不剪。三任务例没有手工修改窗、horizon、PWLF 或 frontier，也不依赖零长度点、0.0005 补片或 EPS；这是一轮完整 NG pricing 的错误闭合，不是已经证明完整 BPC 会到达该 RMP 对偶的整树反例。

NG exact 的 dual-window 判断只读取 Phase-I 状态和 `PricingCompatibility`，不直接读取 heuristic/TI 的两个 window 开关。正式 profile 启用 TI root 预处理；实际写入继承禁弧或 compact window 后会关闭此窗口。对整数时长、粗窗 full 且有效右端仅为整数或 H 的调用，可排除这个尾格条件。但预处理开启不等于必然写入状态，不能据此宣布既有正式结果全部不受影响，也没有证据认定已在正式集合触发。本轮不扫描远端或宣布旧结果失效。

`git blame` 确认该查询及直接剪枝来自 2026-06/07 的代码，不是本次端点补丁或缓存释放新增。后续应局部修正越出物理域的查询语义，例如回退到安全的函数下界，而不是把所有 BigM 一概放行；还需同步核对采用相同查询的其他引擎入口。

### 1.2 NG 非默认 in-round helper：Phase-I 仍累加真实成本（P2）

`TimeIndexedScalarCompletionBound.build():193` 没有 Phase-I 门禁，`processArcReducedCost():1408` 总是累加真实 setup 和罚值；NG 本体此时把真实成本置零。节点深度大于 0、scalar enhancement 和 `timeIndexedCompletionBoundInRoundArcFixing=true` 同时成立时可达，NG 又取两类下界的较大值参与剪枝，因而真实目标下的较大估值不保证仍是 Phase-I 下界。

两任务正常 Data 自然得到 H=4：A 的 due-window 为 [0,3]，B 为 [1,1]，加工时长与权重均 1、setup 为 0、外包 baseline 均 3。局部 Node 固定为深度 3，禁止 A 直接接 sink，禁止两任务外包；固定对偶各 1、machine/arc dual=0，启用 repair 和 Phase-I。真实执行 helper 的 build、零 RC fixing 后，A 在 1 完成的后缀下界返回 **0**；可行后缀 A→B（B 在 2 完成）的 Phase-I RC 为 **-1**。这直接证明下界口径高估，但本例没有证明整轮误剪或完整树错误。

正式 profile 的 in-round 开关为 false，所以本项不据此影响当前正式配置。它也不是普通 TI/TI+SRI 的 Phase-I 实现错误，后二者的零真实成本切换已通过回归。最小修正可在该 helper 的本轮入口排除 Phase-I，或完整统一目标口径；本轮未实施。

### 1.3 TI/TI+SRI 可选无向 adjacency：presence 与 traversal 不一致（P2）

`LP.java:1164`、增列入口 1467 对无向 pair 使用“列是否含任一方向”的 0/1 系数；1879 行则把该行 dual 同时摊给两个方向。TI pseudo 路线 `[1,2,1]` 会扣两次 pair dual，但 master 系数只有 1。普通 directed Arc 使用访问次数，Cluster/CutSet 使用逐弧累计的 aggregate 系数，Successor 的内部弧和 OUT 系数也已核对，不存在这项差异。

诊断输入在 Data 文件中完整提供 setup-cost，所有列成本都由真实 evaluator 计算；实际求解含该 pair 右支的 RMP 后，pair dual=10，同一 pseudo 列的 **CPLEX RC=12，展开式 RC=2**，差值正好是多扣的一次 dual。没有手填假列成本，也没有在最终版本加载后修改 setup-cost。这里动态比较的是实际 master 与展开式 RC，不是实际 TI 整轮输出。

右支是 >=1 行，dual 非负，所以差异只把图 RC 压低，不能直接据此声称图证书或修正下界偏高。但真实成本复核不会修正这个系数，`LP.computeReducedCost` 同样采用展开式；假负候选可能占用有限候选位置并在 PC 中去重。是否由此遮蔽真负列、触发错误闭合，尚无动态反例。本项是已确认的接口不一致，不是已确认的正式整树错误。正式 profile 关闭无向 adjacency；默认 Arc/Cluster 不受这项影响。后续应继续保持此组合关闭，统一模型语义后再启用。

### 1.4 普通 TI：候选堆保留被替换的历史对象（P2，性能）

`TimeIndexedGraphPricingEngine.java:844` 更新同签名候选时，只替换 map 的当前值，仍向 heap 添加新对象。旧版本仅在成为堆顶且调用清理时移除；map 未满时可持续累积。因此 K 限制当前序列数量，不限制物理 heap 大小。

## 3. 正式流程中三个模块的区别

用户追问后再次沿正式配置和Tree调用核对：NG自己的PWLF completion bound及其整数缓存标量快筛正式开启（profile 194、196行）；TI根预处理也开启，但它在正式root之前独立运行（Tree 124行）；in-round TI helper则是在NG定价内部额外建图，正式关闭（profile 223行、NG 7077行）。关闭最后一项不代表关闭第一项，也不代表没有运行根TI预处理；收敛后的节点级TI fixing又由独立入口控制。

dual-window是按当前RMP对偶和任务罚函数临时收缩本轮负列搜索时间范围，不是数据里的zero/narrow/wide宽度，也不是Tmid。普通目标的clean root才允许使用；`PricingCompatibility`检查节点上实际的禁弧、cut、分支和compact-window记录，不检查“root预处理是否开启”这个配置值。根TI预处理在有证据时把安全禁弧和整数任务窗口复制给正式root，存在这些记录即关闭NG dual-window，但NG自身CB仍继续使用。

因此“正式调用CB”和“触发CB尾格错误”是两件事。对当前纯调度整数时间输入，在预处理实际写回状态、关闭dual-window，且有效右端只为整数或H的路径，可以排除已复现反例的触发条件；不能仅凭预处理开关为true就将所有实际调用归入该路径。例如graph fixing在UB-LB已闭合时会跳过，未必写回状态。本轮确认的是模块开启及调用顺序，没有新增逐份正式日志触发统计，也没有新的正式全流程反例；继续保留“已证实受控pricing错误，但正式结果是否触发未证实”的结论。此次仅补清说明，不修改源码或远端。

## 4. 尾格查询的最小修法（方案，未实施）

正式NG启用该检查，因此仍有条件性风险，不能用前置预处理代替修复。用户提出越界用0：不能通用采用，因为这里存的是扣除对偶后的reduced-cost下界，不是非负真实成本；合法前缀最小值可能小于0，此时用0可能高估，仍会误剪。当前反例的U恰好为0不代表一般也为0。

建议只在共享 `CompletionBoundCalculator.Bounds.forwardUBeforeCeil` 接收越出物理右端的整数查询：先按现有规则得到 q=ceil(P)，若q超过当前U函数实际右端，则返回已缓存的 `forwardUMin(job)`；否则维持原整数缓存读取。原有非法入参、空函数及真正不可行的处理保持，不把所有BigM都替换，也不向缓存盲填0。全域最小值允许选到时间上过晚的前缀，因此可能更松，但只会降低该前缀下界，不会高估可在P前完成的前缀；标量未剪时后续原函数CB仍按真实共同域判断。

全域最小值已在建表时缓存，回退为O(1)，不另建函数、不重算图。共享入口可覆盖现有NG及其它使用该查询的旧引擎，避免五个调用点各加不同补丁；不修改probe、DSSR、公共PWLF、TI定价或TI fixing。实施后需验证原三任务反例scalar开关结果一致、整数H/域内查询不变、负前缀值不被0替代，以及真实不可补全状态仍按原规则处理。此处仅确认修法并记录，未修改生产代码或运行新测试。
