# VRP 分支定价前沿与 TWET 可迁移性分析

日期：2026-08-24

## 1. 结论

这次检索重点核对了 DeLuxing、Cluster Branching，以及 2024--2026 年车辆路径分支定价中较有代表性的几条新路线。需要先区分三个容易混在一起的“聚类”：DeLuxing 聚类的是已经枚举出的列，用于寻找一次能安全删除很多列的 dual；Cluster Branching 聚类的是客户，用聚类间的总弧流构造更强的分支变量；Column Elimination 在 clustered VRPTW 上表现较好，但其核心不是聚类，而是从松弛决策图中逐步排除不可行路径。这三者的作用位置和改动规模完全不同。

结合当前 TWET 主线，最值得优先借鉴的不是重写定价流程，而是以下三项。

1. **Cluster Branching**：作为现有 arc branching 的补充候选，不增加 strong-branching 候选总预算。它的约束系数可以分解到转移弧上，现有 pricing 不需要增加资源维度，属于流程保持不变的低侵入试验。
2. **2LBB-dy 的候选筛选和动态预算思想**：当前主线按距 0.5 排序后固定测试最多 20 个候选，每个候选两侧都做 trial RMP。先记录便宜特征与真实 strong score，再做动态候选预算；有足够同分布训练数据后才考虑 XGBoost 排序。
3. **SRI unreachability dominance**：普通 PWLF SRI dominance 已有粗粒度 reachable-set 判断，但 time-indexed rank-1 定价仍对所有 residual 差异支付补偿。可以利用当前时间状态和 completion bound 证明某个 cut scope 后续不可达，从而放宽 dominance。这是 cut-heavy 定价中最贴近现有实现的一项。

DeLuxing 本身是可信且有效的方法，但不是当前第一优先级。它只在完整列枚举后发挥作用，而正式 profile 当前关闭 route enumeration；现有枚举还要求非 time-indexed、无 active SRI、gap 很小。更重要的是，论文在平均路线长度从约 7 增至约 15.6 后已经观察到 DeLuxing 效果明显下降，而 TWET 的单机序列通常更长。它适合留作“枚举成功后的列池缩减”独立试验，不能现在就当作通用 master 加速器。

Column Elimination、Local Area Routes 和 Graph Master 都更像独立算法路线。它们有研究价值，但会改变主问题或定价表示，不应混入当前稳定主线的近期优化。

## 3. DeLuxing：枚举列池上的安全深度固定

### 3.1 它解决的不是 pricing，而是枚举后的变量爆炸

DeLuxing 全称 Deep Lagrangian Underestimate Fixing。它不是 dual stabilization，也不负责找到新的负 reduced-cost 列。它的前提是已经完成 exact enumeration：给定当前整数上界与节点下界之差 `g`，已经枚举出所有 reduced cost 不超过 `g` 的列，因而原指数模型在当前节点可转成一个有限模型。问题随即从“列找不到”变成“有限模型仍有几十万或几百万个变量”。

设枚举列按当前 dual 的 reduced cost 分成 `R1={j: rc_j<=g/2}` 和 `R2={j:g/2<rc_j<=g}`。在整数解中，`R2` 至多有一个正变量；基于这一结构，论文构造一个只含 `R1` 的小 LP。这个小 LP 的任意可行 dual 都可以用于计算 Lagrangian underestimate，并安全证明某些枚举列不可能进入优于 incumbent 的整数解。安全性来自下界证明，不是经验阈值。

论文随后把每个列 `j` 映射成向量 `f_j=(b_i-a_ij)_i`。如果一批列的 `f_j` 相近，针对其中心求得的 dual 往往能同时删除这批列。小列池使用 k-means++；超大列池使用按 `||f_j||_2` 排序分组的 `ClustByNorm`，避免聚类本身成为瓶颈。每次找到新的可删除集合后，再把这些列形成新的参考集合继续“deep search”，直到新增删除数低于阈值。这里的 cluster 是**列特征聚类**，和客户空间聚类或分支聚类没有关系。[论文](https://pubsonline.informs.org/doi/10.1287/opre.2023.0398)

### 3.2 实验表现及其依赖

论文在 CMTVRPTW 及其变体上报告：多数列池删除比例超过 75%，最高约 99%。组件消融中，`ClustByNorm` 明显优于随机分组，k-means 删除率略高但大池上成本更高；deep search 在较大实例上很重要。与完整模型反复求 dual 相比，小 LP 的删除能力接近，但在 `n<=140` 的测试中耗时不到前者十分之一。

更有解释力的是 RouteOpt 消融，而不是论文 headline。RouteOpt 不含 DeLuxing 时，本身已经比 VRPSolver 快约 90%（CVRP）和 42%（VRPTW）；只加入 DeLuxing 后，进一步加速约 21% 和 31%，搜索树缩小超过三分之二。论文所称 CVRP/VRPTW 约 45%/71% 的整体提升，是 DeLuxing 与新 primal heuristic 共同作用，不应全部归因于 DeLuxing。CMTVRPTW 的平均 7 倍、最高 20 倍同样来自 EPCEM、DeLuxing、variable relaxation、restricted cut addition 和新 primal heuristic 的整套算法。[论文 PDF](https://pubsonline.informs.org/doi/pdf/10.1287/opre.2023.0398)

论文还专门做了长路线压力测试。常规 RouteOpt 测试中，CVRP/VRPTW 平均每条路线约 7.1/7.9 个客户；把 CVRP 路线长度提高到平均 15.6、最大 23 后，枚举只在搜索过程约 27.8% 时开始，直到 99.8% 才结束，DeLuxing 不再形成明显优势。这个负结果对 TWET 很关键：`n=40--100,m=2/3` 时，一条机器序列平均可能包含 13--50 个任务，不能照搬短路线结论。

### 3.3 开源与外部组件

[RouteOpt 2.0](https://github.com/Zhengzhong-You/RouteOpt) 已公开 DeLuxing 相关实现，许可证为 GPL-3.0。论文也声明源代码与数据在电子附件中。RouteOpt 不是无依赖实现：它使用商业 LP/MIP solver 适配器，并和 HGS、CVRPSEP、XGBoost、bucket graph、rank-1 cuts、ng-route/DSSR 等组件协同。因此能确认 DeLuxing 有公开实现，但没有找到一个经过同等实验验证、完全独立于 RouteOpt 强基线的第三方通用实现。

### 3.4 对 TWET 的可迁移性

当前 `RouteEnumerationEngine` 只在以下条件同时满足时运行：`enableRouteEnumeration=true`、非 time-indexed pricing、节点 gap 很小、没有 active SRI；正式 profile 当前将 route enumeration 关闭。因此 DeLuxing 没有现成入口。若未来枚举能够稳定完成，可在 `RouteEnumerationFiniteMaster` 前增加独立的 safe fixing 阶段，特征向量仍可使用 master 行系数 `b-a_j`，机器数行、任务覆盖行、外包列和 branch rows 都可纳入。

真正的前置验收标准不是“DeLuxing 能删多少列”，而是：有多少节点能在合理时间内完成 exact enumeration，枚举池规模是多少，单列平均任务数多长，active SRI 是否常见。如果枚举阶段本身很少触发或长序列导致池难以闭合，DeLuxing 即使实现正确也不会带来主线收益。

## 4. Cluster Branching：用聚类总流量代替单弧做结构性分支

### 4.1 核心思路

Cluster Branching 的出发点是，VRP 中很多单弧彼此可替代。对同一簇内的便宜弧，禁止其中一条通常还有许多近似替代；对两个簇之间的某一条弧，令它为 0 也不能阻止走另一条跨簇弧。因此单弧分支虽然完整，但两个 child 的 bound 提升可能都很弱。

论文先对客户做静态聚类。测试了 k-means、k-medoids、DBSCAN 和基于最小生成树的 single-linkage，最终 MST 方案最好。MST 边长阈值取均值加 `vartheta` 倍标准差，`vartheta` 测试 0.5、1.0、1.5。随后构造两类整数 aggregate variable：

1. `omega_C`：跨越簇 `C` 边界的总流量，类似把 cutset branching 聚合到一个客户簇上；
2. `psi_C,D`：簇 `C` 与簇 `D` 之间的总边流量。

只要这些 aggregate value 在 LP 解中非整数，就可按 `<=floor(value)` 与 `>=ceil(value)` 分支。其关键优势是 robust：每条 route 对分支行的系数就是 route 中成员弧的出现次数，分支 dual 可以直接加到相应弧的 reduced cost 上，不需要给 pricing label 新增资源。Cluster Branching 本身不完备，最终仍要保留 edge/cutset/Ryan-Foster 一类完备分支作为 fallback。[论文](https://pubsonline.informs.org/doi/10.1287/ijoc.2024.1036)

论文没有通过无限增加 strong candidates 获益。其两阶段 strong branching 原本 phase 1 最多考察 100 个候选，phase 2 只保留 3 个；cluster candidates 只是替换一部分普通候选，候选总预算不增加。这个设计与 TWET 当前 strong trial 很贵的情况高度相关。

### 4.2 实验结果

在经典 CMT13 上，初始 root LB 为 1471.88，最优值 1541.14。只用 edge branching，24 小时后按剩余树估计约需 4 年；只用 cutset branching 估计约 26.7 天。加入 Cluster Branching 后，Edge+CB 在 79 个节点、约 2 小时 30 分钟求解；Cutset+CB 在 55 个节点、约 1 小时 56 分钟求解。这是方法能够改变树结构的最直观例子。

在 XML100 的 2415 个实例、每例 1 小时时限下，Edge 从 1961 个增至 2041 个，Cutset 从 1998 个增至 2073 个，Ryan-Foster 从 1692 个增至 1923 个。不同聚类阈值有差异，但增益不是来自单一偶然实例。[Optimization Online 论文 PDF](https://optimization-online.org/wp-content/uploads/2024/07/L_2024_2___Cluster_branching.pdf)

边界同样明确。在 X benchmark 的较难实例上，24 小时 solved count 大致只从 25 增到 26，主要改善的是树大小和综合评分；对大规模完全随机布局，Cluster Branching 有时反而变慢。Homberger VRPTW 中提升也小于 CVRP，论文明确指出仅按空间距离聚类会把时间窗不兼容的客户错误放在同一簇中，后续应使用 time-window-aware clustering。长时间运行确实关闭了若干 open instances，但个别证明耗费几十到上百 CPU 天，不能把它理解成普遍的数量级加速。

### 4.3 开源与依赖

[INFORMS 官方复现仓库](https://github.com/INFORMSJoC/2024.1036) 使用 MIT 许可证，包含源码和结果。完整复现依赖 BaPCod/VRPSolver（学术使用条件）以及 CPLEX，部分功能还使用 CVRPSEP。因此方法源码是开放的，但论文结果依赖成熟的 branch-cut-and-price 基座，并非一个可单独运行的无依赖插件。没有找到 RouteOpt 已内置 Cluster Branching 的可靠证据。

### 4.4 对 TWET 的具体改法

当前 `ArcBrancher` 把所有正值机器列累加为有向 arc flow，再按距 0.5 的距离选候选；`LP.buildArcBranchConstraints()` 建立显式 master row，`LP.readDuals()` 已将 branch row dual 写入 `arcDual[from][to]`。因此 Cluster Branching 可以沿用同一机制：新分支行的列系数为序列中跨簇转移的计数，读 dual 时把它分发到所有成员转移。ng-DSSR、time-indexed 和 rank-1 labeling 都无需新增状态。

TWET 没有地理坐标，不能机械使用 Euclidean k-means。可以先构造对称任务不相似度，例如：

`d(i,j) = normalized(min/avg(s_ij,s_ji)) + lambda_t * temporalIncompatibility(i,j)`。

其中 setup time/cost 表示相邻吸引力，`temporalIncompatibility` 应利用 due-window 与可完成区间，避免把在时间上无法连续出现的任务聚在一起。也可以使用历史正值列或高质量整数序列中的邻接频率作为第二阶段数据驱动距离，但第一版应保持静态、可复现。

试验时应把 cluster candidates 与普通 arc candidates 放在同一个 `strongBranchingCandidateLimit=20` 预算内，而不是额外测试 20 个。需要记录：cluster candidate 的 fractionality、两侧 trial bound gain、最终被选比例、每节点 strong-trial 时间、树节点数、总时间。若任务 setup 近似随机且时间窗主导，论文已经给出方法可能无效的先验警告。

## 5. 2LBB-dy：学习候选排序，而不是学习求解结果

### 5.1 思路

2026 年 Operations Research 的 two-stage learning-to-branch 研究针对 BPC strong branching 的特殊成本：master 行通常很稠密，列集还会持续变化，传统多阶段 strong branching 为每个候选反复解 child LP/heuristic pricing，代价很高。

2LBB 第一阶段用 XGBoost 和廉价特征排序，把大量 fractional candidates 缩成小集合；第二阶段只对小集合做部分真实测试。动态版本 2LBB-dy 根据当前一次 branch decision 的试算时间和预期树质量在线调整候选数，不再永久固定“测试 20 个”或“测试 100 个”。机器学习只决定候选考察顺序和预算，不决定剪枝与下界，因此不会破坏 exactness。[论文](https://pubsonline.informs.org/doi/10.1287/opre.2023.0615)

### 5.2 实验和依赖

论文报告相对当时手工 three-phase branching，CVRP 和 VRPTW 总时间分别约降低 45% 和 50%；RouteOpt+2LBB-dy 在 CVRP 上比 VRPSolver 快约 47%。这些是完整 stack 上的结果，不是一个孤立分类器的速度。模型在同分布 VRP 实例上训练，因此泛化依赖于训练、测试问题结构相近；对 TWET 直接拿 VRP 模型没有意义。

[官方复现仓库](https://github.com/ORJournal/2023.0615) 为 MIT 许可证，包含归档 RouteOpt 1.0、训练数据与模型、XGBoost、HGS、CVRPSEP 和实验脚本。运行仍要求单独安装 Gurobi 10 和 CPLEX 22.1；VRPSolver 二进制未随仓库分发，相关对比使用存档日志。

### 5.3 对 TWET 的迁移顺序

当前 `Tree.tryTwoStageStrongBranching()` 先取得全部候选，实际按 fractionality 截断至固定 20 个；phase 1 对每个候选左右 child 分别新建 LP 并解 trial RMP，正式 profile 的 phase 2 候选数为 0。这个位置正好对应 2LBB，但现在缺少训练数据。

正确迁移顺序应为：先记录每个候选的廉价特征与已计算出的真实 score，再实现不依赖 ML 的动态预算，最后才训练 ranker。候选特征可以包括 fractionality、setup 相容度、due-window 相容度、父节点深度、该 arc 在正值列中的支持列数、左右 child 过滤后保留列数、历史 pseudo score、repair 类型和 completion-bound 固弧比例。训练标签应来自现有 strong trials 的两侧 gain，而不是最终选中/未选中的二元标记。

第一阶段可以只做规则版动态预算：当单个候选的 trial 时间已经超过本节点预算、且当前最好 score 与剩余候选的便宜上界有明显差距时提前停止。只有经过多 seed、多时间尺度日志积累后，才有条件检验 XGBoost 是否优于简单线性排序。

## 6. SRI unreachability dominance：证明 residual 差异以后不会再生效

rank-1/SRI cut 给 pricing label 增加 residual 状态。传统 dominance 中，如果支配 label 的 residual 在某个 cut 上比被支配 label 更不利，通常必须加入这条 cut dual 的补偿，否则可能错误删除未来能少支付一次 cut penalty 的路径。

Faldum、Gschwind 和 Irnich 的方法进一步问：从当前 label 的资源状态出发，还能否到达足够多的 cut-scope 客户，使 residual 差异真的触发下一次 cut coefficient？如果时间、容量、电量等资源已经证明这些客户不可达，那么 residual 差异永远不会影响任何 completion，dominance 可以忽略这份补偿。论文预计算不同资源下的 unreachable set，并用离散查询表降低判断成本。[论文 PDF](https://logistik.bwl.uni-mainz.de/files/2025/02/LM-2023-04.R1.pdf)

实验中总体平均提升不算夸张，但随 active SRI 数显著增加。VRPTW 至少一个 SRI 的总体时间比约 0.968；当 SRI 数达到 200 以上时，约降到 0.667。EVRPTW 的高 cut 组常见约 0.57--0.65，困难实例可接近减半。它不是 no-cut 主线的通用优化，而是 cut-heavy pricing 的定向优化。

TWET 普通 PWLF 路线的 `SriAwarePartialListDominanceStore.mayDominatedUseSriLater()` 已经有一个粗粒度版本：若 dominated label 的 `reachableSet` 中没有尚可使用的 cut-scope job，就不加补偿。这说明论文思想并非完全缺失。缺口主要在 time-indexed rank-1 engine：当前 `packedDominates()` 对 `firstResidual & ~secondResidual` 中每个 cut 一律累加 dual，没有结合 label 当前时间、方向、completion bound 或剩余可达 scope。可以为每个 time-indexed state 构造 scope-reachability mask，再从 correction mask 中清除已证明无法再次触发的 cut。该优化必须逐次与旧 dominance 对拍，并验证最终 reduced-cost certificate、列集和 bound，不可只做速度测试。

未找到该论文的公开代码仓库。

## 7. Arc-specific resource windows：从删整条弧进一步变成缩弧的可用区间

Bianchessi、Gschwind 和 Irnich 的 2024 IJOC 工作使用前向/后向 reduced-cost 下界，不只判断一条弧是否可以完全删除，还为每条弧推导独立的 forward/backward 时间与容量窗口。窗口为空时删弧；窗口非空时，modified resource extension function 只允许在该区间使用弧，dominance 本身不变。[论文 PDF](https://logistik.bwl.uni-mainz.de/files/2022/07/LM-2022-05.pdf)

80 个 VRPTW 实例上，time-only 版本时间比约 0.911，time+load 约 0.896，即总体约 10% 加速；baseline 超过 2000 秒的难组，组合版本约 0.546，接近 1.83 倍。论文也报告只收紧 vertex window 反而更慢，真正有效的是 arc-specific window。

TWET 的 time-indexed engine 已保存 `(from,to,time)` 级别的禁用信息，这比连续区间更细；`TimeIndexedScalarCompletionBound` 也已经做 dual-window 与 arc fixing。因此 time-indexed 主线没有必要另造一个区间层。可能存在的迁移点是非 time-indexed ng-DSSR：为 `(i,j)` 保存可用 completion-time 区间，提前截断 PWLF extension domain。但它很可能与现有 completion bound/window tightening 重叠，实施前必须先统计“弧未被全删但实际可用时间区间很窄”的比例。

未找到该方法的公开实现。

## 8. Pricing for Integrality：定向生成能拼成整数解的列

标准 pricing 只关心 LP dual 和负 reduced cost，产生的列未必适合组成高质量整数解。2026 年的 Pricing for Integrality Heuristic 先从当前列池构造一个 partial integer solution，再修改 pricing 目标，使新列更倾向于补齐尚未覆盖的任务、避免重复覆盖，并同时利用 LP dual 和本轮已经生成的列。它是 primal heuristic，不返回 exact pricing certificate，也不替代正常定价。[论文](https://arxiv.org/abs/2602.08673)

论文在带充电时隙的 EVRPTW 上报告：相对只解 restricted master 的 heuristic，平均额外关闭 root gap 的约 30%--40%。这个问题同时含 routing 和 scheduling，因而比纯 CVRP 更接近 TWET。但证据仍来自一个特定 EVRPTW-CTS 实现，不能直接推断总求解时间一定下降。

LiU 已公开 [`BPC-for-EVRPTW-CTS`](https://gitlab.liu.se/lukev81/bpc-for-evrptw-cts) 项目并标注 MIT 许可证；但当前公共页面只显示 1 次提交，README 内容也未正常渲染，因此目前只能确认公开仓库存在，不能确认它足以完整复现实验。作者报告的实现栈基于 GCG/SCIP、定制 labeling、cuts 和 branching。对 TWET，最自然的用法是在已有 pool 上先固定一部分高置信机器列/外包列，然后调用一个只加列的 heuristic pricing，目标中增加“补齐 partial solution 缺口”的扰动。它必须与 exact pricing 完全隔离，不能返回 certificate。是否值得做取决于当前 incumbent 获得是否真是瓶颈；如果主要耗时在 root proof 而上界已经很好，这项优先级应下降。

## 9. Column Elimination：前沿但属于另一条算法主线

Column Elimination 从一个包含所有可行序列、也可能包含不可行序列的松弛状态转移图开始，在图上解 constrained network flow。若当前最优流对应不可行路径，就针对冲突细化决策图，排除这条路径及一类相似不可行路径，反复进行直到获得可行最优解。它与 CG 的方向相反：CG 从小列集开始加列，CE 从紧凑表示的超集开始删掉不可行路径。大图上使用 Lagrangian/subgradient 和专门的 minimum-update successive shortest paths；之后再切换到 CPLEX 模型。[CPAIOR 论文](https://optimization-online.org/2023/03/column-elimination-for-capacitated-vehicle-routing-problems/)、[通用框架论文](https://optimization-online.org/wp-content/uploads/2024/10/column_elimination.pdf)

组件结果显示，专门 SSP 比普通 SSP 平均快约 3.7 倍；variable fixing 使 CVRP 平均快约 53%；cut-and-refine 对 LP 版有效，但与 subgradient 的结合较困难。VRPTW 大实例上它的表现高度依赖问题结构：400/600-customer C2 中有 6 个实例的下界优于同机 VRPSolver，但大量实例仍由 VRPSolver 更好。它关闭了 C2_10_1 这个 1000-customer open instance，用时约 10049 秒；另两个较难实例也被求解，但并没有在所有 VRPTW 类别上普遍压过 VRPSolver。论文自己的解释是 clustered、可由小状态图表达的松弛更适合 conflict refinement。

[官方更新代码 `dd_vrptw`](https://github.com/amkarahalios/dd_vrptw) 使用 Apache-2.0，覆盖 CVRP、VRPTW、PDPTW、TSPTW 和 SOP，包含 500 次提交、论文日志和参数；仍需要 CPLEX 与 CVRPSEP。代码 README 中尚残留 merge conflict 标记，说明虽然是完整研究代码，但工程成熟度不能与稳定库等同。

TWET 已有 time-indexed graph，可从理论上构造 arc-flow/decision-diagram relaxation；但 due-window 软惩罚由 completion time 决定，外包列与多机器数约束也要一起进入 network flow master。这样做会替换当前 Dantzig-Wolfe 主线，不是“加一个优化”。2026 年 DW 与 Arc-Flow 的系统比较也指出：Arc-Flow 在子问题高度松弛或低维时收敛更快，Dantzig-Wolfe 在 master 保持紧凑时更有效，没有一种表示在所有场景占优。[2026 比较论文](https://arxiv.org/abs/2602.22589)

因此 Column Elimination 应作为独立研究分支，而不是近期主线任务。

## 10. Local Area Routes 和 Graph Master

Local Area Routes 预先为每个客户和局部邻域计算最便宜的 elementary local subpath，pricing 不再逐客户扩展，而是拼接 LA arcs。LA-route relaxation 比 ng-route 更强：它允许某些全局重复，但阻止局部邻域内的循环。Graph Master 更进一步，一条生成 route 不只对应一个 master variable，而对应一个 DAG/多图所表示的一族相关 routes；Graph Generation 和 Principled Graph Management 按需激活图边，相当于一次 pricing 给 RMP 带入很多隐式列。[LA Routes](https://arxiv.org/abs/2207.04520)、[Graph Master](https://arxiv.org/abs/2304.11723)

论文中的小型 MATLAB/`linprog` CG 实验在困难样本上常见 2 倍以上，10 倍加速也不少，个别 pricing 时间提升更高。但测试规模主要为 20--60 客户、旧款 MacBook，并非与 RouteOpt/VRPSolver 完整 BPC 的同口径比较；也没有找到维护中的正式公开实现。

TWET 的局部 job block 可以类比 LA arc，但 block 的成本不是常数，而是起始/完成时间到软 due-window 成本的 PWLF 映射。预计算一个 block 需要保存函数型 transfer frontier，组合时容易产生大量分段。Graph Master 则会把现有 route-based RMP 改成 extended network model。两者都改变当前流程，除非未来明确开展独立算法论文，不建议近期移植。

## 11. 这些结果对强基线组件的依赖

前沿论文的绝对性能普遍依赖完整 solver stack，不能把某一项增量与 headline 混为一谈。

RouteOpt/VRPSolver 一类强基线通常同时包含 bidirectional/bucket labeling、bucket arc elimination、ng-route/DSSR、route enumeration、limited-memory rank-1 cuts、rounded capacity cuts、强分支、HGS 上界和商业 LP/MIP solver。DeLuxing 在 RouteOpt 消融中的独立增量约 21%/31%，而不是整套算法的 45%/71% 或 CMTVRPTW 的 7--20 倍。Cluster Branching 建在 BaPCod/VRPSolver 上；2LBB 建在 RouteOpt 上；SRI unreachability 的收益只在已有大量 SRI 时出现；Pricing for Integrality 的实现还依赖 GCG/SCIP 和定制 pricing。

[RouteOpt 2.0 论文与项目页](https://zhengzhong-you.github.io/papers/routeopt/)在 2026 年被 INFORMS Journal on Computing 接收，报告 CVRP/VRPTW 的当前先进结果，并通过 node restoration 与并行处理证明了 3 个此前开放的 CVRP 实例。这里同样不能把结果理解为某一个新组件的作用：RouteOpt 是把 bucket graph、arc elimination、ng/DSSR、rank-1 cuts、enumeration、DeLuxing、学习分支、HGS 和求解器工程组合成完整系统。[公开仓库](https://github.com/Zhengzhong-You/RouteOpt)提供 GPL-3.0 源码和 solver adapter，但仍需用户自行提供商业 LP/MIP solver。

Bucket Graph 本身是 2021 年已经成熟的底座，而不是本轮“最新单项方法”。其主要价值是按资源区间组织 labels，减少 dominance 比较，并用 reduced-cost bucket-arc elimination 缩小后续 pricing 图。[原论文](https://pubsonline.informs.org/doi/pdf/10.1287/trsc.2020.0985)与 RouteOpt、VRPSolver 都表明它是现代 VRP exact solver 的基础组件。TWET 的 time-indexed engine 已经把完成时间离散到图节点，功能上比一般时间 bucket 更细；ng-DSSR 的 label 又保存 PWLF 全域，不能无代价换成单一 scalar bucket。因此近期可借鉴的是 bucket-arc fixing 和按 endpoint/time 分组 dominance，而不是再移植一套通用 bucket graph。

开源也需要区分三层：

| 层次 | 可获得性 |
| --- | --- |
| 方法源码和实验脚本 | DeLuxing/RouteOpt、Cluster Branching、2LBB、Column Elimination 有可检查的公开源码；PFIH 有 MIT 公共项目，但完整内容尚未核实 |
| 完整可编译求解器 | 多数仍要求 CPLEX/Gurobi，Cluster Branching 还要求 BaPCod；不是纯开源一键复现 |
| 独立第三方复现 | bucket graph 有 RouteOpt、VRPSolver 和 [BALDES](https://github.com/lseman/baldes) 等多套实现；DeLuxing、Cluster Branching、2LBB 尚未找到同等成熟的独立第三方实现 |

## 12. 针对 TWET 的实施优先级与验收设计

### 12.1 第一优先级：Cluster Branching 独立开关

先做静态 MST clustering，距离同时包含 setup affinity 与时间相容性。增加 `cluster-cut` 和 `cluster-pair` 两类候选，但和普通 arc 共用 20 个 strong candidate 名额；完整性由 arc fallback 保证。先只做 root 后首层和浅树 A/B，不更改默认。

验收必须同时看：相同 root bound、最终 obj/valid、每次 branch 两侧 gain、候选被选比例、strong trial 总数与总时间、节点数和总时间。若只减少节点但 strong-trial 增加，仍可能是负优化。

### 12.2 第二优先级：为 2LBB 建数据而不是直接上模型

记录所有进入候选池的 cheap features、真实 phase-1 两侧 bound、trial build/solve/repair 时间和最终选择。先比较三个无训练基线：固定 20、按节点预算动态截断、简单线性/规则排序。只有动态基线稳定后，再用跨 seed、同规模训练/测试划分评估 XGBoost；必须另做跨时间尺度 OOD 测试。

### 12.3 不进入当前实施：time-indexed rank-1 unreachability mask

该方向只在 active cut 较多且 rank-1 pricing 确认是热点时才有意义。当前目标是加强无 SRI 的 normal ng-DSSR，因此不修改这条路径，也不把它列为近期优化。它解决的是有 SRI 时 residual state 导致的 dominance 变弱，并不改善 DSSR 的 ng-set 初始化、重复 route 更新、DSSR 轮数、候选池、双向 join 或 completion bound。

如果未来重新启用该方向，才需要对比 generated labels、dominated labels、每 cut correction 次数、被 unreachability 清除的 correction 位数、pricing certificate 和返回列 reduced cost。

### 12.4 条件性试验：Pricing for Integrality

先确认当前正式实例的 incumbent gap 是否长时间主导。如果 root 很快得到好上界，暂不做；若高质量 incumbent 明显滞后，可在 root 或低深度节点调用，限制次数和总 pricing 预算。它只能加列和更新 incumbent，不能关闭 pricing family。

### 12.5 暂缓：DeLuxing、Column Elimination、LA/Graph Master

DeLuxing 先统计 route enumeration 的触发率、完整率、列池规模和平均列长；没有稳定枚举就不实现。Column Elimination 与 LA/Graph Master 都应放到独立 branch/研究课题，不能作为当前主线的小优化。

## 13. 最终判断

如果目标是“不改当前求解流程但寻找前沿、可验证的提速”，分支层可以继续评估 **Cluster Branching -> strong-branching 动态预算/2LBB 数据**，上界明显滞后时再考虑 Pricing for Integrality。SRI unreachability 已按当前决定移出实施项。DeLuxing 解决的是枚举后的列池，Column Elimination 则替换整个列生成框架；二者都不是当前 ng-DSSR 的直接优化。

更严格地说，本轮六项前沿中没有一项直接加强当前无 SRI 的 ng-DSSR。Cluster Branching 和 2LBB 改善分支选择；SRI unreachability 只服务有 cut 的 dominance；DeLuxing 服务枚举后的 finite master；Pricing for Integrality 服务 primal incumbent；Column Elimination 是另一套 exact framework。若后续目标严格限定为 ng-DSSR，应单独检索 adaptive ng-neighborhood、DSSR refinement/update、relaxed-route witness 选择、双向 DSSR join 与 no-SRI dominance，而不能把上述六项的整体求解器收益误当成 ng-DSSR 收益。

## 14. 六项方法的机制澄清

### 14.1 Cutset 与 Cluster Branching：4 年和 26.7 天是怎样估出来的

Cluster Branching 论文没有真的运行普通 edge branching 4 年，也没有真的运行 cutset branching 26.7 天。作者把两种方法各运行 24 小时，然后根据已观察到的平均节点界提升估计剩余树大小。对每个仍开放节点 `i`，令 `gap(i)` 为该节点下界到 best known solution 的剩余差距，令 \(\Delta_{avg}\) 为已经执行的分支中每深入一层带来的平均下界提升。作者先估计还需深度

\[
d_i=gap(i)/\Delta_{avg},
\]

再把该节点以下近似成深度为 \(d_i\) 的完整二叉树，估计剩余节点数

\[
RTS=\sum_{i\in O}\left(2^{gap(i)/\Delta_{avg}+1}-2\right).
\]

已处理节点数记为 `CTS`，预计总树大小为 `ETS=CTS+RTS`，24 小时内已完成比例为 `ETS%=CTS/ETS`。最后用

\[
ETime\approx 24\text{ hours}/ETS\%
\]

外推总时间。论文表中 edge branching 的 `ETS%=0.07%`，所以 \(24/0.0007\approx34286\) 小时，即约 3.91 年；cutset branching 的 `ETS%=3.75%`，所以 \(24/0.0375=640\) 小时，即约 26.7 天。这只是基于“未来节点与已处理节点平均耗时相同、平均界提升保持不变、剩余树近似平衡”的粗外推，没有置信区间。它能说明两种分支的量级差距，不能当作实际完跑时间。

普通 edge branching 对一条边变量 \(x_e\) 分成 `x_e=0` 和 `x_e=1`。VRP 中它经常不平衡：强制使用一条昂贵边通常明显抬高下界，但禁止一条边时往往存在很多近似替代边，另一侧几乎不动。

Cutset branching 不分单边，而选一个客户子集 \(S\)，令

\[
\omega_S=\frac{1}{2}\sum_{e\in\delta(S)}x_e.
\]

TSP/VRP 的整数路线穿过割集 \(\delta(S)\) 的次数为偶数，所以 \(\omega_S\) 在整数解中是整数。若 LP 解中的 \(\omega_S\) 非整数，就按 `omega_S <= floor(value)` 和 `omega_S >= ceil(value)` 分支。它把许多可互相替代的边绑在一起，禁止或强制的是“路线穿过这组客户边界多少次”，因此两侧通常比单边分支均衡。传统 CSB 还需要从指数多个子集里寻找分数性好的 \(S\)，论文用 CVRPSEP 完成这一步。

Cluster Branching 的出发点更具体。CMT13 的客户天然分成六个地理簇，簇间边平均成本约为簇内边的 11.6 倍。对簇内单边分支，`x=0` 时有大量便宜替代边；对簇间单边分支，`x=0` 时也有大量连接同一对簇的替代边。因此作者认为真正应该分支的不是某条边，而是两类高层结构量：一个簇被路线进出多少次，以及两个簇之间总共连接多少次。前者就是把 cutset 的 \(S\) 限制为预先识别的簇，后者定义为

\[
\psi_{C_kC_l}=\sum_{e\in E(C_k,C_l)}x_e.
\]

只把当前为分数的 cluster variables 送入已有 strong branching，且占用原候选预算，不额外扩大每个节点的试算数。它不是用聚类直接构造路线，也不是学习分支策略；核心是用聚类识别“互为替代品的一组边”，再对组的总流量分支。Cluster Branching 自身不完备，最终仍保留 edge/arc branching fallback。

TWET 可以借鉴 cutset/cluster 的数学结构。对内部任务子集 \(S\)，可定义有向外穿越量

\[
z_S=\sum_{i\in S,j\notin S}y_{ij}.
\]

每条整数机器序列对该量贡献一个整数穿越次数，整数 master 解中的总量也必为整数，因此可按 floor/ceil 分支。branch row 的列系数就是该机器序列离开 \(S\) 的次数；其 dual 可以逐弧加到所有跨界弧上，所以仍是 robust branching，不需要给 ng-DSSR label 增加新资源状态，也不改变 exact certificate。

但它不能直接复用 CVRPSEP。TWET 是有向 source-to-sink 序列、master 为 covering，而且可选子集有指数多个；CVRPSEP 使用的无向度数和 VRP cut 结构不能原样套入。更现实的候选是固定少量有业务含义的 task clusters，例如 family/setup affinity 与时间窗相容性形成的簇，再构造 `cluster-cut` 和 `cluster-pair` 变量。与此同时，Node、Phase-I、branch row 和 pricing dual 都要支持 aggregate branch，普通 arc fallback 仍必须保留。它可能减少分支树，但不会减少一次 ng-DSSR pricing 的内部工作，因此属于树搜索优化，不是 ng-DSSR 优化。

### 14.2 2LBB-dy：是机器学习，但只学习 strong branching 的计算预算

2LBB 的完整题名为 *Two-Stage Learning to Branch in Branch-Price-and-Cut Algorithms for Solving Vehicle Routing Problems Exactly*。它确实使用监督机器学习，但不是让模型生成路线、求 reduced cost 或判断最优性。它只回答一个问题：当前很多分数候选中，哪些值得花钱做 strong-branching trial。

传统 strong branching 会对多个候选分别临时施加左右分支，求两个 child relaxation，再按两侧界提升评分。这个分支通常质量好，但每个候选需要两次试算，BPC 中试算还可能涉及 RMP、启发式 pricing 或修复，开销很大。

2LBB 第一阶段用便宜特征对全部候选快速排序并缩成 shortlist。这些特征来自当前 LP、候选分数性、历史 pseudo-cost、图结构和节点信息；监督标签来自历史中真正执行 expensive branching test 后得到的分支质量。第二阶段不对 shortlist 全部做完整测试，而是做论文设计的 partial testing，进一步排除差候选。`dy` 表示动态版本：作者建立“多测试一个候选所增加的当前决策耗时”和“候选变好后预计减少的未来树规模”之间的权衡模型，动态决定第二阶段保留多少个候选，而不是始终固定 top-K。

所以它的机器学习边界很窄：模型可能排错候选，影响速度，但不会让 exact algorithm 给出错误证明；最终选定分支后，左右子树仍由正常 BPC 完整搜索。论文报告相对当时的手工分支策略，CVRP 总时间约下降 45%，VRPTW 约下降 50%。这组结果建立在 RouteOpt 完整组件栈和相应训练分布上，模型不能直接搬到 TWET。对当前项目，先记录 cheap features、真实 trial score、trial 时间和选中结果，再评估动态预算是否有效，比直接训练一个模型更稳妥。

### 14.3 SRI unreachability：以前讨论过，但不属于当前 ng-DSSR 目标

对应论文的最终题名是 *Subset-Row Inequalities and Unreachability in Path-Based Formulations for Vehicle Routing and Scheduling Problems*，作者为 Stefan Faldum、Timo Gschwind 和 Stefan Irnich，2025 年 online first，2026 年发表于 *Networks*。它讨论的不是 ng-set 如何更新，而是：label 带有 subset-row cut residual state 时，普通 dominance 往往因为两个 label 的 cut state 不同而不敢比较；如果从当前状态出发已经不可能再到达该 cut scope 中尚未访问的任务，那么这部分 state 差异未来永远不会生效，可以从 dominance correction 中删掉。

本项目以前确实讨论并实现过同一类核心逻辑，但当时主要称为“旧 VRP `UseSR` / SRI dominance compensation”，没有在早期记录中用这篇论文的最终题名来标识。`SriAwarePartialListDominanceStore` 会检查被支配 label 是否仍可能访问某个 cut scope 内尚未访问的 job；只有仍可触及时才给支配方 frontier 加上相应 SRI penalty。相关提交包括 `393e5123`、`a4857e77`、`66292c02` 和 `6a326b82`，专题记录在 `docs/plans/2026-06-13-partial-dominance与SRI接入分析.md` 及 `docs/plans/2026-06-09-ng-dssr与partial-dominance实验变体记录.md`。

但当前 no-SRI normal ng-DSSR 不携带 cut residual state，active cuts 才回退 SRI-aware store。因此这篇论文不能改善当前重点关心的 ng-set 初始大小、DSSR route witness、每轮新增 pair、DSSR rounds、candidate reservoir、join 或 no-SRI dominance。按当前决定，这一方向不动，也不再作为近期优先级。

### 14.4 DeLuxing：枚举完路线以后，用多组 dual 安全删掉绝不可能进优解的列

DeLuxing 不是定价算法，也不是机器学习。它的使用前提是：先通过 route enumeration 得到一个包含所有可能改进 incumbent 的有限列集，然后要把这个可能很大的 finite master 交给 MIP 求整数解。问题在于，枚举得到的路线可能有几十万甚至更多，直接求 finite MIP 很重。

单个 LP optimal dual 可以做 reduced-cost fixing：设当前 LP 下界为 \(LB\)、incumbent 为 \(UB\)，若强制使用列 \(j\) 后得到的有效下界已经超过 \(UB\)，就能证明该列不可能属于更优整数解并永久删除。最简单的形式是检查 `LB + reducedCost_j > UB`。但 LP dual 高度退化，一个 optimal dual 往往只能把部分列的 reduced cost 拉高，很多实际上无用的列在该 dual 下仍接近 0，无法删除。

DeLuxing 的核心是针对不同列群反复寻找不同的有效 dual 点。它先用列的约束系数缺口向量对相似列聚类，再解很小的辅助 LP，使某个 cluster 中的列在同一 dual 方向下更容易得到强的 Lagrangian fixing bound。每找到一个 dual，就重新检查一批列；删掉一批后继续 deeper search，直到没有明显进展。`deep` 指反复深入寻找多组 dual 证书，不是 deep learning。

它不会启发式地误删列：聚类只决定下一次去哪里找 dual，每一条列最终都必须通过独立有效的下界判定才能删除。它也不找负 reduced-cost 列、不收紧 root LP、不减少 DSSR 轮数。对 TWET，只有在完整 route enumeration 已稳定触发且 finite master 列数成为瓶颈时才有意义；当前正式主线没有这个前提，所以不动。

### 14.5 Pricing for Integrality：让 pricing 专门补整数解缺口，尽早找好 incumbent

普通 pricing 完全服从 LP dual，寻找负 reduced-cost 列。这些列对降低分数 LP 目标有用，却可能彼此冲突，无法组合成好的整数排程。Pricing for Integrality Heuristic 额外开一条只服务 primal solution 的启发式 pricing：先从当前 restricted master 中固定或选择一部分高置信整数列，观察哪些客户/任务仍未覆盖、哪些资源或时隙已经拥挤，再扰动 pricing objective，奖励能补齐未覆盖部分且与已选列相容的路线，并惩罚重复或冲突的路线。把新列加入 pool 后重新求 restricted integer master，迭代构造更完整的整数解。

因此它干的是“定向造出能拼成整数解的列”，不是证明 LP 已闭合。它不能返回 exact pricing certificate，也不能替代 ng-DSSR；即使 heuristic 没找到列，exact pricing 仍必须正常执行。收益来自更早得到低 UB，随后 branch-and-bound pruning、reduced-cost fixing 和 gap-based enumeration 都可能更强。论文在带充电时隙的 EVRPTW 上报告，相对只解 restricted master 的 heuristic，平均额外关闭约 30%--40% 的 root gap；这证明了 incumbent 质量改善，不等于总求解时间必然下降。如果 TWET 当前 root 很快已有好上界而主要耗时在 lower-bound proof，它不会解决主瓶颈。

### 14.6 Column Elimination：从隐式路线超集出发不断排除不可行路径

Column Elimination 不是显式列池清理，也不是 DeLuxing。Column Generation 从少量列开始，通过 pricing 不断加入遗漏的有用列；Column Elimination 则先建一个压缩状态图/decision diagram，它隐式表示大量路线，其中既包含真正可行路线，也可能因为状态合并而包含容量、时间窗、重复访问或先后约束不合法的路径。

算法先在这个松弛图上解最小成本 constrained flow。如果得到的路径对应原问题可行路线，就保留；如果不可行，就识别造成不可行的冲突，拆分状态、细化图或删掉相关转移，使该路径及一类同源不可行路径以后不再出现。然后重新求流、继续检测和细化，形成 `solve -> find conflict -> refine` 循环。有限细化后图能够精确区分所有相关状态，从而得到 exact solution。为处理大图，论文使用 Lagrangian/subgradient、专门的 shortest-path 更新、cut-and-refine 和 branch-and-refine。

名称中的“elimination”指从隐式列超集中排除不可行路径，方向与 CG 的逐列添加相反。它可能利用 TWET 现有 time-indexed graph 作为起点，但必须重新设计哪些状态可以合并、如何识别由于 PWLF due-window cost、setup、外包和多机器约束产生的 conflict，以及如何保证逐步细化的 exactness。这会替换当前 Dantzig-Wolfe + ng-DSSR 主线，而不是给现有 pricing 加一个开关，因此当前先不考虑。

### 15.1 当前真正还能借鉴什么

如果标准是“已有论文直接证明能加速当前 no-SRI ng-DSSR”，结论确实是 **没有**。Cluster Branching 和 2LBB 作用于树搜索；SRI unreachability 的前提不成立；DeLuxing 在 enumeration 之后；PFIH 服务上界；Column Elimination 替换求解框架。

如果允许只借鉴机制而不照搬算法，还剩一个与 ng-DSSR 最接近、但尚未有速度证据的候选：**conflict-directed multi-witness refinement**。Column Elimination 每轮不是按当前最便宜路径机械细化，而是根据不可行路径暴露的冲突选择能排除一类路径的 refinement。映射到当前 ng-DSSR，就是先保留现有 `relaxed pricing -> non-elementary witness -> ng update -> repeat` 流程，只改变一轮内多个 witness 的处理顺序：对每个候选重复段计算其新增 ng-pair 集合及能够同时阻断的 top-C witness 数，优先选择“单位新增 pair 能覆盖更多负 witness”的重复段。

当前实现已经完成了单路线层面的主要工作：non-elementary routes 按 reduced cost 保留 top-C；每条路线选择缺失 pair 最少、跨度更短的完整重复段；已被现有或本轮新增 ng-pair 阻断的路线会跳过；直到找到 `ngDssrNonElementaryRouteUpdateLimit` 条真正产生更新的路线。因此可改空间只剩“跨路线全局去重/覆盖”，不是重新设计 DSSR 流程。

这项不能直接假定更快。一次加入覆盖更多 witness 的 pair 可能减少 DSSR rounds，也可能使 ng-set 膨胀更快、让下一轮 labeling 更重。正确的下一步不是立即改变排序，而是先记录三个量：当前前 10 个 effective witness 的新增 pair 重叠率、每个新增 pair 实际能阻断多少个 top-C witness、下一轮重复出现同类 repeat segment 的比例。只有重叠和复发都高，global coverage 才有明确实施理由。

对整个 BPC 而非 ng-DSSR，还有两项真实候选。第一是 Cluster Branching 的 aggregate candidate，它可能降低节点数，但要新增 robust branch row。第二是 2LBB 的非机器学习部分，即按节点剩余时间、候选 score 分散程度和 historical trial cost 动态决定 phase-1/phase-2 数量。当前 TWET 已有两阶段 strong branching，但正式 profile 仍是固定 `strongBranchingCandidateLimit=20` 且默认 `phase2=0`，所以动态预算是可迁移差距；它仍不应计为 ng-DSSR 提速。

## 17. RouteOpt 与 VRPSolver 能否直接求解 TWET

### 17.1 结论

两者都不能把当前 TWET 数据作为标准输入直接求解。序列相关 setup time/cost、任务覆盖和固定机器数本身不是主要障碍：可以分别映射为有向弧属性、packing/elementarity set 和路线数量约束。真正不匹配的是当前内部定价的状态与成本语义。TWET 的 label 不只保存一个最早到达时间，而是保存“可选完成时间到累计 reduced cost”的整条 `PiecewiseLinearFunction` frontier；每次扩展执行横向时间平移、加入 job 的 earliness/tardiness 分段函数，再加入 setup cost 与 dual。外包侧还包含独立外包列、成员分支、列数约束和分段 tariff。标准 CVRP/VRPTW 的标量资源 labeling 与静态弧成本不能直接表达这些结构。

因此需要区分三种说法：现成程序不能求解；理论上可以把 TWET 重写成相应框架的新应用；但后一种工作不是“换求解器”，而是重新实现 master、pricing、列恢复、分支兼容与证书逻辑。按当前代码成熟度，把现有 TWET pricing 移植过去的成本明显高于继续维护当前求解器。

### 17.2 RouteOpt

[RouteOpt 2.0](https://github.com/Zhengzhong-You/RouteOpt) 的公开应用当前聚焦 CVRP 和 VRPTW。它的优势是 C++ 核心以 GPL-3.0 开源，branching、rank-1 cuts、RCC、DeLuxing、solver adapter 和节点恢复等模块可以检查和替换；[官方文档](https://zhengzhong-you.github.io/RouteOpt-Docs/)也把自定义 branching 和 application callback 作为主要扩展方式。它更像一个高性能、源码级的 VRP BPC 开发平台，而不是输入任意路径模型即可自动生成 pricing 的建模语言。

若用 RouteOpt 求 TWET，至少要新增一个 TWET application，替换现有 `CVRP_Pricing/VRPTW` 的标量 labeling，把本项目 PWLF label、动态 completion window、setup cost 和 ng-DSSR 搬入其 pricing callback；同时改造列对象、master objective、外包变量/外包列、tariff 分段和相应 branching。RouteOpt 的 3PB/2LBB、树管理、LP adapter、部分 cut/枚举基础设施可以复用，但当前最复杂的 TWET 专属逻辑仍需自己实现。因此它不能直接作为本项目的独立求解器对照，保留论文的价值主要是检查现代 BPC 模块边界和开源实现细节。

### 17.3 VRPSolver

[VRPSolver](https://vrpsolver.math.u-bordeaux.fr/) 建在 BaPCod 的通用 BCP 后端上，定位比 RouteOpt 更偏“通用建模”。Julia 接口允许用户定义 `VrpGraph`、source/sink、路径 multiplicity、arc-variable mapping、packing sets、elementarity sets 和资源；当前[资源接口](https://vrpsolver.math.u-bordeaux.fr/documentation-julia/resources.html)支持最多 2 个 main、20 个 non-binary 和 512 个 binary resources，并自动使用 bucket labeling、ng-set、rank-1 cuts、enumeration 和三阶段 strong branching。它对标准的多资源 VRP、硬时间窗和相关路径模型，比 RouteOpt 的现成 application 更容易建模。

但它的通用 RCSP 资源递推是固定形式：资源沿弧做加法或 `max{arc lower bound, previous + consumption}`，路径目标主要由静态 arc-variable mapping 累加。当前 TWET 的 PWLF frontier 是“资源状态决定成本函数”的动态对象，不是再增加一个普通 resource 就能表示。若把时间离散成 time-expanded graph，可以在时刻节点上静态编码 earliness/tardiness 成本，但图会随 horizon 放大，而且等于改走本项目已有 time-indexed 路线；连续 PWLF、动态 dual window 与当前 ng-DSSR 仍无法原样获得。简单逐任务外包变量理论上可放入其 JuMP master，但 columnized outsourcing、成员分支和非线性分段 tariff 仍需专门建模并验证与 pricing 的交互。

VRPSolver 还是 academic-use 软件，需申请并接受 BaPCod 许可。Julia 等接口公开，获批的学术用户也可以取得 BaPCod 源码并在内部研究中修改；但许可不允许像 GPL 项目那样自由再分发，因此准确说法是 source-available academic software，而不是标准意义的开源软件。若需要修改标签状态、成本递推或 certificate 边界，它在获取、传播和协作边界上仍比 RouteOpt 受限。它也不能直接作为当前 TWET 的求解器对照，论文主要用于理解 packing-set 泛化、generic branching 和旧 VRP 主线的实现逻辑。

### 17.4 两者的核心区别

| 维度 | RouteOpt 2.0 | VRPSolver/BaPCod |
| --- | --- | --- |
| 主要定位 | 开源、模块化、高性能 VRP exact solver 开发平台 | 通用 VRP/相关路径模型的 BCP 建模与求解系统 |
| 现成问题 | 主要是 CVRP、VRPTW | 通过 graph/resource/packing-set 接口覆盖更广的标准 VRP 变体 |
| 扩展方式 | 修改或新增 C++ application、pricing 和 callback | 用 Julia/Python/C++ 接口声明 master、pricing graph、资源与映射 |
| pricing 灵活性 | 源码可改，理论上可换成 PWLF，但工作量大 | 通用 RCSP 建模方便，但资源递推模板难以容纳 PWLF 状态依赖成本 |
| 强化组件 | 3PB/2LBB/BKF、rank-1、RCC、bucket/arc elimination、enumeration、DeLuxing、node restoration | 3PB、packing-set/Ryan-Foster/resource branching、rank-1、RCC、bucket/arc elimination、enumeration、stabilization |
| 开放性 | GPL-3.0 源码开放，可按 GPL 修改和再分发；仍需外部 CPLEX/Gurobi 等 | 接口公开；获批学术用户可取得 BaPCod 源码并内部修改，但受 academic license 限制，不能自由再分发 |
| 对当前 TWET | 可作为源码级实现参考，不能直接求解 | 可作为 generic BPC 逻辑参考，不能直接表达 PWLF pricing 与完整外包语义 |

最终定位应当是：RouteOpt 和 VRPSolver 都是值得保留的“宿主求解器文献”，但不是前面六项新方法，也不是当前 TWET 可直接运行的替代求解器。RouteOpt 更适合看代码和模块实现，VRPSolver 更适合看通用模型抽象与成熟 BCP 组件如何组合。

## 18. Bucket Graph、Arc-Specific Resource Windows 与两套 BPC 的层次关系

### 18.1 Bucket Graph

Bucket Graph 不是把时间取整后做近似，也不是改变 master relaxation。它仍然保留 label 的精确资源值，只是在每个原图顶点上按时间、容量等 main resource 区间划分 buckets，把资源值相近的 labels 放入同一 bucket，并预先建立哪些 bucket 之间可能发生扩展的 bucket arcs。这样可以按 bucket 顺序组织扩展，把大量不可能发生 dominance 的 label 对隔开，并只在必要时做跨 bucket dominance。为保证精确性，资源跨越普通相邻 bucket 关系时还要保留 jump bucket arcs，不能因为分桶而漏掉路径。

该框架的第二个作用是 bucket-arc elimination。利用当前上下界 gap、forward/backward reduced-cost bounds，可以证明某个原始弧在某一段资源区间内不可能属于改进解，从而删除对应 bucket arc，而不一定删除整条原始弧。其主要收益来自三部分：减少 dominance 比较、减少无效扩展、为资源区间级 arc elimination 提供直接数据结构。ng-route、DSSR、rank-1 residual 仍可作为 label 状态叠加在 bucket graph 上。

对 TWET，time-indexed engine 已经按完成时刻建立显式状态，功能上接近“粒度为一个时间单位的 bucket graph”；normal ng-DSSR 的 label 却保存覆盖一段完成时间域的 PWLF frontier。若直接分桶，必须把同一 frontier 按时间区间切片并处理跨 bucket 拼接，可能增加函数碎片。因此不能把 VRP 的标量 bucket label 原样套入当前 PWLF 主线。可借鉴的是按 endpoint 和可完成区间组织 dominance、以及资源区间级 arc fixing，而不是再建一套普通 bucket graph。

### 18.2 Arc-Specific Resource Windows

普通时间窗是顶点级的：无论通过哪条入弧到达任务 `j`，都使用同一个 `[e_j,l_j]`。Arc-specific resource windows 进一步为每条有向弧及前后向分别计算资源允许区间。直观上，一条弧 `i->j` 可能只有在“到达 i 的时间位于 40--55”时才可能出现在优于 incumbent 的完整路径中；更早或更晚使用该弧时，forward cost、该弧成本和 backward completion bound 的总和已经超过 `UB`，于是这部分资源状态可以安全禁止。

若一条弧的允许区间为空，就得到普通 arc elimination；若只剩非空子区间，则保留弧但修改 resource extension，使 label 只有在该区间内才能沿弧扩展。它不增加新的 label resource，也不改变 master，只收紧 pricing 图。其证书来自有效的 forward/backward reduced-cost lower bounds 与当前 gap，不能把某次启发式 dual window 或局部观测直接永久写回。

两种方法可以组合：Bucket Graph 负责把资源域组织成 bucket nodes/arcs；Arc-specific windows 负责说明一条原始弧在哪些资源区间仍可用。前者偏数据结构和 labeling 调度，后者偏基于下界证书的域缩减。Bucket Graph 自带的 bucket-arc elimination 与 arc-specific windows 属于同一类区间级删弧思想，但后者用连续资源窗和修改后的 REF 表述，不依赖必须先把资源域离散成 buckets。

### 18.3 RouteOpt 与 VRPSolver 的 BPC 核心差别

两者的数学主循环并没有根本区别，都是 `RMP -> pricing -> cuts -> branching -> child nodes`，而且都使用 bucket labeling、ng relaxation、rank-1/RCC、enumeration 和多阶段 strong branching。主要差别是抽象层和控制权。

VRPSolver 是 model-driven：用户声明原始 JuMP/数学模型、pricing graph、arc-variable mapping、packing sets 和有限种通用资源，BaPCod 自动组织 decomposition、generic pricing、cuts 和 branching。packing set 是其核心统一抽象，同一个任务集合同时驱动覆盖、elementarity、ng-set、rank-1 cuts、Ryan-Foster/resource branching。优点是标准路径模型接入快、组件自动组合；缺点是问题必须落入其通用 RCSP 资源和成本递推模板，底层标签实现也不便自由修改。

RouteOpt 是 code-driven：公开的 C++ application 直接拥有列、pricing、cutting 和 branching callback，BPC tree/controller 提供公共框架。其 CVRP/VRPTW pricing 与 cuts 更专门化，2LBB/BKF、DeLuxing 和 node restoration 也是显式模块。优点是源码可检查、低层算法可替换，适合研究 branching/pricing/cut 的实现；缺点是增加一种结构差异大的问题时，需要自己实现 application-specific master 和 pricing，而不是只写一份模型声明。

一句话概括：**VRPSolver 是“通用模型接口 + 受控的成熟 BCP 引擎”，RouteOpt 是“开放源码模块 + 专门应用代码”**。对当前 TWET，VRPSolver 的 master/graph 声明更容易起步，但 PWLF pricing 超出其通用模板；RouteOpt 允许真正移植 PWLF pricing，却需要重写大量 application code。二者都不会比继续沿用当前主线更省实现工作。

## 19. 三组概念的具体运行示例

### 19.1 Arc-specific resource window 到底收紧了什么

设任务 `i` 的普通可行完成时间为 `[0,100]`，弧 `i->j` 在整个区间内都满足硬约束，因此普通图预处理不能删除该弧。当前节点已有 incumbent `UB=1000`，master/其余路线提供的下界为 `900`，留给包含当前定价路径的改进空间只有 `100`。对每个可能的时间 `t`，用有效前向下界、弧成本和从 `j` 继续到终点的有效后向下界计算

`forwardLB(i,t) + arcCost(i,j) + backwardLB(j,arrival(t))`。

假设只有 `t in [40,55]` 时该值不超过允许的 gap，而 `t<40` 或 `t>55` 时任何包含 `i->j` 的完整方案都不可能改善 incumbent。普通 arc fixing 只能问“整条弧是否删除”，因为 `[40,55]` 非空，所以什么也删不了；arc-specific window 则保留弧，但把其前向使用域裁成 `[40,55]`。以后 label 到达 `i` 时仍保存精确时间，只有其资源值落在该窗口内才执行 `i->j` 的 resource extension。后向 labeling 使用的状态方向不同，因此通常还要单独保存 backward window，不能机械复用前向区间。

这不是新增时间窗约束，也不是启发式截断。原始硬时间窗回答“路径是否可行”，arc-specific window 回答“一个原本可行的弧-时间状态是否还有可能进入优于当前上界的解”。如果窗口为空，它退化为整弧删除；若只删掉一部分时间域，它比整弧 fixing 更细。安全性完全依赖用于构造窗口的 forward/backward bound 对当前节点有效，不能把一次启发式 pricing 的局部 dual 观察永久写回。

对 TWET normal PWLF pricing，`t` 不是单个 label 值，而是函数 frontier 的横轴。因此迁移该思想不是给 label 多加一个标量，而是在扩展 `i->j` 前把该弧对应的 PWLF 定义域裁到允许区间，再做 `shiftX/shiftY` 和任务 penalty 合成。time-indexed pricing 中则更直接，相当于删除该弧在被证明无用的那些时刻副本。

### 19.2 Bucket Graph 到底怎样减少 labeling 工作

普通 labeling 在任务 `i` 可能积累几千个精确 label，例如完成时间分别为 `21,22,...,97`，每个 label 还带容量、访问记忆和 reduced cost。若全部放在一个无结构列表中，新 label 往往要与大量旧 label 做 dominance 检查；扩展时还会扫描许多实际上不可能到达的后继资源区间。

Bucket Graph 先把资源域划成索引，例如时间 buckets `[0,20),[20,40),...`，若容量也是 main resource，则用 `(时间段,容量段)` 的二维 bucket。label 的真实时间仍然是 `27`，不会被改成 `20` 或 `30`，所以这本身不是近似。它只是被存入 `i@[20,40)` 这个容器。dominance 先在同一 bucket 或经过界证明有必要比较的 buckets 之间进行，避免任意两条 label 全比较。

同时预计算 bucket arcs。若 `i->j` 的 setup/processing 至少推进 13 个时间单位，则 `i@[20,40)` 只能到达 `j` 的若干特定时间 buckets，不需要扫描 `j` 的全部资源域。等待或大跨度资源变化可能跳过中间 bucket，因此 exact 实现还要保留 jump arcs；它们是保证不会因为分桶漏掉合法路径的组成部分。得到新的 gap-based 下界后，还可删除某个具体 bucket arc，例如只禁用 `i@[60,80) -> j@[80,100)`，而不删除原图的整个 `i->j`。

因此 Bucket Graph 同时解决三个实现问题：把 dominance 比较限制在少量相关容器中；预先限制每批 label 的扩展目标；为“只删除某条弧的一段资源域”提供直接结构。它和 arc-specific window 可以叠加：Bucket Graph 是资源状态的地图和索引，arc-specific window 是证明这条弧在哪些地图区段开放。对 TWET time-indexed 图，它近似于把相邻时刻状态组成更粗的组织单元；对 normal PWLF frontier，直接套用会要求按 bucket 切分和重组函数片段，未必比现有函数级 dominance 更快。

### 19.3 RouteOpt 与 VRPSolver 的实际使用差别

两者都运行 BPC，但用户把算法交给求解器的方式相反。用 VRPSolver 建一个标准 VRPTW 时，用户主要声明 master 变量和约束、pricing graph 的 source/sink 和 arcs、时间/容量资源、packing sets、arc-variable mapping、ng neighborhoods 与 branching priority，然后调用求解。BaPCod 负责组织 RMP、通用 RCSP pricing、cuts、branching 和节点树。它接近“把问题描述给一个已有通用引擎”。标准资源递推能够表达的问题接入较快，但新增 PWLF 这种全新 label 对象会越过其建模接口，需要深入改 BaPCod，而且受学术许可约束。

RouteOpt 的使用方式更像“拿一套 BPC 源码开发自己的求解器”。现有 CVRP/VRPTW application 已实现列对象、pricing、cuts 和 branching callbacks；加入 TWET 不是写几条资源声明，而是新增或重写 application，自己实现 PWLF label、列恢复、外包 master、分支约束如何进入 pricing，以及每个 heuristic/exact certificate 的边界。公共树管理、solver adapter、branching controller、rank-1/RCC 等模块可以复用。自由度更高，但实现工作显著更多。

开放性上，RouteOpt 是公开 GitHub 上的 GPL-3.0 项目，可直接 clone、修改，并按 GPL 条件再分发；商业 LP/MIP solver 仍需另行取得。VRPSolver 的 Julia 接口公开，BaPCod 源码可向接受许可的学术用户提供，也允许内部研究修改，但不能像 GPL 软件那样自由传播修改版。所以不是简单的“一个有源码、一个完全没源码”，而是“GPL 开源”与“受限学术 source-available”的差别。

### 19.4 先区分分支对象和分支候选选择方法

`edge/arc branching`、Ryan-Foster 和 resource-consumption branching 是“分什么”；strong branching、3PB、2LBB、BKF 和 pseudo-cost 是“在很多可分对象中怎样选一个”。后五者通常不会改变子节点的数学约束，只改变选择成本与所选分支质量。

**Edge/arc branching。** 定义当前分数解中弧 `i->j` 的总流量 `x_ij=sum_r a_ijr*lambda_r`。若 `x_ij=0.4`，一侧禁止所有包含该弧的未来列，另一侧要求解满足该弧的相反整数条件。它控制的是直接先后关系。TWET 当前的 job arc branching 属于这一类，pricing 很容易通过禁止/强制弧兼容实现。

**Ryan-Foster branching。** 对任务对 `i,j` 定义“二者同属一条路线”的总权重 `z_ij`。若 `z_ij` 分数，一侧要求二者必须由同一路线/同一机器覆盖，另一侧要求二者不能同属一条路线。它只决定是否同组，不决定 `i` 在 `j` 前还是后。VRPSolver 的 packing-set Ryan-Foster 把单个客户推广成 packing sets。对 TWET 可以解释为 same-machine/different-machine branching，但 pricing 必须维护这类成对成员约束，未必比现有 arc branch 简单。

**Resource-consumption branching。** 选择任务或 packing set `j`、某个主资源和阈值 `tau`，一侧只允许服务 `j` 时资源值不超过 `tau`，另一侧只允许不低于 `tau`。在 VRPTW 中通常就是“在 `tau` 之前或之后服务客户”，可通过收紧进入该 packing set 的弧资源界实现。它保持 RCSP 结构，但官方说明该分支族本身不完备，必要时仍需回退到完备分支。

**Strong branching。** 对多个候选的左右两个子节点实际做 trial solve，用两侧 bound improvement 评分，通常质量好但非常贵。

**3PB。** 这是逐层缩小候选集的 strong-branching 流程，而不是第三种分支约束。Phase 0 用 fractionality、pseudo-cost 等廉价指标初筛；Phase 1 只在当前 restricted columns 上改 branch row/列兼容性并重解 LP，不做完整定价；Phase 2 对少量候选运行 heuristic column generation；RouteOpt 还保留 Phase 3 exact CG 接口，对极少候选做完整定价。trial 越往后越接近真实 child bound，也越贵。

**2LBB。** 它仍然从同一批 edge 等分支对象中选候选。第一阶段用学习模型和廉价的图/节点特征代替一部分手工初筛，第二阶段用 partial testing 避免把每个候选两侧都完整测试。机器学习只服务排序，不参与最终定价证书和剪枝，因此最坏情况是选了一个较差分支，不会令 exact BPC 得出错误解。

**BKF/dynamic testing budget。** 它不是新的 branch type，也不等同于机器学习；它动态决定当前节点值得测试多少个候选 `K`。若 trial 很贵、候选分数已明显拉开，就早停；若候选接近且潜在树规模很大，就多测几个。它可套在 3PB 或 2LBB 外面。

**Pseudo-cost。** 它用历史节点上某类分支每单位 fractionality 带来的平均 bound improvement 预测当前候选质量，几乎不需要 trial LP。常用于 3PB Phase 0，或在非 root 节点减少 expensive testing。

因此 RouteOpt 常见的是 `edge branching + 3PB`，也可把候选选择器替换成 `2LBB`，再由 `BKF` 动态决定测试数量；这些名称不代表四种不同子节点约束。VRPSolver 则提供更通用的 packing-set Ryan-Foster、resource-consumption 等分支对象，并用分阶段 strong branching 选择对象。其当前参数文档中的 phase 1 候选上限 100、phase 2 上限 3，描述的是测试预算，不是生成 100 或 3 种不同分支规则。

## 20. 与 time-indexed 的边界及分支策略的实际组合

### 20.1 Arc-specific windows 不是 time-indexed formulation

该方法仍在原始客户图上运行双向 RCSP labeling，没有为每个 `(customer,time)` 建立节点，也没有把原始弧展开成所有时刻副本。每条原始弧只增加前向和后向的资源允许区间，label 仍携带精确连续资源值，REF 扩展时检查区间。它与 time-indexed 的共同点只是都能禁止“某条弧在某段时间的使用”；状态规模、求解方式和 master 都不同。

论文发表于 *INFORMS Journal on Computing* 36(1), 224--244。以只做 arc fixing 的 BPC 为基线，80 个非平凡 Solomon VRPTW 实例上，arc-specific load、time、二者联合的几何平均总时间比分别为 `0.997/0.911/0.896`；联合方案平均约快 10.4%。对基线超过 20 秒的组，联合方案平均约省 25%；基线超过 2000 秒的 5 个实例时间比为 `0.546`，接近减半，并且联合方案是唯一在两小时内解完全部 80 个相关实例的设置。相反，普通 vertex resource-window reduction 虽能收紧 12.8%--14.7% 的窗口，但整体不提速甚至变慢。实验使用 `UB=opt+1`、root-only reduction、双向 bucket labeling、ng=10 和 lm-SRI，因此收益依赖高质量上界与有效双向下界，不能直接外推为 TWET 必然同幅度提速。

### 20.2 Bucket Graph 也不是粗粒度 time-indexed 模型

Bucket node `(i,[20,40))` 是 pricing 内部的容器，里面的 labels 仍分别保存 `t=21,27,39` 等精确值；bucket 只决定 labels 放在哪里、与哪些 labels 比 dominance、向哪些 bucket 扩展。time-indexed graph 的 `(i,t)` 本身就是一个精确状态节点，通常会随 horizon 逐时刻展开。因而可以把 Bucket Graph 类比为“对时间状态做更粗的索引”，但不能把它理解为粗时间离散近似。论文发表于 *Transportation Science* 55(1), 4--28，报告在多类 VRP 上显著减少 dominance checks 和 labeling 时间，并首次求解了一批既有困难实例。

### 20.3 为什么 TWET PWLF 超出 VRPSolver 普通资源接口

VRPSolver 的普通 RCSP label 对每个资源保存一个标量，沿弧执行固定的加法或 `max{lowerBound,old+consumption}`，路径 reduced cost 主要由静态弧系数累加。硬时间窗、容量和固定弧成本都符合这个模板。

TWET normal pricing 的一个 label 却同时表示整个函数 `f(t)=该前缀在完成时间t下的最小reduced cost`。扩展任务时要平移定义域、叠加任务的 earliness/tardiness PWLF、取下包络并做函数 dominance。也就是说，同一前缀同时保留多个时间及其不同成本，而不是一个 `time` 标量加一个 `cost` 标量。这不是再声明一个普通 resource 可以实现的。若强行用 VRPSolver 接口，只能把每个时间状态展开为图节点并把 penalty 静态编码到弧上，等价于走 time-indexed 路线；否则就要修改 BaPCod 的 label 类型、REF、dominance、join 和 certificate 边界。

### 20.4 Ryan-Foster 确实是 non-robust branching

Ryan-Foster 行的列系数是“该 route 是否同时包含 packing sets `B,B'`”。这个系数不能写成每条弧独立贡献之和：看到 `B` 时还不知道以后是否会看到 `B'`。分离侧必须禁止任何完整路径同时包含二者；合并侧必须识别二者是否共同出现。无论实现为二进制 branch state、图复制还是专门 automaton，本质上都要记录 co-occurrence，并相应修改 dominance。活跃 Ryan-Foster 决策增多后，状态可能组合膨胀。VRPSolver 官方文档和论文都明确说明它会让 pricing 更难，应尽量推迟使用，但通常能给出较平衡且完备的搜索树。

对 TWET，它对应 same-machine/different-machine，但当前还有外包选择，必须先定义 `z=1` 是否强制二者都内部加工；normal ng-DSSR 还要携带 branch pair 状态，不能只靠当前 ng-memory。因而它不是比 arc branching 更容易接入的候选。

### 20.5 Accumulated-resource branching 的含义和边界

设 packing set `B_j` 表示服务任务 `j` 的所有入弧，当前 LP 用 `0.5` 条在时间 30 服务 `j` 的路线和 `0.5` 条在时间 70 服务 `j` 的路线。选择阈值 `tau=50` 后，左孩子把 `B_j` 上对应时间资源的上界收紧到 50，右孩子把下界收紧到 50；当前混合解至少在一侧被切开。任何整数解服务 `j` 时最终总落在阈值某一侧，所以这是有效 disjunction。

它不需要新增 label state，只修改已有弧资源界，pricing 仍是同一个 RCSP，因此 VRPSolver 优先使用它。缺点是不完备：有些 fractional route 组合在每个 packing set 上都没有可分的资源混合，最终仍需 Ryan-Foster 等 fallback。Generic Solver 论文的 bin-packing 实验中它有效到一次也没有调用 Ryan-Foster，但这是 bin packing 的证据，不能外推到所有 VRP。对 TWET 可类比为 job completion-time branching；不过一条序列由 PWLF 表示多个可选完成时刻，必须在 child pricing 中裁剪相关函数域，并重新定义现有列能否在 child 内重排，实施并不等同于标准 VRPTW 的标量资源收紧。

### 20.6 3PB、2LBB、BKF 和 pseudo-cost 如何组合

Strong branching 是总类。`3PB` 和 `2LBB` 是两条替代的主要候选选择流水线；`BKF` 是可叠加在任一流水线上的动态测试预算；pseudo-cost 是廉价历史特征，可用于初筛而不与前三者冲突。因此论文实际比较的是 `3PB`、`3PB+BKF(3PB-dy)`、`2LBB`、`2LBB+BKF(2LBB-dy)`，不是要求四选一，也不是把四个模块全部串行执行。

论文中 2LBB-dy 相对固定 3PB 的 headline 是 CVRP 约省 45%、VRPTW 约省 50%。详细组中，BKF 单独用于 3PB 通常也减少时间，但幅度小于 2LBB-dy且并非逐实例稳定；2LBB-dy 的优势依赖同分布训练数据。对没有 TWET 训练数据的当前项目，最可落地的顺序是保留 pseudo-cost/fractionality 初筛和现有多阶段 trial，先研究 `3PB+动态K`；只有 strong branching 仍为主要瓶颈、且积累了足够 trial label 后，才有依据训练 TWET 专属 2LBB。不能直接使用论文的 CVRP/VRPTW 模型。

## 21. Resource window、当前外包分支与 accumulated-resource branching 的进一步核查

### 21.1 Arc-specific resource window 的实际构造

该方法不是把时间离散成节点，也不是先猜一个允许区间。它先在给定对偶解下完成完整的 forward 和 backward labeling，在每个顶点保留全部 nondominated labels。对每条原始弧 `(i,j)`，分别考察四类完整路径：在 `i` 的资源值小于阈值 `t` 时使用该弧、在 `i` 大于 `t` 时使用该弧、使用该弧后在 `j` 小于 `t`、使用该弧后在 `j` 大于 `t`。每一类路径的最小 reduced cost 都通过 forward label、弧扩展和 backward label 的精确 merge 得到。

把该最小 reduced cost 加到当前 dual lower bound 后，如果已经严格超过 incumbent `UB`，就证明任何优于 incumbent 的解都不可能包含这一类“弧+资源区间”状态。例如 `LB[T_i<t,ij]>UB` 时可把弧 `(i,j)` 的 tail lower bound 提高到 `t`；`LB[T_i>t,ij]>UB` 时可降低 tail upper bound；head 两侧同理。每条弧因而保存 tail window `[e_i^{ij},l_i^{ij}]` 和 head window `[e_j^{ij},l_j^{ij}]` 两个区间，而不是只保存一个顶点时间窗。

未来 forward extension 经过 `(i,j)` 时使用 head window，执行 `T_j=max(e_j^{ij},T_i+tau_ij)` 并检查 `T_j<=l_j^{ij}`；backward extension 使用 tail window，执行 `T_i=min(l_i^{ij},T_j-tau_ij)` 并检查 `T_i>=e_i^{ij}`。例如证明 tail 只可能在 `[35,70]`、head 只可能在 `[50,90]` 后，forward label 到达 `i` 的时间仍是精确值 `40`，扩展后得到 `max(50,40+tau_ij)`；结果超过 90 才拒绝。一个时间为 20 的 label 仍可从 `i` 走其他弧，只是不能在该时刻走 `(i,j)`。这正是它比普通 vertex-window reduction 更细的地方。

算法不需要遍历每个整数时刻。上述 lower-bound functions 是由有限 label 资源值形成的单调分段常数函数，只在 breakpoints 上更新即可；不同 cut round 的对偶解还能对同一 property 的 lower bound 逐点取最大值。代价是必须从通常的 halfway bidirectional pricing 补全至少一个方向乃至两个方向的完整 labels，因此论文只在 root 和 cut rounds 后做 reduction，而不是每个 pricing round、每个树节点都做。

### 21.2 当前代码在有外包时怎样分支

当前默认配置是 `outsourcingModel="masterVariables"`，即 SP2。它的严格分支优先级是 `TariffSegmentBrancher -> MachineCountBrancher -> optional UndirectedAdjacencyBrancher -> ArcBrancher`，默认 undirected adjacency 又是关闭的，因此实际通常是“外包 tariff segment 先、机器数第二、内部 arc 第三”。显式任务外包变量 `y_j` 没有自己的 brancher；`LP.isIntegerSolution()` 仍检查每个 `y_j`。代码依赖的结构是：内部列整数后，未被内部覆盖的任务由 `0<=y_j<=1` 和覆盖行强制为 1，已经内部覆盖的任务在正常非递减外包费用下取 0；tariff segment 的离散性由第一层分支保证。

若配置切换为列化外包 `columns/columnized/sp1`，顺序才是 `MachineCount -> optional UndirectedAdjacency -> Arc -> OutsourcingMembership`。这时可概括为“先机器数和内部机器结构，最后分任务是否属于外包集合”。membership 左支 `forbidOutsourcingJob(j)`，右支 `requireOutsourcingJob(j)`；右支会排除所有包含 `j` 的内部列，并 seed 一条覆盖当前 required jobs 的外包集合列。机器数只统计内部机器列，不统计那条外包集合列。

`Tree` 对 brancher 列表逐个处理，对当前 brancher 先做 strong selection；只要该分支族存在候选就创建 children 并停止，不会把 tariff、machine、arc 和 outsourcing candidates 放进同一个全局 strong-branching 比较。因此 SP1 的“外包最后”与 SP2 的“tariff 最先”都是严格层级，而不是候选排序上的轻微偏好。

### 21.3 Accumulated-resource branching 的来源、实际步骤和实验边界

该思想由 Gélinas、Desrochers、Desrosiers 和 Solomon 在 1995 年的 *A new branching strategy for time constrained routing problems with application to backhauling* 中系统提出。原算法从当前正权 fractional routes 出发，对每个客户 `i`、每条相关路线 `r` 计算该路线仍可服务 `i` 的 earliest/latest interval `[l_i^r,u_i^r]`。若某个客户满足 `max_r l_i^r > min_r u_i^r`，就能在两者之间选整数阈值 `t`，创建 `[a_i,t]` 和 `[t+1,b_i]` 两个孩子；当前 fractional route mixture 在左右两边都会至少损失一条路线，但所有整数服务时间仍完整地落在某一侧。

原论文在时间窗较紧、time 是主要约束的测试上，相对 flow/arc branching 平均减少约 66% 的 branch nodes、54% 的总时间；但在宽时间窗的 `r104` 变体上，切完后仍有很多相近路线可行，time branching 没解完而 arc branching 解完。结论不是“resource branch 总比 arc 强”，而是应选当前真正 binding 的资源。

Pessoa 等 2020 年的 Generic Solver/VRPSolver 将其推广到 packing set `S`、main resource `r` 和 threshold `t*`：左支把 `S` 中对应 arcs 的 resource upper bound 改成 `t*`，右支把 lower bound 改成 `t*`。它不新增 label state，也不改变 RCSP 的资源维数，所以 pricing difficulty 基本不变；但该分支族不完备，仍需 original-variable 或 Ryan-Foster fallback。现代专用 CVRP/VRPTW 求解器通常优先车辆数和 edge/arc branching，这一规则属于有稳定实现但不算主流默认的分支。它在 bin/vector packing 上更突出：Generic Solver 的 bin-packing 实验把 resource branch 置于 Ryan-Foster 之前，所有实验中都没有实际回退到 Ryan-Foster；这是特定 packing 模型和完整 solver stack 的结果，不是可直接外推到 TWET 的独立消融。

### 21.4 能否用于 TWET

数学上最自然的候选是 job completion-time branching：选择内部任务 `j` 和阈值 `tau`，左右支分别要求 `C_j<=tau` 和 `C_j>=tau`。对 time-indexed pricing，禁止一侧的 `(j,t)` 状态即可；对 normal PWLF pricing，则要裁剪所有服务 `j` 的 frontier domain。真正的障碍在 master column 语义：标准 VRPTW 的 route cost 通常只由行驶距离决定，缩时间窗只改变 route feasibility，不改变同一路线的成本；TWET 的列成本是该 sequence 在完成时间域上优化 earliness/tardiness PWLF 后的最小值。同一 sequence 在两个 child 中可能都可行但有两个不同最优成本。

当前 `Pool` 用 `SequenceSignature` 全局唯一化列，并只保留同一 sequence 已知的最低成本版本。因此不能把现有列简单标成“兼容/不兼容”，也不能把一个 child 的重算成本写回全局列后供另一个 child 使用。要正确实现，至少需要 node-local column cost/evaluation，或把列身份扩成 `sequence + branch resource domain` 并允许同序列多列；normal pricing、strong trial、route enumeration 和 seed 继承都要同步适配。这已不是一个低成本的新 brancher。

外包又增加一个完备性问题：若 `j` 被外包，`C_j` 不存在，二分 `C_j<=tau/C_j>=tau` 并不覆盖该整数解。可行的定义要么先分 `j` 内部/外包，仅在内部支继续 completion-time branching；要么人为给外包定义 sentinel resource 并明确归入某一侧。前一种较自然，但默认 SP2 当前没有 per-job outsourcing branch，而且会改变既有分支层级。

因此当前不建议直接实现 completion-time resource branching。若只想做低成本诊断，可先在无外包或已强制内部的实例上统计：正值内部列在各 job 上是否经常形成两个互斥可行 completion intervals、可用阈值能切掉多少 LP mass、出现位置是在 arc 候选之前还是之后。只有这种现象频繁且树搜索确实是主要耗时，才值得承担列语义改造。若改用完全由 sequence 决定的累计 processing/setup 或 job position 作为资源，可以保留现有列成本，但预计与 arc/order branching 高度相关，也失去了原论文利用紧时间资源的主要优势。

### 21.5 对 3PB、2LBB、BKF 和 pseudo-cost 的当前判断

它们确实只是 branching-selection 策略，不会增强 LP relaxation，不会降低一次 ng-DSSR exact pricing 的 label 数，也不会改善 certificate。当前瓶颈若在 root preprocessing 或 ng-DSSR pricing，它们应排在后面。只有树较大且 strong trials 已占显著时间时，这类策略才会通过减少 trial 数或改善树形产生明显总时间差；2LBB-dy 的约 45%/50% 结果属于这种场景。

当前 TWET 代码更接近固定预算的简化 3PB：每个分支族按 fractionality 取至多 20 个候选，phase 1 做左右 trial RMP，正式默认 phase 2 候选数为 0。`Node.pseudoCost` 当前主要保存父 bound 并参与节点队列优先级，不是经典的“按 branch candidate 和方向累计单位 bound improvement”的 learned pseudo-cost；代码也没有 BKF 或 2LBB。由此，除非新 profile 再次显示 strong-trial RMP 是主耗时，否则无需为这四项改流程。

## 22. Resource-window 断点、SP1/SP2 分支及 completion-time branching 的最终澄清

### 22.1 Resource-window reduction 不逐整数时刻枚举

论文构造的是关于阈值 `t` 的单调分段常数 lower-bound function。函数只会在 forward/backward labels 实际携带的资源值以及相应扩展值处跳变，因此实现时应按这些 breakpoints 排序扫描，而不是对 `0,1,...,H` 每个离散时刻重新做一次完整 merge。对 `<t` 类 property 可随 `t` 增大逐步纳入越过断点的 labels，对 `>t` 类 property 反向扫描；只有用 time-indexed 图表示资源时，逐状态扫描才会自然表现为逐时刻处理，但那是数据表示，不是论文算法的要求。

对一条给定弧 `(i,j)`，需要处理的时间不是一个统一的 `0...H` 列表，而是由 Proposition 5 的四个公式分别决定。tail 下界窗口 `e_i^{ij}` 只在 forward label 的 `F.time` 处检查，因为 `LB[T_i<t,ij]` 的候选集合由 `F.time<t` 决定；tail 上界窗口 `l_i^{ij}` 只在 backward label 穿过 `(i,j)` 后得到的 `b_ij(B).time` 处检查，因为 `LB[T_i>t,ij]` 的候选集合由 `b_ij(B).time>t` 决定。head 下界窗口 `e_j^{ij}` 只在 forward label 穿过弧后得到的 `f_ij(F).time` 处检查；head 上界窗口 `l_j^{ij}` 只在 backward label 自身的 `B.time` 处检查。也就是说，四个断点集分别是 `{F.time:F in F_i}`、`{b_ij(B).time:B in B_j}`、`{f_ij(F).time:F in F_i}` 和 `{B.time:B in B_j}`，只保留可行扩展产生的值并排序去重。相邻两个断点之间，严格不等式筛出的 label 集不变，lower bound 也不变，没有必要检查中间时刻；在断点处则按 `<` 的左连续、`>` 的右连续语义处理等号。

更具体地，设弧 `(i,j)` 的时间消耗 `tau_ij=10`。三条 forward labels `F1/F2/F3` 分别表示三种从源点走到 `i` 的 partial path，其 `F.time={12,20,37}` 是各自能在 `i` 开始服务的最早时间；两条 backward labels `B1/B2` 分别表示两种从 `j` 走到终点的 partial suffix，其 `B.time={55,70}` 是为了保证后缀可行、最晚能在 `j` 开始服务的时间。忽略窗口截断时，forward labels 穿过该弧后在 `j` 的最早时间为 `f_ij(F).time=F.time+10={22,30,47}`，backward labels 反向穿过该弧后在 `i` 的最晚时间为 `b_ij(B).time=B.time-10={45,60}`。所以前四组时间并非四批独立样本，而是同一批 prefix/suffix labels 在弧两端的 earliest/latest 表示。

再设兼容 merge 的相对 reduced-cost lower bound 为 `m(F1,B1)=9,m(F1,B2)=8,m(F2,B1)=7,m(F2,B2)=8,m(F3,B1)=2,m(F3,B2)=8`，当前 gap 为5。对 tail 下界，在 `t=37` 时性质 `T_i<t` 只允许 `F1/F2`，其最小 merge bound 为7，大于gap，因此所有能在37以前使用该弧的完整路线都可排除，可令 `e_i^{ij}=37`；阈值一旦越过37，`F3` 被纳入且 `m(F3,B1)=2`，便不能继续提高下界。对 tail 上界，在 `t=45` 时性质 `T_i>t` 只保留反向扩展时间大于45的 `B2`，相关 merge bound 最小为8，因此可令 `l_i^{ij}=45`。完全相同地，head 下界在 `t=47` 时只纳入 `F1/F2`，可令 `e_j^{ij}=47`；head 上界在 `t=55` 时只保留 `B2`，可令 `l_j^{ij}=55`。最终该弧只允许在 tail 时间 `[37,45]`、head 时间 `[47,55]` 内使用；forward REF 直接计算 `T_j=max(47,T_i+10)` 并检查 `T_j<=55`，因此超出这些区间的 label 在扩展时立即删除。即使 horizon 是10000，也只处理上述 label 时间断点。窗口改变后，下一轮 complete labeling 再按新的 labels 生成新的有限断点集。

论文所说的 aggregation 也不是先得到每个时刻的结果再把相邻时刻聚合，而是对 root/cut rounds 中得到的多组对偶解逐点取最大值：`LB*(t)=max_p LB(pi_p,t)`。实际只需增量维护当前最大分段函数。再利用整数目标和 incumbent gap 把超过 `UB` 的值统一截为 `UB+epsilon`、其余值按安全规则取整后，跳点数量主要受 `UB-LB` 控制，而不是直接受 horizon 控制。TWET normal PWLF 若迁移，应处理 label/PWLF 的断点；按每个整数完成时刻扫描会丢掉该方法本来的紧凑性。

### 22.2 核心贡献及对 TWET 的预期幅度

“把普通 arc fixing 细化成 arc 的一段资源域 fixing”是正确的核心直觉：普通 fixing 只有整条弧保留或删除，arc-specific window 可以保留 `(i,j)`，但只允许它在 tail/head 的某个完成时间区间内使用；窗口为空时自然退化为整弧删除。不过论文完整贡献还包括 property-based reduced-cost lower bounds、forward/backward 各自的 tail/head windows、多对偶解累积、紧凑分段函数存储以及修改后的双向 REF，并不只是给已有 arc fixing 多加两个端点。

对当前 TWET，默认预期应是中等而不是数量级收益。论文总体约快 10%，困难组约 25%，最难尾部才接近减半；同时当前 time-indexed 图本来就能删除 `(arc,time)` 状态，normal ng-DSSR 也已有 completion-bound/window tightening，新增区间很可能与现有缩减重叠。只有在大量弧无法整弧删除、但其可用完成时间域已非常窄，而且这些弧仍制造大量 PWLF extension 时，增量收益才可能明显。实施前应先统计“surviving arc 的保留时间宽度/原宽度”和这些部分时间域对应的 extension 数，而不是仅看 fixed arc 数。

### 22.3 论文与当前 SP1/SP2 分支的精确差异

Dabia、Lai 和 Vigo 的 SP2 先选择最分数的 tariff segment `z_s`，直接建立 `z_s<=0` 与 `z_s>=1` 两个孩子；论文没有对多个 tariff candidates 做左右 trial。等所有 `z_s` 整数后，才回到 SP1 的车辆数、车型车辆数、无向 arc、定向 arc 层级，并在这些候选上使用 strong branching。因而“论文中的 tariff 分支不使用 strong branching”是正确的。

当前代码则不同，但不能概括为“所有分支都做 strong branching”。`Tree` 的确会对 brancher 列表中的每个分支器先调用 `tryTwoStageStrongBranching()`；只有覆盖了 `collectStrongBranchingCandidates()` 并返回非空候选的分支器才真正执行左右 trials。当前 `ArcBrancher`、`TariffSegmentBrancher` 和 SP1 的 `OutsourcingMembershipBrancher` 实现了该接口，`MachineCountBrancher` 与可选的 `UndirectedAdjacencyBrancher` 沿用接口默认空集合，因此直接调用普通 `branch()`。所以 SP2 的实际层级是 tariff 做 strong、机器数直接分、可选无向相邻直接分、最后 arc 做 strong；SP1 则是机器数直接分、可选无向相邻直接分、arc 做 strong、最后 membership 做 strong。每个节点仍在第一个有候选的分支族处停止，不做跨分支族全局比较。

这意味着当前 SP2 tariff 确实会做 phase-1 左右 RMP trials，但这是 tariff 分支自身实现了 strong candidates 的结果，不是 `Tree` 调用入口就能令任意 brancher 自动 strong。该差异不影响正确性，却会为最多三个正式 tariff segments 增加最多六次 trial RMP；若要严格对齐论文并减少额外试算，应让 tariff brancher 直接按 fractionality 分支。是否总时间更快仍需 A/B，因为省 trial 可能换来稍差的树。

在当前正式数据和默认 strong branching 开启的配置下，SP1/SP2 的外包逻辑没有发现主线正确性错误。SP2 的 `y_j`、tariff quantity/segment linking 和 segment integrality 完整；不单独对 `y_j` 分支依赖 `b_j>0` 且 `G` 严格非递减，使内部覆盖为 0 时 `y_j=1`、已有内部覆盖时最优 `y_j=0`。正式三段 tariff 的边际费率为正，满足该前提。SP1 的唯一外包集合列、membership rows、required/forbidden pricing domain 和外包 exact certificate 也一致；其 dominance 同样依赖 `G` 非递减。

但有两个配置边界不能混同为无条件正确。第一，通用数据读取器只补 tariff 定义域，不验证连续性和单调性；零/负边际费率可能使 SP2 的无 `y_j` brancher 逻辑退化，也会破坏 SP1 当前 dominance 的前提。第二，SP1 若关闭 two-stage strong branching，普通 membership 右支的 child seed 可能保留父 LP 中取正值、但包含 required-outsourcing job 的内部列。比如父 LP 有正值内部列 `(1,2)`，又在“任务1是否属于外包集合”上取分数；右支要求任务1外包后，新的内部 pricing 不会再生成含1的列，但继承的 `(1,2)` 仍可能留在 RMP。当前 membership master row 只要求“所选外包集合包含1”，没有同时给所有含1的内部列加 `lambda=0` 行；普通 seed 筛选又为保持首次 LP 可行而保留父正值列，于是右支可能同时内部加工和外包任务1，得到比预期 child 更大的 relaxation，甚至形成双重覆盖的整数 master 解。默认配置下，membership 候选会完整执行 two-stage strong trial，并启用 branch-implied penalty 与 Phase-I repair：不兼容继承列若取正会触发 repair，repair 闭合后先从 restricted set 删除，再重解真实成本 RMP，只有该 trial 可复用时才把清理后的列集交给正式 child。因而正常成功路径不受影响；这里所需的条件不只是“进入 strong 入口”，而是上述 penalty/repair/seed-reuse 链完整执行。若以后关闭 two-stage strong branching、branch-implied penalty 或 Phase-I repair，应在普通 child 路径显式过滤/固定这些内部列并配套 feasibility repair，不能依赖 strong trial 做语义清理。

另有一个不属于外包模型、但会阻止“strong 开启即无条件安全”这一表述的通用异常边界：strong trial 若因 CPLEX 异常或未知状态返回 `NOT_SOLVED`，`StrongBranchingTrialResult` 会标为 unusable 且不能复用 seed。原控制流仍可能返回该 candidate，随后在 child 未入队时把父节点视为已分支。现已按正式节点 master 的既有失败语义做最小修正：任一 phase1/phase2 trial 在试算现场出现 unusable 就立即向上传播，不再参与候选排序；主循环在现有 trace 中记录 candidate、phase、左右 bound/message 和候选预览，设置 `failedByMaster` 并立即停止整棵树，最终返回 `FAILED`。失败时即使 open queue 为空也保留最后一个可信 bound，不再误报成 incumbent/gap=0。正常成功 trial、明确 infeasible、dual-bound closure 和显式 time limit 路径不变。

再次沿 CPLEX 状态链复核后，当前口径仍然成立：`cplex.solve()==false` 时，只有 `IloCplex.Status.Infeasible` 被映射为 `INFEASIBLE`，其余状态以及建模、求解、解读取阶段抛出的 `IloException` 都映射为 `NOT_SOLVED`；因此 unknown、unbounded、数值错误等未获证明的结果不会被拿去关闭节点。正式 node 的初始 RMP、筛列后 RMP 和 pricing loop 重解均会把该状态返回给 `Tree` 并终止为 `FAILED`；strong trial 则先标记 unusable，再由上述新路径立即终止。正式/strong RMP 没有设置 CPLEX 局部 time limit，项目 wall-clock time limit 由独立 checker 控制，所以正常超时仍走既有 `TIME_LIMIT` 路径。

旧 VRP 参考工程没有对应的显式状态控制。其 `LP.Solve()` 只返回 `cplex.solve()` 的 boolean，但 `GCNGBB.Solve()` 忽略该返回值并立即调用 `GetDual()`，`PC.Solve()` 最终也固定返回 true；若求解失败，通常只能依赖随后读取 dual/value 时抛出的 `IloException` 被动中止。各 `Branch*.UpdateRouteSet()` 虽检查 `cplex.solve()` 的 boolean，却把 `false` 与 restricted RMP 不可行或人工 slack 未归零统一送入补列 repair，没有读取 `cplex.getStatus()`，因此 unknown 与 infeasible 并未区分。当前 TWET 的处理不是照抄旧 VRP，而是比旧实现更严格的正确性保护。

### 22.4 不考虑外包时 completion-time branching 应怎样实现

数学二分仍是选任务 `j` 和阈值 `tau`，建立 `C_j<=tau` 与 `C_j>=tau+1` 两侧；后一写法需要先固定“整数数据存在整数最优完成时间”的口径，连续时间口径则要用覆盖完整定义域的左右区间并处理边界点。这里切开的不是原始软 due window `[d_e[j],d_l[j]]`，而是当前节点的硬可行完成时间域 `[L_j,U_j]`：左孩子变成 `[L_j,min(U_j,tau)]`，右孩子变成 `[max(L_j,tau+1),U_j]`，原有 earliness/tardiness penalty function 完全不变。只有当 `tau` 恰好落在 due window 内时，表面上才像把 due window 从该点切开。它可能比 arc branch 更贴近 TWET，因为一侧可以统一切掉所有 predecessor 下的 early/tardy 完成区间，尤其适合当前 LP 同时混合 due-window 两侧调度的任务；但它仍不完备，arc branch 必须保留为 fallback。

当前不能把它实现成一个只给现有列加 0/1 系数的普通 branch row。`TWETColumn` 的身份只有 sequence，cost 是该 sequence 在全部可行完成时间中优化后的最小 TWET cost。同一 sequence 在左右孩子中可能都可行，却分别产生不同最优成本；用父节点 `evaluateTiming()` 得到的一个完成时刻把整条 sequence 判给某一侧，会错误删除另一侧可重排的可行方案。

当前“一个 sequence 在 Pool 中唯一”的数据结构与仓库里的旧 VRP 参考实现表面一致。旧 `BPC.LP.Pool` 也用 `HashMap<ArrayList<Integer>,Integer>` 按 route/job sequence 判重，同一路线只保留一个 id；当前改成 `SequenceSignature -> id`，并允许同序列出现更低成本时更新。关键语义却不同：旧 VRP 的 route objective coefficient 是路线的行驶距离/固定费用，时间只作为 feasibility resource，收紧客户服务时间窗不会改变同一路线的目标系数。因此 resource branching 后同一路线只需判断还能否排出可行服务时间，能则沿用原 cost，不能则删除。TWET 的 completion time 直接决定 earliness/tardiness cost，收紧 `C_j` 后同一 sequence 即使仍可行，最小 cost 也会改变。所以“按序列唯一”本身与旧 VRP 一致，但旧 VRP 在资源分支下仍能安全复用一个全局 scalar cost，当前 TWET 不能。仓库里的旧 VRP 参考代码本身只实现了机器数/arc 分支，没有实现这里讨论的 completion-time resource branch；上述比较针对其列语义，而不是说旧代码已有可直接复制的实现。

若以后实现并继续保留 PWLF compact column，正确路径是把 `Pool` 仅作为 structural sequence pool，`Node` 保存各任务 completion lower/upper bounds，并增加按 `(columnId,node-bound-version)` 缓存的 node-local sequence evaluator。每个 child 构造 RMP 时都以本节点边界重算父列成本；pricing 在服务 `j` 时裁剪相应 PWLF domain；seed、RMIH、route enumeration、incumbent timing 和 strong trial 全部使用 node-local cost，且绝不能把某个 child 的成本写回当前全局 `Pool.addOrImproveColumn()`。resource candidate 可先按正值列的 canonical completion times 构造加权分布，取能平衡左右 LP mass 的 weighted median，并优先考虑靠近 `d_e[j]/d_l[j]` 的 PWLF 斜率断点；这只负责选候选，左右孩子的真实可行性和成本仍必须由 constrained evaluator 决定。

这条实现会使 strong trial 不能继续复用父列的固定 objective coefficients。第一版若真做，应先不对 completion-time candidates 做 strong branching，或为每个 side 重算全部 trial 列成本后再解 RMP；直接沿用当前 strong RMP 会得到错误评分。更低风险的前置诊断是只对若干现有节点的正值 sequence 做左右 constrained evaluation，记录两侧不可行/重定价的 LP mass、restricted-RMP bound gain 和重算成本。若多数 sequence 在两侧都能低成本重排，说明该分支在 TWET 上不会像紧窗 VRPTW 那样强，不值得改造主线列语义。

## 23. 排除硬时间窗技术后的下一批前沿方法

### 23.1 当前筛选边界

Arc-specific resource windows 不是因为软时间窗而在数学上完全不可用：TWET 仍有硬可行完成时间域，也能基于有效 gap bound 删除 `(arc,time)` 状态。但 normal PWLF pricing 要把点级结论压回连续函数域，且当前 time-indexed root preprocessing 已直接处理时间状态，normal ng-DSSR 也已有 completion bound、dual window 和时间域收紧，因此新增收益大概率与现有预处理重叠。除非后续统计显示大量 surviving arcs 只在很窄时间域制造 label，否则不再优先实现。

SRI unreachability 只在 active rank-1/SRI cuts 使 pricing graph 额外复杂时有直接价值，不能改善当前无 SRI 的 ng-DSSR 主线。Bucket Graph 的 exact 分桶理论并不依赖硬时间窗，但把 normal PWLF frontier 拆入 bucket、跨 bucket 维护函数 dominance 和 join 会增加一套状态组织；time-indexed pricer又已提供更细的精确时间状态。因此这两项也退出当前候选。

### 23.2 第一优先：arc-based 与 fully dynamic ng-memory

最值得继续分析的是 Bulhoes、Sadykov 和 Uchoa 的 Minimum Latency Problem BPC。Minimum Latency 的路径目标直接累积客户完成/到达时间，比固定行驶成本的 VRPTW 更接近 TWET。论文除了 multiple partial label dominance，还提出两项与当前瓶颈直接相关的机制：一是把“访问任务 `j` 后哪些状态继续记住 `j`”从 vertex-based ng set 细化为 arc-based ng memory，只禁止目标 cycle 所需的弧前缀，减少一次 pair 更新对其他合法路径的连带限制；二是 fully dynamic ng strategy，在定价过慢时从较小 memory 重新构造，并逐步补回足以复现当前 lower bound 的限制，不让长期累积的旧 ng pairs 永久扩大 label state。论文报告求解了若干此前开放的 MLP 实例，测试规模达到 200 个客户。正文和技术报告分别见 [Computers & Operations Research 论文](https://www.sciencedirect.com/science/article/pii/S0305054818300248) 与 [开放技术报告](https://www.math.u-bordeaux.fr/~rsadykov/papers/BulhoesSadykovUchoa_LOGIS17.pdf)。

这比给当前 top-C witness 再换一个评分函数更值得研究。现有实现已经能保留多条有效非初等 witness、选择最短重复段、跳过已被新 pair 阻断的路线并限制每轮真实更新数，剩余问题不是“有没有多 witness”，而是 vertex-pair 更新是否过度禁止、哪些历史 pairs 对当前 dual certificate 已经没有贡献。下一步应先精确映射论文的 lower-bound-preserving reduction 条件与当前“DSSR 仅作为一次 pricing call 的内部 exactification”语义，不能直接照搬动态删 pair；同时比较现有 partial dominance 是否已经覆盖论文 MPLD，避免重复实现。

Roberti 和 Mingozzi 的 *Dynamic ng-Path Relaxation for the Delivery Man Problem* 是这条路线的直接前驱。它研究如何依据当前非初等路径动态重定义允许的 subtours，并维持单调改进的 lower bounds，也采用与完成时间累积相关的目标。该文适合和 MLP 论文一起读，用来区分三件事：当前单次 exact pricing 内的 DSSR 更新、跨定价调用复用的 warm history、以及 master relaxation 层面的 dynamic ng memory。来源见 [Transportation Science 论文](https://pubsonline.informs.org/doi/10.1287/trsc.2013.0474)。

### 23.3 第二优先：Selective Pricing

Desaulniers、Pecin 和 Contardo 的 Selective Pricing 不是通过扩大 ng set 直到完整 elementarity，而是允许 relaxed pricer 丢弃一部分 relaxed routes，只要仍能保证：存在负 reduced-cost elementary route 时，就至少返回一条可用负列。其 VRPTW 实验在困难的 200-customer 实例上，把达到高质量 lower bound 的时间最多降低约 32%。来源见 [EURO Journal on Transportation and Logistics 论文](https://www.sciencedirect.com/science/article/pii/S2192437620300303) 和 [开放稿](https://pure.eur.nl/ws/portalfiles/portal/48204101/Repub_116700.pdf)。

它与当前目标直接相关，因为它尝试减少“为了一个 exact negative column 或 no-negative certificate 而完成全部 DSSR 收紧”的工作。不过可迁移前提很强：必须针对 PWLF label、双向 join 和当前 dominance 证明 selective discard 不会把所有负 elementary paths 一起删掉。它不是一个启发式候选过滤开关；证明做不到时只能作为前置 heuristic，不能承担 exact certificate。因此优先级低于 arc-based/fully dynamic ng-memory，但高于改造整个 master。

### 23.4 第三优先：master 稳定化与整棵树方法

Smooth and Flexible Dual Optimal Inequalities 及其面向 relaxed columns 的版本，是减少 dual oscillation 和无效 CG rounds 的另一条路线。后者专门讨论 ng-route relaxed columns，在不削弱最终 relaxation 的前提下加入可恢复的 dual inequalities；来源见 [Relaxed Dual Optimal Inequalities for Relaxed Columns](https://arxiv.org/abs/2004.05499) 和 [Smooth and Flexible Dual Optimal Inequalities](https://pubsonline.informs.org/doi/10.1287/ijoo.2021.0057)。软时间窗本身不是障碍，真正困难是为 sequence-dependent setup 与 completion-time PWLF 构造有效的任务交换/删除成本界。当前简单 dual smoothing 无效，不能据此否定 DOI，但 DOI 需要单独数学推导，不是近期低风险修改。

如果后续 profile 显示瓶颈转到整棵 BPC 而不是 root/ng-DSSR certificate，则仍保留 Cluster Branching 和非机器学习的 dynamic strong-testing budget。Cluster Branching 改的是 robust arc aggregate 分支对象，2LBB/BKF 改的是 strong trial 测试预算；它们不受软时间窗影响，也不会直接降低一次 ng-DSSR labeling 的复杂度。现阶段应先完成 arc-based/dynamic ng-memory 的语义与实现对照，再决定是否回到这两项。

Local Area Routes 虽然是 ng-route 的直接替代松弛，但它依赖可预计算的局部 elementary subpath cost。TWET 局部子序列成本随进入完成时间变化，正确迁移需要把 LA arc 从一个标量改成 PWLF transfer function，并重写 dominance、join 和 column recovery，已经属于新定价框架。DeLuxing、Column Elimination、Graph Master 和 completion-time branching 同样改变枚举/master/列语义，不再作为当前 ng-DSSR 强化的近期候选。

本轮新增方法中先核对 `Bulhoes-Sadykov-Uchoa 2018 MLP`，再判断 Selective Pricing 是否值得进入 PWLF exact-pricing 设计；Roberti-Mingozzi 2014 只作为前者的历史基线，relaxed DOI 排在原始前沿方法清单讨论完成之后。MLP 方向首先要回答：当前 vertex-pair ng 更新实际过度阻断了多少路径；历史 ng pairs 中有多少对当前 dual lower bound 已无贡献；能否在不改变 exact certificate 的前提下使用 arc memory 或按当前 dual 重建更小 memory。只有这些问题出现明确正证据，才进入实现设计。

## 24. Arc-window 离散化、arc-based ng 消融及未完成方法清单的纠正

### 24.1 TWET normal PWLF 没有可直接复用的 scalar-label breakpoint 列表

Arc-specific resource-window 原论文不逐整数时刻扫描，是因为每条普通 RCSP label 只有一个标量资源值，关于阈值的候选集合只会在这些 label time 上改变。TWET normal pricer 的一条 label 表示整个 PWLF frontier，没有同样可直接排序的单个 `label.time`。理论上仍可从所有 PWLF 段端点、前后向 merge 函数交点和 gap crossing 构造有限 breakpoints，但这等于为每条 arc 的四类 property 再构造并维护 lower-envelope PWLF，复杂度和实现成本都明显高于原论文。

因此实践判断应修正为：不是数学上必须枚举全部时间点；但若不新增 per-arc lower-envelope 算法，当前最直接的 exact 实现确实只能在整数时间域逐点检查。time-indexed preprocessing 已经在 `(arc,time)` 状态上做了更细的处理，再实现一遍 arc window 没有明显价值。normal PWLF 上只在有证据表明 surviving arc 的有效时间域很窄、且这些扩展占主要时间时才值得重新考虑。

### 24.2 Arc-based ng-memory 到底改变什么

传统 vertex-based memory 对重复环 `H=(i0,i1,...,ip,i0)`，需要把中间顶点 `i1,...,ip` 加入“记住 `i0`”的 vertex memories。这不只禁止目标环，还会禁止经过这些顶点任意子集、并持续记住 `i0` 的一批其他回路，容易让 memory 对 labeling 的影响过大。arc-based memory 改为让“某条 arc 是否继续记住任务 `i0`”成为基本单位；针对上述环，只把前缀 arcs `(i0,i1),...,(i_{p-1},ip)` 加入 `i0` 的 arc memory。这样主要禁止目标前缀族，不会因为经过同一批顶点就自动产生同样强的限制。

对应到 label 更新，vertex-based 近似为经过顶点 `v` 后执行 `remembered = remembered intersect N_v`；arc-based 则经过 `(u,v)` 后按该 arc 的 memory mask 执行 `remembered = remembered intersect M_(u,v)`。当前 TWET 使用 `ngNeighborhoodByJob` 和“把 repeated job 加入中间 job neighborhood”的 vertex-pair 更新，尚没有 arc mask 这一层。迁移会同时影响 forward/backward memory 更新、join compatibility、DSSR cycle update 和 history 表示，不是只把一个集合换成另一个集合。

### 24.3 论文没有给出 arc 对 vertex 的统一倍数

Bulhoes、Sadykov 和 Uchoa 的论文只有 multiple partial label dominance 做了干净消融：固定 ng size 为 8、12、16 时，平均 labeling 加速分别为 `4.37/6.01/7.28` 倍。Arc-based memory 和 fully dynamic reduction 没有单独的平均时间比或逐组件消融表；主表同时包含 MPLD、arc memory、memory reduction、dual stabilization、reduced-cost fixing、enumeration 和 strong branching，不能从整套 B&P 结果反推 arc memory 的独立增益。

论文给出的直接证据是实例依赖而非统一占优：`pr124` 只用 arc-based augmentation 两天内无法求解；`pr136/pr144/pr152` 则主要依赖 arc-based augmentation 才首次求解。最终稳健策略是先做较激进、接近 vertex-based 影响范围的 augmentation；当单次 labeling 超过 `100s` 时，中断 CG，调用 memory reduction，并切换到 moderate arc-based augmentation。两天配置首次求解 6 个此前开放实例；五天的 moderate 长跑又解出 `pr136/pr152/kroB150`，合计解出 Roberti-Mingozzi 2014 未解的 9 个实例，并把测试扩到 200 个顶点。但这些是整套算法结果，不是 arc memory 单项提速。

Fully dynamic reduction 也不是任意删除历史 memory。给定当前 memory `M_ori` 和当前 dual `pi*`，算法从空 memory 重新 pricing；若当前最优 relaxed route 在 `M_ori` 下仍 ng-feasible，则已经复现原 lower bound并停止；否则只在 `M_ori` 允许的范围内用 moderate augmentation 阻断当前 route，再 pricing，直到得到 `LB(M_new)=LB(M_ori)`。作者明确指出 reduction 调用过于频繁会在大实例上很耗时并破坏外层收敛，因此它是定价已经失控后的重建机制，不是每轮清理。

开放技术报告已保存为 [`A_Branch-and-Price Algorithm for the Minimum Latency Problem`](papers/vrp-frontier/12-minimum-latency-ng-memory/PDFs/A_Branch-and-Price_Algorithm_for_the_Minimum_Latency_Problem.pdf)，正文 28 页，未下载 SI；来源和 SHA-256 见同目录 `manifest.json`。

### 24.4 Dynamic ng-path 只保留为背景，不单列实施候选

Roberti 和 Mingozzi 2014 是 fully dynamic ng 的被改进基线：它只增加 vertex-based memories，不提供在保持当前 bound 下缩减 memory 的机制。当前 TWET 已有单次 pricing 内的 DSSR 增量更新，继续把这篇旧方法单独列为新候选没有意义。后续只在核对 Bulhoes 等人的 reduction 证明和 master-level dynamic-ng 语义时回看它，不另行优先实现或单独开展实验。

### 24.5 Selective Pricing 的严格思路及当前适用性

令 `R` 为 elementary feasible routes，`R_hat` 为允许重复访问的 relaxed ng-routes。传统 relaxed pricing 只有在 `R_hat` 中所有路线 reduced cost 均非负时才停止，因此可能为了大量负的非初等路线反复扩张 ng-memory，尽管 `R` 中已经没有负列。Selective Pricing 改写所需证书：只需保证当 `R` 中存在负列时，算法一定返回至少一条负路线；若算法不返回负路线，则必须证明 `R` 中不存在负列，即使 `R_hat minus R` 中仍存在负路线。

论文的实现不是直接丢弃重复路线，而是让每个 label 保存 dominated-path set 的紧凑摘要 `C(L)`：它表示被当前 label 代表或支配的所有隐藏路径共同访问的客户交集。只有当某次重复扩展对 `C(L)` 所代表的所有隐藏路径都会形成重复时，才可跳过该扩展；dominance 也据此放宽 memory-set 包含条件，同时增加稳定性条件，保证已经扩展过的 label 的 `C(L)` 不会事后缩小而破坏证明。

同一 VRPTW stack、同一 cuts 和固定 ng size 15 的九个困难 200-customer root 实验中，Selective Pricing 相对标准 ng pricing 平均省时 `16.3%`，最好 `32.7%`，该组没有实例变慢；相对论文采用的旧强基线平均省时 `35.4%`、最好 `59.9%`，但这部分还混入新 labeling heuristic。这个结果不能概括成稳定的 `16%` 单组件收益：在只保留 capacity cuts 的另一组对照中，带相同 heuristic 的 Selective Pricing 反而平均慢 `8.9%`，不带该 heuristic 时只平均快 `4.1%`。作者的判断是它主要在 non-robust cuts 使 pricing 极难时有用，普通或 cycle 不严重的情形收益有限。

当前默认 `ngDssrReturnRelaxedColumns=false`，非初等负路线只作为 witness，不进入 RMP；因此 Selective Pricing 若迁移，应被理解为“用更强的 exact dominance 直接证明无负 elementary route，从而允许在仍有负 relaxed witness 时结束”，而不是过滤正式列。它需要为双向 PWLF labels 定义等价的 dominated-frontier summary，并重新证明 forward/backward dominance 和 join 的 existential guarantee，实施难度高于 arc-based memory，暂时只保留为第二层研究候选。

## 25. Arc memory、Selective Pricing、DOI 及其余前沿方法的统一说明

### 25.1 Aggressive arc augmentation 到底是什么

Arc-based memory 确实可以理解为把传统“经过某个顶点后还记住哪些已访问任务”的 vertex memory，细化成“走过某条 arc 后还记住哪些已访问任务”的 arc memory。但 aggressive augmentation 不是简单地多加几条目标 arc，而是在 arc 表示下恢复一种接近 vertex augmentation 的广泛阻断效果。

设当前 relaxed route 暴露重复环 `H=(v,a,b,c,v)`，需要阻止第二次访问 `v`。moderate 模式只把该环的前缀 arc `(v,a),(a,b),(b,c)` 加入任务 `v` 的 memory。以后路线沿这些前缀走时会持续记住 `v`，因此 `v-a-v`、`v-a-b-v`、`v-a-b-c-v` 这一前缀族会被禁止；但从 `v` 改走 `b` 或在这些点之间换一种顺序，未必受到影响。

Aggressive 模式则把集合 `{v,a,b,c}` 中所有实际存在的有向 arc 都加入任务 `v` 的 memory。这样不只目标环，任何从 `v` 出发、经过上述中间点的某个子集或排列、最后回到 `v` 的环都会继续记住 `v`，例如 `v-b-v`、`v-c-a-v` 等也会被一起阻断。它仍以 arc mask 存储，但一次更新排除的是一整个环族，而不是一条目标前缀。

二者的取舍因此很明确。Aggressive 每轮阻断范围大，外层 dynamic-ng/CG 的迭代数通常更少；代价是大量入弧都携带较大的 memory，论文用 `gamma(j)` 表示进入顶点 `j` 的 arc 同时属于多少组 memory，label 数可能对 `gamma(j)` 指数增长。Moderate 每轮增加的 memory 少，单次 labeling 更可控，但可能需要更多轮才能恢复同样强的 relaxation。论文的稳健方案正是先 aggressive；一旦单次 labeling 超过 `100s`，中断当前 CG，先做 memory reduction，再切到 moderate。主更新参数为 `alpha_I=5,beta_I=200`，缩减内的温和更新为 `alpha_R=5,beta_R=200`，不是始终坚持某一种模式。

因此 arc memory 并非只为难算例设计。它对所有实例都定义有效，但主要价值确实出现在 vertex/aggressive memory 已经令 labeling 状态爆炸的难例。容易实例上 aggressive 或接近 vertex 的更新可能更快结束；难例上才更需要 arc 粒度和 reduction 控制单次定价复杂度。论文也没有给出一个“arc 比 vertex 平均快多少”的干净消融；能确认的是 `pr136/pr144/pr152` 等实例依赖 arc-based memory 才能处理，而 `pr124` 的 arc-only 配置两天仍未解，最终结论是实例依赖和混合策略更稳健。[开放技术报告](https://www.math.u-bordeaux.fr/~rsadykov/papers/BulhoesSadykovUchoa_LOGIS17.pdf)

### 25.2 Fully dynamic reduction 的目的和完整步骤

Fully dynamic reduction 的作用不是加强 relaxation，而是把已经膨胀的 memory **重新压缩到足以复现当前下界的较小子集**。这一步尤其解决 aggressive 切换到 moderate 时的历史包袱：如果只改变后续添加规则，过去 aggressive 加入的大量 arc 仍永久保留，labeling 不会自动变容易。

给定原 memory `M_ori` 和当前 dual `pi*`，其逻辑可以按下面理解：

1. 将新 memory `M` 重置为空或很小的初始状态，在同一个 `pi*` 下重新求 relaxed pricing。
2. 若此时得到的最优 relaxed route 在旧 memory `M_ori` 下也合法，则新 memory 已经复现旧 relaxation 在该 dual 下的 pricing 值，也就复现了当前 lower bound；停止。
3. 若该 route 只因 memory 太小才出现，则从它的重复环中做 moderate augmentation，但只允许加入属于 `M_ori` 的限制，保证始终有 `M subseteq M_ori`。
4. 重新 pricing，继续阻断当前暴露的违规 route，直到 pricing 值回到旧 memory 对应的值。

例如旧 memory 有 100 条 arc restriction，当前 lower bound 为 100。清空后 pricing 得到值 80 的 route A；加入阻断 A 所需的少量 arc 后得到值 95 的 route B；再阻断 B 后，最优值回到 100，且最优 route 在旧 memory 下合法。此时可能只保留 12 条限制。得到的 memory 不保证是基数最小的，但在当前 dual/lower-bound 口径下，其余 88 条是暂时冗余的，可以丢弃以降低后续 label state。

这也解释了它为什么不能每轮调用：一次 reduction 本身要做多轮额外 labeling。论文试过更频繁地缩减，发现大实例上耗时明显，而且频繁改变 relaxation 会破坏外层收敛。因此它是 labeling 已经失控后的应急重建，不是常规垃圾回收。

对当前 TWET 还不能直接照搬。论文的 memory 是跨 CG 迭代定义 master relaxation 的一部分；当前 ng-DSSR 主要在一次 exact pricing call 内递增 memory，目标是最终证明 elementarity。若删除当前 DSSR pair，必须重新证明最终 `certifiedInternalReducedCost` 的语义仍成立。较合理的研究入口只能是：当某次 pricing 的 memory/label 数越过阈值时，尝试在固定当前 dual 下重建一个更小但保持当前 pricing bound 的 memory，然后继续原 exactification；不能仅按“历史 pair 很久没用”直接删除。

### 25.3 Selective Pricing 的动机、证书和当前代码含义

Selective Pricing 针对的是 relaxed pricing 中一个浪费：令 `R` 为真实 elementary routes，`R_hat` 为允许部分重复的 ng-routes。传统做法要求证明 `R_hat` 中没有负 reduced-cost route 才停止；但 master 真正缺少的列只有 `R`。完全可能出现 `R` 中已经没有负列、`R_hat minus R` 中仍有很多负的非初等路线，DSSR 于是不断围绕这些“假目标”扩 memory。

Selective Pricing 把定价合同改成：只要 `R` 中存在负列，pricer 就必须返回至少一条负路线；返回的路线可以是 elementary，也可以是 relaxed witness。反过来，如果 pricer 返回“没有”，就证明 `R` 中没有负 elementary route，即使完整 `R_hat` 中仍有负非初等路线。它不再要求找到 `R_hat` 中最小 reduced cost 的 route，而只保留“负 elementary route 存在时绝不漏报”的存在性证书。[原论文](https://pure.eur.nl/ws/portalfiles/portal/48204101/Repub_116700.pdf)

论文在单向 VRPTW label 中增加 `C(L)`：它是当前 label 所代表及支配掉的所有隐藏路径共同访问客户的交集。普通 dominance 有时因为两个 label 的 ng-memory 不满足包含关系而不能删掉较差 label；Selective Pricing 会进一步判断，那个较差 label 看似可做的某次扩展，是否对它所代表的所有隐藏路径都必然重复。如果是，这个扩展不可能形成 elementary route，可以安全忽略。相应地，扩展条件和 dominance 条件都引入 `C(L)`，并要求已扩展 label 的 `C(L)` 以后不能缩小，避免事后破坏已经执行的剪枝。

一个直观例子是：label `L2` 在成本和时间上都差于 `L1`，但 `L1` 的 memory 看起来禁止去任务 `k`，`L2` 看起来允许，普通 dominance 因而保留 `L2`。如果 `C(L2)` 说明 `L2` 背后所有可能的隐藏前缀其实都访问过 `k`，那么 `L2->k` 对所有真实前缀都是非初等扩展；保留 `L2` 只会帮助找到 relaxed cycle，不会帮助找到 elementary 负列，故可由 `L1` 覆盖。

论文在九个困难的 200-customer Homberger root、固定 ng size 15 且 cuts/其他模块一致的实验中，相对标准 ng pricing 平均省时 `16.3%`、最好 `32.7%`，该组没有观察到变慢；相对更旧的完整基线平均 `35.4%`、最好 `59.9%`，但后一组还混入新的 labeling heuristic，不能全归因于 Selective Pricing。另一个只用 capacity cuts 的对照却显示：带相同 heuristic 时 Selective Pricing 平均慢 `8.9%`，不带 heuristic 时平均快 `4.1%`。因此它不是稳定减少每次 labeling 工作量的技巧，而是在 non-robust cuts 造成很多难处理 relaxed cycles 时，可能通过改变停止证书缩短整个 CG 过程。

当前 `ngDssrReturnRelaxedColumns=false` 时，非初等负路线不进入 RMP，只作为 DSSR witness；这与 Selective Pricing 的动机高度一致：当前流程可能为了清掉不会进入 RMP 的负 relaxed witnesses 而继续收紧。所谓“用更强的 exact dominance，在仍有负 relaxed witness 时证明不存在负 elementary route”，就是在 label 搜索中证明所有可能形成负 elementary route 的前缀、后缀或 join 都已被覆盖；剩下的负 route 即使存在，也只能是非初等 witness，因而可直接结束本次 exact pricing。

难点在于这不是返回端过滤器。TWET 是双向 PWLF labeling，一条 compact label 代表一组不同时间和成本的 frontier segments。迁移时必须定义“被一个 PWLF label 支配的全部隐藏时间路径共同访问什么”的摘要，保证该摘要在 envelope dominance 后不收缩，并分别证明 forward、backward dominance；最后还要证明 join 不会把某个被支配前缀与后缀组合成遗漏的负 elementary route。原论文只证明了单向标量 label，不能直接把 `C(L)` 塞进当前 label 就宣称 exact。因此它比 arc memory 更可能直接减少 DSSR 轮数，但数学和实现风险也更高。

Dynamic ng-Path Relaxation 不再作为独立候选继续分析，只保留为上述 arc/dynamic-memory 文献的历史基线。

### 25.4 DOI 是怎样稳定 column generation 的

DOI（Dual Optimal Inequalities）的出发点是：完整 master 往往有很多最优 dual，RMP 缺列时更容易选到非常极端的 dual。这样的 dual 会让 pricing 只产生一批针对当前尖峰的列；列加入后 dual 又跳到另一个尖峰，造成 reduced cost 振荡、重复定价和大量作用很短的列。DOI 给 dual 增加一组经过证明的边界，排除这些无必要的极端点，同时保证至少保留一个完整 master 的最优 dual，所以最终 LP optimum 不变。[Smooth and Flexible DOI](https://pubsonline.informs.org/doi/10.1287/ijoo.2021.0057)

S-DOI（smooth DOI）的典型构造是任务替换。若能证明任意可行列中把任务 `u` 换成 `v`，目标最多增加 `rho_uv`，则任务覆盖 dual 必须满足 `pi_v-pi_u<=rho_uv`；否则把高 dual 的 `v` 换到覆盖 `u` 的列中就会与最优 dual 条件矛盾。它使“相似且可替换”的任务 dual 不会相差任意大。CVRP 在三角不等式和需求兼容下可用 `2*c_uv` 一类局部距离界，所以比较容易构造。

F-DOI（flexible DOI）从删除任务出发：若能给出从某条 route 删除任务 `u` 时可靠的成本节省下界/上界，就可限制 `pi_u` 对 over-coverage 的异常激励。其 primal 等价形式允许 master 暂时以有罚价的任务替换、欠覆盖/超覆盖变量表达这些操作；这些变量帮助 RMP 在列不足时沿较平滑的方向移动，而不是靠极端 dual 驱动 pricing。

Relaxed DOI 进一步承认这些交换/删除界可能只对 elementary routes 有效、对 ng-relaxed columns 不完全有效。算法允许先加入 DOI；若 CG 结束时某些 DOI 对应的 primal 辅助变量仍为正，就删除这些 active DOI，从当前列池重新启动，直到无 active DOI。这样 DOI 可以暂时帮助稳定，但最终仍恢复原 ng master 的有效 lower bound。[Relaxed DOI for Relaxed Columns](https://arxiv.org/pdf/2004.05499)

该文在 46 个至多 50 个客户的 CVRP root-CG 实例、固定 ng size 5 上报告：标准方案平均约 `1354s`，S-DOI 约 `1006s`，SF-DOI 约 `999s`，即平均约 `20%` 提速；S-DOI 在 44/46 个实例改善，SF-DOI 在 41/46 个实例改善，F-DOI 单独没有平均提速。S-DOI 仅 2/46 个实例需要 active-DOI recovery，而 F/SF 中 recovery 更频繁。这个实验是小规模 CVRP root relaxation，不是带 SRI、强分支和整棵树的 TWET BPC。

TWET 的障碍不是软时间窗本身，而是无法轻易给出紧且安全的 `rho_uv` 或删除 rebate。把任务 `u` 换成 `v` 会改变前后 setup，并平移所有后续任务的 completion time；PWLF earliness/tardiness 成本可能在多个任务上同时升降。只看局部两条 setup arc 会漏掉下游成本，使用全局 BigM 虽安全但几乎没有稳定作用。F-DOI 的任务删除也有同样问题。因此 DOI 目前是有原理、有 CVRP 证据，但缺少 TWET 有效数学界的中长期方向；它不是把现有 dual 做平均，也不是一个可直接打开的参数。

#### 25.5.1 DeLuxing

DeLuxing 的动机发生在 pricing 已经结束以后。Exact enumeration 根据当前 incumbent gap 枚举出所有仍可能参与改进整数解的列，但有限 master 仍可能极大；普通 reduced-cost fixing 只使用 LP 求解器随机返回的一组最优 dual，许多本可证明无用的列在这组 dual 下 reduced cost 不够大，因而留在 MIP 中。

它先按 reduced cost 将列池分层，再用列的 master 系数缺口向量做聚类；针对不同列群解很小的辅助 LP，寻找不同的 qualified dual/Lagrangian underestimate，让该群中的大量列得到安全 fixing 证书。删掉一批后继续对残余列做 deeper search。这里的 `Deep` 指反复寻找多组 dual，不是深度学习。[DeLuxing 论文](https://optimization-online.org/wp-content/uploads/2023/09/DeLuxing_OR_2023.pdf)

多数 CMTVRPTW 有限列池可删除超过 75%，最高约 99%。但当前更应采用 RouteOpt 的模块消融：只增加 DeLuxing 约带来 21% CVRP、31% VRPTW 加速；45%/71% 的 headline 还加了新 primal heuristic，CMTVRPTW 的 7--20 倍还混入多项 extension。论文长路线压力测试中平均 route length 增至 15.6、最大 23 后，enumeration 很晚才完成且 DeLuxing 优势消失。TWET 每台机器序列往往更长，且当前 route enumeration 触发条件苛刻，因此近期不应实现。

#### 25.5.2 Cluster Branching

Cluster Branching 的动机是“对可互相替代的一组 arc 的总量分支”。若一个簇内有许多便宜连接，禁止单条 arc 后马上能换另一条；若两个簇之间必须存在若干连接，禁止某一条跨簇 arc 也很弱。论文先基于距离做静态 clustering，然后构造簇边界 crossing flow 和簇对之间的 aggregate flow；其 LP 值为分数时按 floor/ceil 二分。每条 route 的 branch-row coefficient 只是包含多少条成员 arc，branch dual 可直接分摊回成员 arc reduced cost，因此属于 robust branching，不给 label 增加资源。它本身不完备，最后仍需 edge/arc 等 fallback。[Cluster Branching 论文](https://optimization-online.org/wp-content/uploads/2024/07/L_2024_2___Cluster_branching.pdf)

CMT13 的“4 年”和“26.7 天”不是实跑，而是根据 24 小时内已观察的平均 child-bound improvement 估计每个 open node 还需多深，再按满二叉树估剩余节点。加入 cluster candidates 后，Edge+CB 用 79 节点约 2 小时 30 分，Cutset+CB 用 55 节点约 1 小时 56 分完成。XML100 一小时 solved count 中 edge 约 `1961->2041`、cutset 约 `1998->2073`、Ryan-Foster 约 `1692->1923`；但困难 X benchmark 只约 `25->26`，随机几何有时会变慢，VRPTW 也因纯空间簇忽略时间兼容而收益较小。

TWET 没有地理坐标，但可按 setup compatibility 与 due-window/processing compatibility 聚类。实现上可沿用现有 arc branch row 和 arc-dual 注入，只新增 aggregate coefficient 和候选生成；它是剩余方法中最接近低侵入迁移的一个。不过它改善的是树，不是 ng-DSSR；若 root/pricing 才是瓶颈，收益不会出现。

#### 25.5.3 2LBB/BKF

2LBB 与 BKF 不改变分支约束，只决定 strong branching 花多少钱。2LBB 第一阶段用 XGBoost 和廉价 LP、图、历史特征排序，第二阶段用 partial testing 缩小真正 trial 的候选；BKF 根据多试一个候选的当前成本和预期树收益动态选 `K`。`3PB+BKF` 与 `2LBB+BKF` 都可以，pseudo-cost 也只是其中一个特征，并非四选一。论文相对同一 RouteOpt 的 3PB 报告 CVRP/VRPTW 总时间约降低 45%/50%，归因比跨求解器 headline 更可信，但依赖同分布训练数据。当前按本轮要求先不推进。

#### 25.5.4 Pricing for Integrality

它的动机是 LP-optimal columns 未必 integer-friendly。算法从当前 RMP/列池构造 partial integer solution，识别未覆盖任务和已占用资源，额外调用一个启发式 pricer，奖励能补齐缺口且与已选列相容的 route，再用新增列重解 restricted integer master。随后标准 exact pricing 和下界证书照常进行，所以正确性不依赖它。[PFIH 论文](https://arxiv.org/pdf/2602.08673)

论文针对带充电时隙的 EVRPTW，在同一 GCG/SCIP stack 内比较插入 PFIH 的不同位置；相对 restricted-master integer heuristic，平均能额外关闭约 30%--40% root primal gap。它证明的是 incumbent 质量，不是 exact pricing 变快，也没有证明总 optimal-solve time 等比例下降。当前 TWET 上界通常不构成首要瓶颈，因此只保留条件性价值。

#### 25.5.5 Column Elimination

Column Generation 从少量显式列出发不断加列；Column Elimination 从一个压缩 decision diagram/状态图出发，该图隐式表示一个包含可行路线和伪可行路线的超集。若当前最优图路径违反容量、elementarity 或其他约束，就分裂合并过度的状态，排除这条路径以及共享同类冲突的一族路径。大图阶段用 Lagrangian/subgradient、minimum-update successive shortest path 和 arc fixing，图缩小后再交给 CPLEX。

论文中 muSSP 的子问题组件约快 3.7 倍，variable fixing 对 CVRP 平均删除约 53%；VRPTW 曾关闭一个 1000-customer open instance，并在部分 clustered C2 大例上优于 VRPSolver lower bound，但其他类别并不稳定占优。它改变的是整个 exact framework；TWET 若迁移，需要重新把 PWLF 时间成本、机器数、外包和 cuts 编进图/refinement，不能作为现有 BPC 的一个开关。

#### 25.5.6 Local Area Routes 与 Graph Master

Local Area Routes 认为 ng-route 逐任务扩展仍太细，且允许的局部 cycle 会削弱 relaxation。它为任务 `u` 的小邻域预计算从 `u` 到较远任务 `v`、中间经过某个邻域子集的最优 elementary local path，把整个 local path 当作一条 LA arc；全局 pricing 再拼接这些 blocks。这样可一次跨过多个客户，并在局部范围强制 elementarity。

Graph Master 针对另一个粒度问题：普通 CG 一次 route 只增加一个变量，即使围绕这条 route 的许多局部替换也明显有用。它用 DAG/多图表示一族相关 routes，master 中一个图块隐式容纳许多 s-t paths；内部 family pricing 在已有图中找列，外层 exact pricing 只有在现有图族不足时才创建新图或扩图。[LA Routes](https://arxiv.org/pdf/2209.12963)，[Graph Master](https://arxiv.org/pdf/2304.11723)

论文的常见 2--10 倍来自 20--60 客户的 MATLAB root-CG 原型，并非包含 modern cuts、strong branching、enumeration 和高级 labeling 的完整 BPC 同栈对比。TWET 的一个 local block 成本依赖进入时间，输出又是完成时间与累计 TWET cost 的 PWLF transfer frontier，不能预计算成一个 scalar cost；Graph Master 还会把当前 route-based RMP 改成 extended graph master。因此二者可形成独立算法论文，但不是当前主线的小改。

### 25.6 当前结论

严格限定“加强当前 no-SRI ng-DSSR”时，最相关的只剩两条：arc-based memory/触发式 memory reduction，以及更困难的 Selective Pricing。前者控制 memory 对 labeling 的副作用，工程可迁移性更高；后者可能在仍有负非初等 witness 时直接结束 exact pricing，但需要重做双向 PWLF dominance/join 证明。DOI 作用于 dual stabilization，Cluster Branching 作用于搜索树，DeLuxing 作用于枚举后的 finite master，Pricing for Integrality 作用于 incumbent，2LBB/BKF 作用于 strong-trial 预算，Column Elimination 与 LA/Graph Master 则是新框架。后续不能再把这些方法的整套求解器收益当作 ng-DSSR 提速证据。

## 26. Fully Dynamic Reduction、Selective Pricing 与其余方法的进一步拆解

### 26.1 DOI 是否已经用于 RouteOpt 或 VRPSolver

截至 2026-08-24，公开资料不支持“RouteOpt 或 VRPSolver 已经实现了这里讨论的 S-DOI/F-DOI”这一说法。二者都做了 column-generation stabilization，但 stabilization 是大类，DOI 只是其中一种有特定数学结构的方法，不能因为存在稳定化开关就视为实现了 DOI。

RouteOpt 当前公开源码的确有 `IF_USE_STAB`。在 2026-04-17 的公开版本 `950b9a333a7b30114d5ebaf0c1709f83710b7a67` 中，它为每条 master row 加一正一负的有界人工列，用 `gamma` 控制可偏离范围，并围绕 incumbent dual 用 `delta` 调整人工列成本；收敛时逐步缩小人工列上界并最终删除。这属于显式人工列/box-penalty 风格的 LP 稳定化。源码中没有 S-DOI、F-DOI、任务交换界 `rho_uv` 或 relaxed-DOI recovery 结构。因此正确结论是：**RouteOpt 有稳定化，但公开版没有发现 DOI。**

VRPSolver/BaPCod 的情况类似但技术来源不同。其通用求解器论文和当前参数表中的 `StabilizationMinPhaseOfStage` 对应 Pessoa、Sadykov、Uchoa 和 Vanderbeck 2018 年提出的 automatic dual-price smoothing 与 penalty-function stabilization。该方法通过 incumbent dual、平滑权重和惩罚区域抑制 dual 跳动，不需要构造任务之间的交换/删除成本界。公开论文和参数文档同样没有把 S-DOI/F-DOI 列为组件。因此 **VRPSolver 使用成熟的通用稳定化，但不是 Haghani 等人的 DOI。**

DOI 本身也不是只为 VRP 提出的。*Smooth and Flexible Dual Optimal Inequalities* 研究一般 set-covering column generation，并在 single-source capacitated facility location、capacitated p-median 和 CVRP 上实验；2021-10-07 在线发表，期刊卷期为 *INFORMS Journal on Optimization* 4(1), 29--44, 2022。[期刊页面](https://pubsonline.informs.org/doi/10.1287/ijoo.2021.0057) 其后 *Relaxed Dual Optimal Inequalities for Relaxed Columns: with Application to Vehicle Routing* 才专门处理 CVRP 的 ng-route relaxed columns；该文 2020-04-11 提交 arXiv，目前检索到的是预印本而非正式期刊版本。[arXiv](https://arxiv.org/abs/2004.05499)

### 26.2 Fully Dynamic Reduction 到底减少什么

它减少的不是 route、column 或 DSSR round，而是 **ng memory 中已经积累的限制**。传统 dynamic ng 的更新只有一个方向：发现负的非初等 route，就往 memory 中增加一些 vertex/arc restrictions，禁止该重复环以后再次出现。这样 lower bound 逐渐增强，但 memory 只增不减。问题在于很多早期 restriction 只针对当时的 dual 有用；dual 变化以后它们可能不再阻断任何当前有竞争力的路线，却仍扩大每个 label 的 memory state，使 dominance 变弱、label 数增加。

只把后续更新从 aggressive 改成 moderate 不能解决这个问题。过去 aggressive 加入的 restrictions 仍全部存在，新的 label 仍要携带它们。Fully Dynamic Reduction 的目的就是在某个固定 dual `pi*` 下重新回答：**为了保持当前 pricing value/lower bound，旧 memory 中到底哪些限制还必需？**

设旧 memory 为 `M_ori`，它允许的 route 集合为 `R(M_ori)`。从空 memory `M0` 开始时限制更少，所以 `R(M_ori) subseteq R(M0)`，最小 reduced cost 只可能更低。算法在同一个 `pi*` 下执行以下过程：

1. 用当前较小 memory `M` 做一次 relaxed pricing，取得最小 reduced-cost route `r*`。
2. 检查 `r*` 在旧 memory `M_ori` 下是否也合法。如果合法，则 `r*` 同时属于新旧 route 集。因为新集包含旧集，有 `minRC(M) <= minRC(M_ori)`；又因为旧集包含当前新集的最优解 `r*`，有 `minRC(M_ori) <= rc(r*) = minRC(M)`。两边合起来得到二者相等，当前 lower bound 已被复现，可以停止。
3. 如果 `r*` 在旧 memory 下不合法，说明当前删得太多，放进来了一条旧 relaxation 已经排除的低 reduced-cost route。算法只从 `M_ori` 中找出阻断 `r*` 的少量 restrictions，以 moderate augmentation 加回 `M`，然后重新 pricing。
4. 重复直到某次新 memory 的最优 route 也被旧 memory 接受。最终得到 `M_new subseteq M_ori`，并且在当前 `pi*` 下 `minRC(M_new)=minRC(M_ori)`。

例如旧 memory 有 100 条 restriction，当前最小 reduced cost 为 0。清空后先出现 `rc=-20` 的重复路线 A，加回阻断 A 的 4 条限制；接着出现 `rc=-5` 的重复路线 B，再加回 3 条；之后最优 route 的 reduced cost 回到 0 且该 route 在旧 memory 下也合法。此时只保留 7 条 restriction，就在当前 dual 下复现了旧 100 条 restriction 的 pricing bound。它不保证这 7 条在未来 dual 下仍足够，也不保证是最小基数集合；dual 变化后，被删除的 restriction 可能再次被 DSSR 学回来。

这就是“fully dynamic”的含义：旧 dynamic ng 只能增加 memory；该方法允许清空、重选和再次增加，使 memory 对当前 dual 重新适配。其代价也很明确：缩减本身要额外做多轮 labeling。因此论文只在单次 labeling 已超过 `100s` 时触发，频繁缩减反而拖慢外层 CG。论文没有给出它独立于 multiple partial dominance、arc memory、stabilization 等组件的统一加速比。

当前 TWET 默认 `enableNgDssrHistoryWarmStart=false`、`enableNgDssrSameNodeWarmStart=false`，每次 pricing 调用不会继承一个长期只增不减的 ng memory。因此论文最主要的“清理跨 CG 调用历史包袱”动机在当前主线基本不存在。它最多可能用于一次特别长的 exact pricing call 内，在多轮 DSSR 后 memory 已膨胀时做一次固定-dual重建；但这会主动重新放宽当前 relaxation并增加 labeling 次数。没有 profile 证明单次 call 的最终 ng memory/label 数爆炸以前，不应实现。

### 26.3 Selective Pricing 为什么能在仍有负 relaxed route 时停止

标准 ng/DSSR pricing 解决的是较大的 relaxed route 集 `R_hat`，真实 master 需要的是其中的 elementary route 集 `R`。标准停止条件是

`min{rc(r): r in R_hat} >= 0`。

这个条件比实际需要的 `min{rc(r): r in R} >= 0` 更强。假设所有 elementary route 已经非负，但仍有一条重复客户的 ng-route reduced cost 为 `-10`。标准 DSSR 会把它当作 witness，继续扩大 memory；扩大后又可能出现另一条 `-3` 的重复路线。它花时间证明整个 relaxed 集都没有负路线，但 master 其实早已没有可加入的负 elementary column。

Selective Pricing 改的是定价器必须提供的证书，而不是在返回端过滤路线。它不要求找到 `R_hat` 中真正的最短路，只要求满足：

- 若 `R` 中存在负 elementary route，算法一定返回至少一条负 route；
- 若算法返回“没有负 route”，则可断言 `R` 中没有负 elementary route；
- `R_hat minus R` 中是否还存在更负的非初等 route，不影响这一证书。

论文允许返回的负 route 本身仍是 relaxed route，并把已生成的 relaxed routes `R0` 留在 RMP 中；最终 lower bound 对应 `R0 union R`。当前 TWET 不把非初等列加入 RMP，因此不能原样照搬这一 master 语义。较自然的兼容方式是：若 Selective pricer 返回 elementary route，就正常加列；若返回 relaxed route，仍只把它当作 DSSR witness 更新 memory；只有 pricer 返回 none 时，才使用其“无负 elementary route”证书结束。这样不必开放 relaxed columns，但仍需完整实现论文的 selective dominance，不能把普通 ng pricer 找不到候选误当成该证书。

难点在于 label dominance。一个 label 不只代表其显式前缀，还隐式代表已经被它支配并删除的其他前缀。论文为 label `L` 保存 dominated-path set 的摘要 `C(L)`，即这些显式/隐藏前缀 **共同访问过的客户交集**。例如显式前缀是 `0-1-2-3`，它还支配了隐藏前缀 `0-4-2-3`。若现在扩展到客户 1，仅看显式前缀会认为重复访问 1，可以丢弃；但隐藏前缀没有访问 1，`0-4-2-3-1` 可能是一条负 elementary route，因此不能删。此时 1 不属于两个前缀访问集合的交集 `C(L)`。只有当 1 属于 `C(L)`，也就是所有被该 label 代表的前缀都已经访问过 1 时，扩展到 1 才对所有潜在 elementary route 都无用，可以安全跳过。

论文相应修改 extension 和 dominance：extension 不再只看当前显式 ng-memory，还看 `C(L)`；一个资源更优但 memory 条件原本不够强的 label，只要被支配 label 多出来的可扩展客户对其全部隐藏前缀都已构成重复，也可以执行 dominance。为防止已经据此扩展/剪枝的 label 后来吸收新路径而使 `C(L)` 变小，论文还增加稳定性条件：已扩展 label 的共同访问集合不能在后续 dominance merge 中被任意放宽。

因此 Selective Pricing 的真实作用是：**允许删除只影响 relaxed route 最优性的搜索状态，同时完整保留“若存在负 elementary route 就一定返回负 route”的存在性保证。** 它通常不是让每次 extension 本身更便宜。九个困难 Homberger 200-customer VRPTW root 的完整同栈比较中，相对标准 pricing 平均省时 `16.3%`、最好 `32.7%`，该组没有实例变慢；但只用 capacity cuts 的对照中，带相同 heuristic 时反而平均慢 `8.9%`，不带 heuristic 时只快 `4.1%`。其收益明显依赖 pricing 是否已被 non-robust cuts 推到很难的区域，不能把 `16.3%` 当成可直接迁移的稳定提速。[论文页面](https://link.springer.com/article/10.1007/s13676-017-0112-9)

旧车辆路径代码没有这一实现。[`Label.java`](../../src/BPC/GC/Label.java) 保存完整 `low_visit/high_visit` 访问位集，[`GC.java`](../../src/BPC/GC/GC.java) 的 `UpdateReach()` 直接把已访问客户标为不可再次到达；它做的是 full elementary labeling，没有 ng-relaxed label、dominated-path common-set `C(L)`，也没有 Selective Pricing 的 existential certificate。代码搜索也没有 `selective pricing` 或 dominated-path-set 结构。严格说，它不是“漏了一个开关”，而是根本没有该方法所针对的 relaxed-cycle 层。

当前 TWET 虽然存在 ng-relaxed witness，但使用双向 PWLF label。一条 label 代表的是一组时间-成本 frontier segments，dominance 后隐藏的不只是不同访问前缀，还有不同完成时间与成本函数段。要迁移 Selective Pricing，必须分别定义 forward/backward 的共同访问摘要，证明 envelope dominance 后摘要稳定，并证明 join 不会把已删前缀与另一侧拼成遗漏的负 elementary route。旧 VRPTW 的单向标量证明不能直接复用。因此它有困难 non-robust-cuts 场景约 `16%` 的同栈证据，也有 capacity-cuts-only 场景平均变慢的反证；实现风险明显高于 arc memory。

### 26.4 DOI 怎样实施，表现到底如何

DOI 处理的是 dual oscillation，不处理 elementarity。以 set-cover master 的任务 dual `pi_i` 为例，若能证明在任意列中把任务 `u` 替换为任务 `v` 最多增加 `rho_uv` 成本，那么至少存在一个最优 dual 满足 `pi_v-pi_u <= rho_uv`。S-DOI 把这些不等式加入 dual；在 primal 侧等价为加入“用一个任务的超覆盖补偿另一个任务欠覆盖”的 transfer variables，并对每单位转移收取 `rho_uv`。这些辅助变量让缺列的 RMP 暂时沿一个有已知成本的替换方向调整，避免把两个相似任务的 dual 拉到极端差值。

F-DOI 使用另一种局部操作：从一条列删除任务。若能安全界定删除任务 `u` 后列成本最多/至少改变多少，就加入 over-coverage rebate variables，使额外覆盖一个任务能够获得受控 rebate。S-DOI 主要限制相似任务 dual 的相对差，F-DOI 主要控制单个任务 dual 与删除成本之间的关系；二者可以同时使用为 SF-DOI。

对 ng-relaxed columns，elementary 列上正确的替换/删除界不一定对重复路线也成立。Relaxed DOI 的实施不是假装它们永远有效，而是带恢复循环：先把 DOI 放入 RMP 加速 CG；当定价暂时收敛时检查 DOI 对应的 primal auxiliary variables。若某些仍取正值，说明当前解依赖这些对 relaxed columns 未必有效的替换/删除操作，就删除 active DOI，从现有列池继续 CG；重复直到无 active DOI。最终取得的是原 ng master 的 lower bound，不以牺牲 relaxation 强度换速度。

面向 relaxed columns 的 CVRP 论文使用 46 个 A/B/P/E 基准实例，客户数最多 50、ng size 为 5，只比较 root LP column generation。平均时间约为：标准 `1354s`，S-DOI `1006s`，F-DOI `1162s`，SF-DOI `999s`。S-DOI/SF-DOI 平均约快 20%；S-DOI 有 44/46 个实例改善，SF-DOI 有 41/46 个改善，F-DOI 单独没有平均优势。S-DOI 仅 2/46 个实例需要 active-DOI recovery，而 F/SF 大多需要恢复。该证据说明平滑交换界有效，但规模小、仅 root CG、没有现代 cuts/strong branching，不能外推成整棵 BPC 的 20%。

TWET 的关键障碍仍是构造有用的安全界。任务替换会改变前后 sequence-dependent setup，并平移所有后续任务的 completion time，使多项 PWLF earliness/tardiness 成本一起变化；任务删除也会改变整条后缀。用 BigM 可以得到安全 `rho_uv`，但 DOI 过宽就不约束 dual，等于没有稳定效果。因而 DOI 目前没有直接实施方案，不能把 RouteOpt/VRPSolver 现有 stabilization 当作已经替我们解决了这个界。

### 26.5 DeLuxing 不是删当前 RMP 列，而是枚举完成后的多证书 fixing

DeLuxing 的前提是 exact enumeration 已经得到一个有限列池，其中包含所有仍可能改善 incumbent 的列。问题是这个池可能有几十万到几百万列，直接交给 MIP 或在每轮 cut/branch 后反复扫描很慢。普通 reduced-cost fixing 只利用当前 LP 返回的一组最优 dual；由于 dual degeneracy，同一个 optimal face 上有许多不同 dual，一组 dual 可能把 A 类列的 reduced cost 拉高，却对 B、C 类列几乎没有排除力。

设当前 LP lower bound 为 `z`、incumbent 为 `UB`、gap 为 `g=UB-z`。在一组有效 dual 下，若强制列 `r` 出现在整数解时的 Lagrangian underestimate 已经超过 `UB`，则该列可安全固定为 0。DeLuxing 的核心不是改变这个 fixing 定理，而是廉价地寻找 **多组针对不同列群的 qualified dual**，让不同列分别得到强证书。

它先用当前 reduced cost 清除 `rc>g` 的标准可固定列，再分成 `R1={rc<=g/2}` 与 `R2={g/2<rc<=g}`。任何能改善 incumbent 的整数解不可能同时使用两条 `R2` 列，否则仅两条列的 reduced-cost contribution 就超过 gap。利用这个结构，可以只用较小的 `R1` 建辅助 LP，又仍对强制某条 `R2`/候选列构造有效 Lagrangian underestimate。

但逐列解一个辅助 LP 仍太贵，所以论文按列的 master coefficient/缺口向量聚类：结构相近的列通常能被同一个 dual 方向同时压高 reduced cost。对每个 cluster 取代表向量，解一个只含 `R1` 的小 LP，得到一组 qualified dual，然后批量测试该组中大量列。删掉一批后，算法用新发现的 removable columns 更新 reference point，再沿该 cluster 做下一轮小 LP，直到新增删除很少。这种反复深入同一列群的 dual search 就是 `Deep`；不是 deep learning。

论文报告多数列池可删除超过 75%，最高约 99%。在 RouteOpt 同栈消融中，仅 DeLuxing 的增量约为 CVRP 21%、VRPTW 31%；论文摘要中的 45%/71% 还包含受 DeLuxing 启发的 primal heuristic 等扩展。长路线使 enumeration 很晚才成功时，DeLuxing 的优势会消失。当前 TWET 没有稳定、早期、完整的巨大枚举池，所以它不会改善现在的 ng-DSSR，也不应近期实施。[Operations Research 论文](https://pubsonline.informs.org/doi/10.1287/opre.2023.0398)

### 26.6 BKF 是动态预算公式，不是机器学习

BKF 在论文和 RouteOpt 源码中的全称是 **Best K Formula**。RouteOpt 文档某一处把它展开为 Branching Kernel Functions，但公开代码 `bkf_controller.hpp` 和论文都明确写 Best K Formula，应以后者为准。它不负责判断哪个候选最好，而只回答：**当前 strong-testing 阶段到底值得完整测试前 K 个候选？**

固定 K 的问题是节点状态差异很大。root 的一次 trial 虽贵，但选错分支可能放大整棵树；深层节点 gap 已小、剩余树浅，多测 20 个候选可能永远收不回成本。BKF 建立一个总时间权衡：测试 K 个候选的当前成本大致为 `K*t`；K 越大，找到高质量候选的概率越高，预期 child-bound lift 越好，后续节点数越少，后续成本约为 `E[N(K)]*c`。它用当前 `UB-LB`、平均单个 trial 时间 `t`、普通节点处理时间 `c`、历史 branching lift、树深/枚举前后状态等在线统计估计 `E[N(K)]`，选择使

`T(K) = K*t + E[N(K)]*c`

最小的 K。它是基于模型与运行统计的动态预算控制，不需要训练数据。

BKF 可以和不同候选排序器组合。`3PB+BKF` 用手工/现有评分先排序，再由 BKF 决定测多少；`2LBB+BKF` 则由机器学习的第一阶段排序和 partial testing 缩小候选，再由 BKF 决定昂贵阶段的 K。2LBB 是机器学习，BKF 不是；二者不是四选一。RouteOpt 当前公开源码已有 `packages/branching/bkf`，会记录单次 testing time、node time、上下界与历史 lift 并调用 `getBestK()`。

论文中较干净的 BKF 对比是：静态 `K=2,...,40` 的最好方案约 `446.9s`，BKF 约 `396.6s`，约快 11%；相比若干线性动态预算，BKF 把 LP testing 时间从约 `172--181s` 降到 `98.3s`，总时间从约 `455--467s` 降到 `396.6s`。论文 headline 的 CVRP 45%、VRPTW 50% 是完整 `2LBB-dy` 相对 3PB 的结果，不能全归因于 BKF。该方法不改变 exactness，只有 strong trials 再次成为主要耗时时才值得移植。

### 26.7 Column Elimination 是从路径超集向下收紧的另一套 exact framework

Column Generation 从少量真实可行列开始，pricing 不断加入遗漏列；Column Elimination 反过来，先用一个压缩 decision diagram 表示真实列集的 **超集**，其中既有可行路线，也有因状态合并产生的伪路线，然后不断消除伪路线。

例如精确 DP 状态本应记录 `(最后任务, load, visited-set)`。为了压缩图，初始 diagram 可能只记录 `(最后任务, load)`，把“已经访问 A”和“没有访问 A”的历史合并。合并后的图可能出现 `Depot-A-B-A-Depot` 这种原问题不允许的路径。算法先在这个 relaxed graph 上求 constrained network flow；因为图包含全部真实路线，得到的是合法 lower bound。若最优 flow 选出的每条路径都能映射为原问题可行路线，则该可行解同时达到 lower bound，已经最优。若发现重复 A，就沿冲突路径分裂相关状态，引入“是否访问 A”的局部区别，删除这条路径以及共享该冲突的一族路径，再重新求解。

所以它的循环是 `solve relaxed graph -> decode paths -> identify infeasibility witness -> split/refine states -> solve again`。大图阶段用 Lagrangian relaxation 和 subgradient 处理覆盖等 linking constraints，每个子问题是 diagram 上的 shortest path；图局部变化后用 minimum-update successive shortest path 重用旧最短路信息，并做 arc fixing。图缩小到一定程度后可转给 CPLEX。它所谓 elimination 不是从 Pool 删除几个高 reduced-cost columns，而是通过状态 refinement 从隐式路径超集中永久去掉伪路径族。

CVRP 专文发表于 CPAIOR 2023，LNCS 13884, 35--51；更一般的 *Column Elimination: An Iterative Approach to Solving Integer Programs* 于 2024-10-15 放在 Optimization Online，页面仍标注 `Submitted`，不能写成已发表的 Operations Research 论文。一般框架报告关闭了 graph multicoloring 的 5 个开放实例、一个 1000-location VRPTW 开放实例和 6 个 PDPTW 开放实例；这说明框架有潜力，但它替换的是现有 BPC/price 主线，而不是可以嵌入当前 TWET ng-DSSR 的局部优化。[一般框架](https://optimization-online.org/2024/10/column-elimination-an-iterative-approach-to-solving-integer-programs/)

### 26.8 Local Area Routes 与 Graph Master 分别解决两个不同粒度问题

Local Area Routes 解决 pricing extension 太细的问题。普通 labeling 每次从客户 `u` 扩到一个客户 `v`；LA 方法先为一个小邻域预计算 LA arc。一个 LA arc 由起点 `u`、较远终点 `v` 和一组靠近 `u` 的中间客户 `S` 定义，保存从 `u` 出发、恰好服务 `S` 中客户并以某种最优局部顺序到达 `v` 的 elementary subroute。全局 pricing 不再逐客户走，而是拼接多个 LA arcs，一次 extension 可跨过多个局部客户。LA route 仍是 elementary routes 的超集，但比同邻域 ng-route 更严格；外层 DSSR 再逐步增加必须记忆的客户，恢复 elementary pricing。

这不是把 VRP 完全改成 time-indexed。CVRPTW 版本确实会在剩余容量、离散时间和 visited restrictions 上建 pricing graph，但 LA arc 的核心是预计算局部 elementary route block；时间离散只是让这些 blocks 能按可行时间状态拼接。TWET 的局部 block 成本随进入该 block 的完成时间变化，而且 block 内每个任务的 PWLF penalty 会共同形成输出 frontier，因此不能只存一个 scalar cost，需要存从 entry time 到 exit time/cost 的 PWLF transfer function。

Graph Generation/Graph Master 解决的是另一个问题：普通 CG 一次昂贵 global pricing 只往 RMP 加一条 route，即使这条 route 附近还有大量有用的局部变体，也要等后续 pricing 一条条发现。Graph Master 把一条新 route 映射成一个小 DAG/多图；源到汇的每条 path 都是一条可行相关 route。这样一次 global pricing 不再只增加一个变量，而是增加一个可隐式选择整族 route 的 graph block。RMP 先在已有 graph family 内做便宜的 shortest-path/family pricing；只有这些图都没有负列时，才调用原来的 global pricing 生成新 route 和新图。

图越丰富，global pricing 次数越少，但 extended RMP 越大。Principled Graph Management 因此只激活当前 reduced cost 可能有用的图节点和边，反复在小 active graph 上求解，再补充被发现有用的边。CVRPTW 的 Graph Master 进一步把 generated route 扩成一个全客户 strict total order，以 `(customer, remaining capacity, remaining time)` 为图状态，只有遵守该 order 的可行 LA arcs 才连边；一张图因此能表达原 route 及一批顺序相近的 elementary routes。

这条文献线目前主要是预印本：Graph Generation 2021、Principled Graph Management 2022、Local Area Routes 2022、Graph Master+LA for CVRPTW 2023 均为 arXiv，未检索到已正式发表的期刊版本。其实验主要证明 root-CG iteration/pricing-call 可显著减少，PGM 可使 Graph-Generation RMP 本身快数百倍；但多为小中规模原型，并非在 RouteOpt/VRPSolver 的完整 cuts、strong branching、enumeration 栈上消融。对 TWET 而言，它们需要新的 PWLF block transfer 和 extended graph master，属于新算法框架。

### 26.10 对当前主线的最终判断

Arc memory 已决定暂不动；Fully Dynamic Reduction 在当前关闭跨调用 ng warm-start 的主线中缺少原始动机，也暂不动。Selective Pricing 的动机与当前“非初等负 route 只作 witness”最贴近，但必须重做双向 PWLF dominance/join 证明，不能作为低风险优化。DOI 有约 20% 的小规模 CVRP root-CG 证据，但 TWET 缺少紧的安全交换/删除界，而且 RouteOpt/VRPSolver 的现有稳定化并不提供该界。

DeLuxing 只在 exact enumeration 后的大有限列池有用；BKF 是非机器学习、低风险的 strong-testing 预算器，是否值得做只取决于后续 profile 中 strong trial 的占比；Column Elimination、LA Routes 和 Graph Master 都会改变当前算法框架。就近期主线而言，没有一项应在缺少新 profile 或数学证明时直接实现。

## 27. Relaxed DOI、Fully Dynamic Reduction 与 Selective Pricing 的再澄清

### 27.1 Relaxed DOI 到底稳定什么，为什么最后仍然正确

考虑 set-cover master：每条 route 是一列，任务覆盖约束的 dual 为 `pi_i`。RMP 只含少量列时，dual 约束也很少，经常存在大量同值但形状完全不同的最优 dual。一轮中某个 `pi_i` 被推得很高，pricing 生成专门覆盖任务 `i` 的列；列加入后这个尖峰消失，另一个任务的 dual 又跳高。最终 lower bound 没错，但会出现 dual oscillation、许多短命列和过多 CG rounds。DOI 的目标不是增强 elementarity，也不是改 reduced cost 定义，而是从完整列集的结构证明：至少存在一组最优 dual 满足某些额外关系。把这些关系加入 RMP 后，删掉的是无必要的极端 dual，不删完整 master 的全部最优 dual，因此最终 LP 值不变。

S-DOI 的依据是“可替换性”。若任意 elementary route 中把任务 `u` 换成 `v` 都保持可行，且成本最多增加 `rho_uv`，则可以限制 `pi_v-pi_u<=rho_uv`。CVRP 中 `d_u>=d_v` 保证容量兼容，三角不等式给出简单界 `rho_uv=2*c_uv`；论文实际使用更紧的 predecessor/successor 最大插入差。其 primal 等价形式是 transfer variable：允许暂时少覆盖一个任务、以另一个任务的超覆盖补偿，并支付已知替换代价。F-DOI 的依据是“可删除性”：为从某条 route 删除任务 `u` 的成本节省构造安全 rebate，允许 RMP 对超覆盖取得受控返还。S-DOI 约束相似任务 dual 的相对差，F-DOI 抑制 over-coverage 对单个 dual 的异常激励，二者可合成 SF-DOI。[S/F-DOI 期刊论文](https://pubsonline.informs.org/doi/10.1287/ijoo.2021.0057)

标题中的两个 relaxed 容易混淆。`relaxed columns` 指 ng-routes 的列空间 `Omega+`，它包含非初等路线；`relaxed DOI` 指这些 DOI 对 `Omega+` 未必严格有效，只是先暂用。原因是 elementary route 集对“替换/删除任务”通常封闭，ng-route 集却不封闭。例如 `0-u-v-u-depot` 可能是合法 ng-route，删除 `v` 后得到 `0-u-u-depot`，反而不是合法 ng-route；因此 elementary route 上证明的 F-DOI 不能直接宣称对全部 ng-routes 有效，S-DOI 的替换也有同样问题。

论文用 active-DOI recovery 保证最终正确：先带 DOI 做 CG；当 pricing 暂时收敛时，检查 DOI 在 primal 侧对应的 transfer/rebate 辅助变量。若某个辅助变量取正值，说明当前解实际依赖这条对 ng columns 未必有效的 DOI，就删除该 active DOI，并从现有列池继续 CG。重复到所有 DOI 辅助变量均为零，此时当前解不依赖任何临时放宽，得到的就是原 `Omega+` master 的最优值。由于 DOI 数量有限，这个删除循环有限终止；它不是用一个可能错误的 certificate 直接结束。[Relaxed DOI 原文](https://arxiv.org/abs/2004.05499)

实验只覆盖 46 个最多 50 客户的 CVRP root-CG，ng size 为 5。平均用时为标准 `1354s`、S-DOI `1006s`、F-DOI `1162s`、SF-DOI `999s`；论文按实例汇总称 S/SF 平均约快 `20%`。S-DOI 在 44/46 个实例改善，SF-DOI 在 41/46 个实例改善，F-DOI 单独没有平均优势；S-DOI 只有 2/46 个实例触发 recovery，而含 F-DOI 的方案频繁触发。这个证据说明“紧的任务替换界”确实能稳定 CVRP root CG，但没有 BPC 树、SRI、强分支或软时间窗，不能外推成 TWET 整体快 20%。

TWET 当前缺的不是 DOI 框架，而是紧且安全的 `rho_uv`/rebate。替换或删除任务会改变前后 sequence-dependent setup，并平移整条后缀的 completion times，多个 PWLF 成本会同时变化。局部两条 setup arc 无法覆盖后缀影响；BigM 虽安全，却使 DOI 近乎不约束 dual。因此当前结论仍是：DOI 原理和 CVRP 结果成立，但在没有推导出非 BigM 的全路线安全界前，不进入实现。

### 27.2 Fully Dynamic Reduction 在什么时刻用，和当前代码是什么关系

Bulhoes、Sadykov、Uchoa 的 fully dynamic ng-path 不是每次发现重复 route 后做 reduction。其主流程让 ng-memory 跨多次 LP/CG 迭代持续增长，子节点还继承父节点最终 memory；aggressive augmentation 会一次加入较多 arc-memory restrictions。历史限制越积越多后，label 数可能爆炸，而其中一部分限制只对旧 dual 下的旧坏路线有用，对当前 dual 已无作用。论文以单次 labeling 超过 `100s` 为触发器：中断当前 CG，固定当前 LP 的最优 dual `pi*`，调用 reduction；完成后将后续 augmentation 从 aggressive 切为 moderate，并重启当前迭代。[Minimum Latency 论文](https://www.sciencedirect.com/science/article/pii/S0305054818300248)

reduction 不是从旧 memory 中逐项试删。设旧 memory 为 `M_old`，算法从空 memory `M_new` 开始，在固定 `pi*` 下做 labeling。若 `M_new` 的最优 route 在 `M_old` 下也可行，则停止；否则只使用受 `M_old` 允许的 moderate augmentations 阻断当前最优坏路线，再重算。因为 `M_new` 限制更少，`minRC(M_new)<=minRC(M_old)`；而停止时 `M_new` 的最优 route 又属于 `M_old` 的路线集，所以 `minRC(M_old)<=minRC(M_new)`，两者相等。由此新 memory 可以更小，同时保持当前 dual 下的 pricing value；结合 `pi*` 是 `LP(M_old)` 的最优 dual，可保持当前 LP lower bound。它保持的是**当前 dual/当前 LP bound**，不是保证以后每组 dual 下都与旧 memory 等价。

当前 TWET 主线的生命周期不同。`GCNGBBStyleBidirectionalNgDssr.solve()` 每次调用开始把 `ngNeighborhoodByJob` 置空，本次调用首轮再按基础模式初始化；同一次调用内，各 DSSR 轮才单调增加 memory。正式 profile 又关闭 `enableNgDssrHistoryWarmStart` 和 `enableNgDssrSameNodeWarmStart`，因此完成一次 pricing call 后，膨胀的 final ng-set 默认不会进入下一次 RMP dual，更不会由 child 长期继承。论文 reduction 要清理的“跨 CG/跨节点累积历史包袱”在当前主线不存在。

若硬要放进当前实现，唯一相近位置是单次 exact call 内某一 DSSR round 已极慢时：用当前固定 dual，从较小 memory 重建到与当前 pricing value 相同，再继续 DSSR。但这会丢掉本次已积累的 elementarity restrictions，后续很可能重新发现相似 witness。更关键的是，论文的 bound-preserving reduction 只能证明当前 relaxed pricing value 没变，不能替代当前最终的 elementary/no-negative certificate；reduction 后仍必须继续完整 exact pricing。只有 profile 明确显示“同一 pricing call 后期因 memory 膨胀导致 label/时间突增”，并且重建成本小于后续节省，才有实验价值。当前没有这一证据，因此不实现；若未来打开跨调用/父子 memory 继承，它才重新获得论文中的主要动机。

### 27.3 Selective Pricing 从目标、证书到 label 操作

先用一个数值情形说明动机。对当前 RMP dual，所有 elementary routes 的最小 reduced cost 已是 `+0.2`，实际上没有真实可加列；但 ng-relaxation 里仍有 `A-B-A` 这样的重复 route，reduced cost 为 `-5`。标准 ng pricing 的任务是求整个 relaxed 集 `R_hat`，所以看到 `-5` 就不能结束；DSSR 阻断它后可能又出现 `-3`、`-1` 的重复 route。Selective Pricing 只要求回答“真实 elementary 集 `R` 中是否存在负 route”，因此允许在这些负 relaxed routes 尚存在时证明 `minRC(R)>=0` 并停止。

它的精确定价合同不是“只返回 elementary route”。传统合同为：若 `R_hat` 中存在负 route，就返回一条负 route；没有返回时证明 `R_hat` 全部非负。Selective 合同为：若 `R` 中存在负 elementary route，就必须返回一条负 route，但返回的这条可以是 elementary，也可以是 relaxed；没有返回时才证明 `R` 全部非负。也就是说，它放弃保证找到 relaxed 集的最短路，只保留“不漏掉负 elementary route 的存在性”。[Selective Pricing 原文](https://pure.eur.nl/ws/portalfiles/portal/48204101/Repub_116700.pdf)

论文允许已生成的 relaxed routes `R0` 留在 RMP。结束时，`R0` 都是显式 RMP 变量，故 reduced cost 非负；Selective certificate 又保证所有未显式生成的 elementary routes `R` 非负。因此当前 RMP 已经精确求解了列集 `R0 union R`，其值仍是原整数模型的合法 lower bound。未生成的其他 relaxed routes 即使为负也不属于这个被求解的列集。由于 `R0 union R` 比完整 `R_hat` 小，这个 bound 还可能高于标准 ng master bound；代价是 bound 依赖具体生成过哪些 `R0`，child 甚至可能因新 relaxed columns 出现而低于 parent，论文用 parent bound 兜底。这一 master 语义是理解该方法的关键，不能把它简化成“返回前过滤非初等列”。

它如何做到“不漏 elementary route”，核心是 dominated-path set。普通 label `L` 只有一条显式路径 `p(L)`，但执行 dominance 后，它实际上还代表被它及其前缀支配掉的一组隐藏路径 `S(L)`。论文不存完整 `S(L)`，只存 `C(L)`：`S(L)` 中所有路径共同访问客户的交集。假设显式路径是 `0-1-2-3`，它还代表隐藏路径 `0-4-2-3`。显式路径再访问 1 会形成 `0-1-2-3-1`，但隐藏路径可以形成 elementary 的 `0-4-2-3-1`，所以仅看到显式路径重复 1 不能剪；因为 1 不是两条路径共同访问的客户，也就不在 `C(L)`。只有 `j in C(L)` 时，所有隐藏路径都已经访问过 `j`，扩到 `j` 才不可能产生任何 elementary completion，可以安全跳过。

同理，普通 dominance 可能仅因 `M(L1)` 比 `M(L2)` 多禁止若干客户而无法让资源更优的 `L1` 支配 `L2`。若这些差集客户都在 `C(L2)` 中，它们对 `L2` 代表的每条隐藏路径也已经访问过，任何 elementary continuation 本来就不能再用；于是可放宽为 `M(L1) subset M(L2) union C(L2)`。由于 label 后续吸收新的 dominated paths 时 `C(L)` 可能缩小，论文还加了更严格的 dominance 稳定条件，防止已经依据 `C(L)` 执行的剪枝事后失效。它不是机器学习，也不是简单 cycle filter，而是把 dominance 的正确性目标从“保留 relaxed shortest path”改成“保留至少一条可能的 negative elementary completion”。

实验结果有明确条件性。九个带困难 non-robust cuts 的 200-customer Homberger root 中，相对同栈标准 pricing 平均省时 `16.3%`、最好 `32.7%`，没有实例变慢；但只保留 capacity cuts 时，带相同 heuristic 的 Selective Pricing 平均慢 `8.9%`，不带 heuristic 时只快 `4.1%`。逐次 pricing 的 label 数和时间也并非总下降。它有效的主要场景是 relaxed cycles 与 non-robust cut dual 共同使 exact ng pricing 很难，不是一般性的 label 加速器。

当前 `ngDssrReturnRelaxedColumns=false`，论文的 `R0` master 语义并不存在：非初等负 route 只作 DSSR witness，不进入 RMP。若保持当前流程，唯一可考虑的迁移是把 Selective dominance 作为 ng-DSSR 内部的 exact certificate：返回 elementary route 时正常加列，返回 relaxed route 时仍只更新 DSSR，返回 none 时允许在仍有负 relaxed route 的情况下结束。这个版本在逻辑上可以不改变 master，但必须重新证明双向 PWLF labels 的 forward/backward dominated-path summary、frontier dominance 和 join 都满足“none implies no negative elementary route”。论文只有单向、标量资源的 VRPTW 证明，不能直接覆盖当前一条 label 表示多个时间-成本函数段的实现。因此当前结论是：思路与现有 witness-only DSSR 的浪费最相关，但实现和证明风险最高，且实验收益不稳定，暂不进入主线。

## 28. DOI 的最优 dual 口径、Fully Dynamic Reduction 细节与 ng-route 列分类

### 28.1 “保留一组完整 master 最优 dual”到底是什么意思

完整 master 的 dual 往往不是唯一点，而是一整个 optimal face。DOI 不要求每一组最优 dual 都满足新增不等式，只要求原 optimal face 与新增不等式有非空交集。也就是说，它可以删掉一部分形状极端但目标值相同的最优 dual，只要至少留下一组同目标值 dual，完整 master 的最优值就不变。“完整”修饰的是已经考虑全部合法列的 master，不是说要保存一份 dual 向量供后续使用。

S-DOI 的 `pi_v-pi_u<=rho_uv` 来自一个列替换界。设任意包含 `u`、不包含 `v` 的合法列 `r`，都可以把 `u` 替换成 `v` 得到合法列 `r'`，且 `c(r')-c(r)<=rho_uv`。若某组最优 dual 违反该式，令 `delta=pi_v-pi_u-rho_uv>0`。由替换列 `r'` 的 dual feasibility，

`sum_(i in r) pi_i - pi_u + pi_v <= c(r') <= c(r)+rho_uv`，

所以每条“含 `u` 不含 `v`”的列在原 dual 下至少有 `delta` slack。取 `epsilon=delta/2`，令 `pi'_u=pi_u+epsilon`、`pi'_v=pi_v-epsilon`。dual 目标 `sum_i pi_i` 不变；含 `u` 不含 `v` 的列只消耗已有 slack，含 `v` 不含 `u` 的列变得更松，同时含二者或均不含的列不变。因此 `pi'` 仍 dual-feasible、目标值仍最优，而且 `pi'_v-pi'_u=rho_uv`。这证明了即使原最优 dual 违反 DOI，也能在同一 optimal face 上构造一组满足 DOI 的最优 dual。CVRP 的 `rho_uv` 正是替换客户后两条相邻弧成本增量的统一上界；若替换不能保持合法，`rho_uv` 就是无穷大，该 pair 不能形成有效 DOI。[Relaxed DOI 原文](https://arxiv.org/pdf/2004.05499)

该论文的实验不是成熟 BPC 求解器上的增量消融。它只解 relaxed ng-route root master：46 个 A/B/P/E CVRP 实例、最多 50 客户、每个客户取 5 个近邻，ng pricing 用动态规划；代码为 MATLAB，RMP 由 CPLEX 解，基线明确是 non-stabilized CG。正文没有报告 cuts、branching、strong branching、heuristic pricing、route enumeration、BPC tree 或其他 dual stabilization。因而 `20%` 是相对一个无稳定化 root-CG 原型的结果，不是 DOI 加在 RouteOpt/VRPSolver 完整组件栈上的边际收益。S-DOI 44/46 改善、平均约 20% 有一定一致性，但实例小、绝对时间仍高，且 F-DOI 没有平均收益；对 TWET 应评价为“机制有证据，但实验强度一般，迁移界又难构造”，不应排在近期实现前列。

### 28.2 Fully Dynamic Reduction 为什么要积累，以及逐步如何工作

用户的判断基本正确：论文先用 aggressive augmentation 快速加入大量限制，labeling 超过 `100s` 后需要把膨胀 memory 瘦身，并改用 moderate augmentation；如何从旧限制中选择真正必要的一部分正是 reduction 的任务。但根因不只是“存在两种更新模式”，而是论文把 memory 作为 **LP 放松列空间的定义**。`Omega(M)` 包含全部 elementary routes，同时允许满足 memory `M` 的非初等 ng-routes；这些 relaxed routes可以直接作为 `LP(M)` 的列并取正值。每次 LP 解后，算法从正值 non-elementary columns 中找 cycle，再增大 `M`，删除已被新 memory 禁掉的列并重解更紧的 `LP(M)`。因此 `M_1 subseteq M_2` 意味着 `Omega(M_2) subseteq Omega(M_1)`，lower bound 单调不减。

这解释了为什么 memory 要跨 CG 累积。若下一轮 LP 前把 memory 清空，前一轮刚从 master 中排除的 non-elementary route family 会重新合法，放松又退回原处，同一批 cycle 会反复出现，之前取得的 lower-bound tightening 也消失。子节点继承父 memory 同理：所有 elementary routes始终保留，所以继承不影响 exactness；它只让 child 不必重新学习父节点已经识别的 relaxation weaknesses。这里的 memory 是 master relaxation 的状态，不是一次 pricing 调用内的临时 witness 表。

reduction 的完整流程如下。先保存旧 memory `M_old` 和当前 `LP(M_old)` 的最优 dual `pi*`，再令 `M_new` 为空。随后固定 `pi*` 对 `Omega(M_new)` pricing：

1. 若当前最优 route `r_new` 也属于 `Omega(M_old)`，立即停止。
2. 若 `r_new` 被 `M_old` 禁止，则从它暴露的 cycle 中做 moderate augmentation，但只能重新加入原来已经属于 `M_old` 的 arc-memory 元素；`M_old` 在这里是允许重建的零件库，不允许创造旧集合外的新限制。
3. 重新 pricing，反复执行，直到新最优 route 被旧 memory 接受。

始终有 `M_new subseteq M_old`，所以新限制更少、候选路线更多：`Omega(M_old) subseteq Omega(M_new)`，从而 `z_new=min_(r in Omega(M_new)) rc(r)<=z_old=min_(r in Omega(M_old)) rc(r)`。停止时，新集合的最优 route `r_new` 又属于旧集合，于是旧集合也可以选择它，得到 `z_old<=rc(r_new)=z_new`。两式合并才得到 `z_new=z_old`。这不是说“用 `M_new` 更新时只能使用 old route”，而是说可重新加入的 **memory 元素** 只能来自 `M_old`；每一轮产生的最优 route 恰恰是在当前较松的 `M_new` 下重新算出的，可能从未在旧 LP 中出现。

停止路线不要求 elementary，只要求它在 `M_old` 下 ng-feasible。论文保持的是固定 `pi*` 下旧 relaxed master 的 pricing value和当前 LP bound，不是恢复 elementary certificate。触发也确实很少：它被设计成单次 labeling 超过 `100s` 后的应急机制；作者还明确报告更频繁 reduction 会因重建本身耗时而损害 convergence。实验表中它主要出现在约 100 客户以上的困难实例，大部分容易实例不触发。因此它对平均实例可能是冗余的，但对少数 memory 已失控的 hard instances 是 robustness 组件，而不是日常加速器。[Minimum Latency 论文](https://www.sciencedirect.com/science/article/pii/S0305054818300248)

### 28.3 不同文献中的 relaxed route、固定 ng-set 与 elementary route

最后纠正当前代码表述。`solve()` 开头把 `ngNeighborhoodByJob=null` 只是丢弃上一 pricing call 的工作集合并设置“尚未初始化”哨兵；真正进入 exact 初始化时，`initializeNgNeighborhoods()` 会按 `ngDssrInitialNgSetMode` 重建集合。当前 profile 使用 `nearestK`，默认 `ngDssrInitialNgSetSize=-1` 解析为 `floor(n/10)`；若实验配置显式设为 `3`，则每个 job 每次调用都从最多 3 个允许的最近任务开始，而不是从空集开始。只有模式显式配置成 `empty` 时初始集合才为空。同一次 `solve()` 内后续 DSSR rounds 不会重新初始化，而是在这组基础集合上单调增加。当前关闭 history/same-node warm-start，所以增长后的 final set 默认不跨 pricing call 或父子节点保留。由此，Fully Dynamic Reduction 的论文级动机在当前主线确实基本不存在；只有将来启用跨调用继承，或 profile 证明单次 solve 后期发生 memory-driven label explosion，才值得重新评估。

## 29. DOI 的实际作用与三层 ng-memory 口径

### 29.1 DOI 是 dual stabilization，不是提高最终 LP bound

DOI 的直接作用是限制 CG 过程中 RMP 可以选择的 dual 形状，减少由缺列和 dual degeneracy 引起的剧烈 oscillation。RMP 尚未包含全部列时，同一个 lower bound 附近可能有很多差异很大的 dual：本轮把 `pi_u` 推得很高，pricing 生成专门利用该尖峰的列；列加入后 `pi_u` 降下去，另一个 `pi_v` 又出现尖峰。许多列只在一两轮内具有负 reduced cost，随后立即失效，导致 CG rounds 和短命列增加。S-DOI 用任务可替换成本限制相似任务 dual 的相对差，使 pricing 看到的 reduced-cost landscape 更平滑。

它可以缓解 dual degeneracy 的后果，并可能缩小 optimal face，但不能简单说成“消除退化”：primal RMP 仍可能退化，dual 仍可能不唯一。它也不提高完整 master 的最终 lower bound；有效 DOI 只是在不删除全部最优 dual 的前提下选择较稳定的一部分。主要预期收益是减少 dual jumps、无效列和 CG iterations。

若直接写 dual，S-DOI 确实就是增加约束 `pi_v-pi_u<=rho_uv`。但代码通常求的是 primal RMP，因此按 LP 对偶关系，增加一条 dual 约束等价于在 primal RMP 增加一个非负辅助变量 `omega_uv`，其目标系数为 `rho_uv`，在任务 `u` 的覆盖行取 `-1`、任务 `v` 的覆盖行取 `+1`。它表示支付 `rho_uv`，暂时把一单位 `u` 的覆盖要求转移为 `v` 的额外覆盖。这个变量不是一条真实 route；它给不完整 RMP 提供一个已知安全成本的替换方向，从而不必靠极端 dual 诱导真实列。F-DOI 同理通过 rebate auxiliary variables 表达受控的过覆盖/删除。Relaxed DOI 若在 ng master 上未必有效，则在收敛时删除仍取正值的辅助变量并重新 CG，直到最终解不依赖它们。

### 29.2 先分清三层：master 列口径、长期 ng-memory、pricing working memory

第一层是 **master column universe**：RMP 最终允许 elementary routes，还是也允许 non-elementary ng-routes。这决定最终求的是 elementary master bound 还是 ng-relaxed master bound。

第二层是 **长期 target/global memory**：哪些重复模式被 ng-relaxation 永久禁止。经典固定 ng-route relaxation 为每个客户预先选固定近邻集合 `N_i`，整个 root CG 中不改变；Bulhoes 等的 dynamic ng-master 则让 `M` 随外层 LP 解动态增长，并由父节点传给子节点。

第三层是 **一次 pricing 内的 working memory**：为了降低一次 exact pricing 的初始状态空间，DSSR 可以先使用较小的 `Gamma_i`，发现不合格最短路后逐轮增加，直到对第二层的目标 relaxation 或 full elementarity 取得正确 certificate。这个 working memory 可以在 pricing 返回后丢弃，不代表第二层发生变化。

经典固定 ng-master 可以概括为：第一层允许 ng-routes，第二层的 `N_i` 固定，第三层可直接按完整 `N_i` pricing，也可以用 DSSR 从 `Gamma_i subseteq N_i` 逐步恢复到目标 `N_i`。若最终最优 route 只需要对固定 `N_i` ng-feasible，它仍可能重复客户，并可以进入 master。

当前 TWET 则是：第一层只允许 elementary routes，第二层没有一个 size=`floor(n/10)` 的全局 ng-master；真正长期不变的目标是 full elementarity。`floor(n/10)` 或显式 `3` 只是第三层每次 exact pricing 的初始 working memory。非初等负路线只暴露当前 working memory 太松，驱动同一次 `solve()` 继续增加限制；它不进入 RMP。取得 elementary columns/无负 elementary route 的 certificate 后，本次新增 memory 被丢弃，下次 pricing 再从基础 initial K 开始。因此不能把当前 initial K 称为“全局固定 ng-set”，它只是全局固定的 **初始化规则**。

dynamic ng-master 的三层则是：第一层允许当前 `Omega(M)` 中的 non-elementary ng-routes进入 RMP；第二层 `M` 是节点级长期状态，先解当前 `LP(M)`，再根据 LP 中取正值的 non-elementary columns 增大 `M`，删除被新 memory 禁止的 relaxed columns并重解；child 继承 parent 的最终 `M` 后还可继续增长。其外层循环是 `solve LP(M_k) -> inspect active relaxed columns -> M_(k+1) -> solve tighter LP`，不是当前 TWET 的 `one pricing call -> DSSR rounds -> discard additions`。Fully Dynamic Reduction 清理的正是第二层长期 `M`，不是第三层一次 pricing 的临时集合。

### 29.3 固定 K 与 relaxed columns 进 master 为什么是两件事

固定 `K` 只回答“哪些重复路线算作合法 ng-route”。例如某条 `0-A-X-A-0` 是否被允许，取决于固定 neighborhoods 在经过 `X` 后是否还记得 `A`。它没有回答“找到这条合法 ng-route 后，是否把它作为 RMP 变量”。后者由第一层 master policy 决定。

同一套固定 `K=5` 可以有两种完全不同的用法：

1. **ng-relaxed master**：只要路线满足固定 `N_i`，即使重复客户也直接加入 RMP；最终得到固定 ng-master 的 LP bound。Baldacci 的 ng-route relaxation和 Relaxed DOI 实验属于这种口径。
2. **elementary master 的内部 relaxation**：先用 K=5 减少 labeling 状态；若最优负路线非初等，就把它当 witness 增加 working memory而不加入 RMP，直到找到 elementary route 或证明不存在负 elementary route。当前 TWET 属于这种口径。

还有第三种 dynamic ng-master：non-elementary route 先允许进入 RMP；如果它后来在 LP 解中取正值并暴露放松过弱，则增大全局 `M`，使它和同类 routes 以后不再合法。它位于前两者之间：master 当前允许 relaxed columns，但允许集合会在外层算法中逐步收紧。

因此更准确的分类不是“固定 ng-set”和“relaxed columns”二选一，而是分别回答两个问题：`N/M` 是固定、动态还是仅作 DSSR 临时状态；RMP 接受 elementary only，还是接受当前 memory 下的 ng-routes。Martinelli 等既能以固定目标 `N_i` 精确定价 restricted non-elementary ng-routes，也能把目标设为 full elementarity 后只返回 elementary routes，正好说明这两个维度可以独立组合。

## 30. Dual oscillation、DOI 数量和 reduction 内部 DSSR 关系

### 30.1 Dual oscillation 的动机、形成机制与实际代价

Dual oscillation 指 column generation 相邻迭代的 dual 向量发生大幅、反复且缺乏稳定方向的变化，即使 RMP objective 或真实 full-master bound 只改善很少。它不是普通的“dual 数值在变化”，而是由 restricted master 缺列和高度退化共同造成的搜索不稳定。

完整 master 对每条潜在 route 都有一条 dual feasibility 约束 `sum_i a_ir*pi_i<=c_r`。RMP 只保留少量 route columns，等价于 dual 暂时缺少大量约束，因此某些任务 dual 可以被推得很高而不违反当前 RMP。覆盖/分割 master 又高度退化：很多列结构相近，同一 primal objective 可能对应大量 primal bases 和一整个 dual optimal face。单纯形法本轮可能返回 optimal face 的一个极端点，下轮增加几条列后又跳到远处的另一个极端点。

例如任务 `u,v` 在完整列空间中地理、资源和替换成本都相近，合理 dual 应相近；但当前 RMP 恰好缺少含 `u` 的便宜列时，可能出现 `pi_u=100, pi_v=5`。pricing 于是生成一批专门利用 `pi_u` 尖峰的列。列加入后，这些新 dual constraints 压低 `pi_u`，求解器又可能把 `pi_v` 或另一个任务推高；上一轮生成的列 reduced cost 很快转正，形成短命列。结果表现为 CG rounds 增多、列池膨胀、pricing 反复解决不同的偏置目标，lower bound 却缓慢改善，严重时还会 tailing-off。

DOI 的动机正是利用完整列空间的结构，提前补上一部分“缺失列最终一定会施加的 dual 关系”。S-DOI 不知道具体缺少哪条 route，但知道 `u` 可被 `v` 以至多 `rho_uv` 替换，因此限制 `pi_v-pi_u<=rho_uv`。它把 dual 从无意义的极端点推向同一 optimal face 内较平滑区域，使连续 pricing rounds 的 reduced-cost landscape 更一致。它缓解的是 dual degeneracy 的后果和 oscillation，不保证 primal 不退化、dual 唯一，也不增强完整 master 的最终 bound。评价此类方法以后必须按“形成机制、被修改的算法层、正确性、实现成本和实验增量”展开，不能只写“稳定 dual”。

### 30.2 DOI 数量是否确定，以及是否需要动态加变量

S-DOI 对给定实例有一个有限候选集合 `S={(u,v):rho_uv<infinity}`。CVRP 中只有替换保持容量可行的有向 pair 才进入，例如论文条件为 `d_u>=d_v`；最坏不超过 `n(n-1)` 条。若在 primal RMP 实现，就是最多同数量的 `omega_uv` 辅助变量。它们可以在第一次求 RMP 前统一创建，不需要随着 route columns 动态产生。论文还明确建议只选最 restrictive 的 DOI，即 `rho_uv` 最小的一部分，避免二次数量全部进入模型。Relaxed DOI recovery 的动态操作主要是删除最终仍 active 的 DOI，再重启 CG，而不是每轮发现一个 route 就新增一条 S-DOI。

F-DOI 更复杂。理论上 rebate `sigma_ur` 与具体 route `r` 有关，新列可能带来新的 `sigma`，原始集合 `Lambda_u={sigma_ur}` 可能很大。论文通过把 `sigma` 向下离散到每个任务的一组小型有限 levels，避免 rebate auxiliary variables 和 linking rows随列数增长而爆炸。新 route 加入时只需计算它属于哪个已有 rebate level，并把该 route variable 对已有 linking row 的 coefficient 一并加入；这是普通 column construction 的额外稀疏系数，不要求不断创建无限种 DOI 变量。若实现者选择按需增加新 level，CPLEX 技术上支持增量加 row/variable和重优化，但会增加 basis/model 管理复杂度，论文的有限离散化正是为了避免这一点。

因此对当前问题若只考虑 DOI，S-DOI 的工程复杂度明显低于 F-DOI：预计算一组安全 pair 和 `rho_uv`，建立固定 auxiliary columns即可。真正困难的不是动态模型修改，而是 TWET 中任务替换会改变 setup 和整条后缀 PWLF，尚未得到紧的安全 `rho_uv`；使用 BigM 后 DOI 基本不产生约束效果。

### 30.3 Fully Dynamic Reduction 内部有没有 DSSR

有一个与 DSSR 同构的迭代 refinement 流程，但论文不是在做“恢复 elementary pricing”的传统 DSSR。需要区分三个循环：

1. 固定全局 memory `M` 的 CG：反复解 RMP、pricing 并加入当前 `Omega(M)` 的列，直到解完 `LP(M)`。
2. Dynamic ng-master 外层收紧：检查 `LP(M)` 中取正值的 non-elementary routes，据此增大全局 `M`，再解更紧的 `LP(M)`。
3. 超过 `100s` 后的 reduction：固定当前 dual `pi*`，令临时重建 memory `M_red` 从空开始；每次 labeling 找 `Omega(M_red)` 的最优 route。若该 route 不被旧 `M_old` 接受，就只用 `M_old` 中已有的 memory 元素做 moderate augmentation，再 labeling；直到当前最优 route 被 `M_old` 接受。

第三个循环的形式就是 `relax memory -> solve pricing -> inspect violating route -> augment memory -> reprice`，与 DSSR 的骨架相同。区别在终止目标：传统 elementary DSSR 要让最终最优 route elementary，或证明没有负 elementary route；reduction 只要求当前最优 route 对 `M_old` ng-feasible，从而证明固定 `pi*` 下 `minRC(M_red)=minRC(M_old)`。该 route 仍可以 non-elementary，reduction 也不提供 elementary certificate。

因此不能说 reduction “完全没有 DSSR”，更准确的说法是：它内含一个 target-memory DSSR 式重建循环，但没有再嵌套一套以 full elementarity 为目标的 DSSR。完成 reduction 后，全局 memory 被替换为较小的 `M_red`，当前 CG 迭代重启，并改用 moderate augmentation继续 dynamic ng-master；后续 exact B&P 仍依赖论文其他阶段处理完整最优性。

## 31. Fully Dynamic Reduction 的触发、选取和再次增长

### 31.1 先纠正主流程术语和粒度

论文外层不断增大全局 `M` 的流程不应称为 DSSR。它是 dynamic ng-path relaxation refinement：每个外层迭代先通过一整轮 column generation 求得当前 `LP(M_k)` 的最优 primal-dual pair，再从取正值的 non-elementary ng-routes 中选 cycle，构造更强的 `M_(k+1)`。一次 `LP(M_k)` 通常包含多次 RMP solve 和 pricing call，所以也不能精确表述成“每次 pricing 就增大一次基准 ng-set”。正确粒度是 `solve complete LP(M_k) -> augment global M -> solve LP(M_(k+1))`。

当前 TWET 的 DSSR 是同一个 pricing call 内围绕固定 dual，从初始 working memory 出发，利用 negative non-elementary witnesses 增加限制，目标是 elementary column/certificate；论文 dynamic ng 外层则改变下一整个 relaxed master 的列空间。两者不在同一算法层。论文自己只把 reduction Algorithm 4 描述为 based on the same DSSR technique，因为它确实在固定 dual 下执行 repeated labeling/refinement。

DOI 当前结论同时冻结：其作用是抑制 dual oscillation，但 TWET 尚无非 BigM 的安全紧替换/删除界，小规模 non-stabilized root-CG 的约20%证据不足以支持近期实现。后续除非找到适配 setup+PWLF 后缀影响的紧 `rho_uv`，不继续投入实现分析。

### 31.2 超过 100 秒后到底发生什么

根节点从等价于 time-nearest size 8 的 memory 开始，节点初始 augmentation mode 为 aggressive。若一次 labeling call 的耗时超过 `t_red=100s`，该节点将当前 dynamic-ng/CG 流程转入 reduction，调用参数为 `alpha_R=5, beta_R=200`，随后以缩减后的 memory 重启当前外层迭代，并把后续 augmentation mode 永久切到 moderate。若 labeling time 再次超过阈值，论文的 node stop condition I 会停止该节点的 dynamic-ng refinement，而不是无限 reduction。

论文文字写的是“single labeling call exceeds 100 seconds, column generation is interrupted”，但 formal Algorithm 4 要求输入 `pi*` 是 `LP(M_old)` 的最优 dual，Algorithm 2/7 也先写 `Compute an optimal primal-dual pair` 再检查 reduction condition。正文没有给出 label 热循环中在恰好100秒强制中断并用 partial dual 的实现细节。因此不能断言它在 `100.000s` 直接杀掉 labeling。数学上可靠的解释是：某次 labeling 已被识别为超过阈值的昂贵调用，完成/取得当前 `LP(M_old)` 的有效最优 dual 后停止继续旧 memory 的外层推进，转而 reduction；不能用未闭合 RMP 的任意 dual宣称 bound-preserving reduction。

### 31.3 它怎样从旧 memory 中选择元素

它不先给 `M_old` 中每条 arc-memory element 计算频率或重要性，也不逐项试删，而是从空集做 greedy reconstruction：

1. 保存 `M_ori=M_old`，令当前重建集合 `M_red=empty`，固定 `pi*`。
2. 在 `Omega(M_red)` 上 labeling，返回一组 routes；augmentation 按 reduced cost 非递减顺序处理，最危险的 routes 优先。
3. 若全局 best route 已对 `M_ori` ng-feasible，停止。
4. 否则检查返回 routes 的重复 cycles，先按 cycle size 非递减顺序处理长度不超过 `alpha_R=5` 的短 cycle。短 cycle 需要更少 memory，且更容易反复出现。
5. 若某 route 没有可禁止的短 cycle，第二阶段才允许考虑任意长度 cycle，并在成功禁止一个后转到下一 route。
6. `A` 明确禁止所有不 confined to `M_ori` 的 augmentation；`cycleCanBeForbidden` 只有在 moderate mode 所需的每条 arc-memory element 都已属于 `M_ori` 时才允许该 cycle。
7. moderate mode 只把该实际 cycle 前缀上的 arcs 加到重复顶点的 arc-memory，不像 aggressive mode 那样加入 cycle 顶点间的大量两两 arcs。
8. 单次 `augmentNgMemories` 最多显式禁止 `beta_R=200` 条 routes，然后重新 labeling；循环直到 best route 被旧 memory 接受。

所以 selection 的本质是：在当前 `pi*` 下，从最有竞争力的旧 memory 违规 routes 开始，用尽量短、尽量稀疏、且完全属于 `M_old` 的 arc restrictions重新组成一个 working subset。它优化的是“当前 dual 下先挡住谁”，不保证得到基数最小的 `M_red`，论文也明确只称 often significantly smaller。

### 31.4 dual 更新后会不会重新需要被删掉的旧元素

会，完全可能。Reduction 只证明当前 `pi*` 下 `LP(M_red)` 与 `LP(M_old)` 具有相同 bound，不证明对未来所有 dual 都等价。某个从 `M_old` 删除的 arc restriction 可能只是在当前 dual 下不影响最短 ng-route；重解 RMP、加入 cuts/branch constraints或进入 child 后，另一个 dual 可能让它原先禁止的 non-elementary route重新有吸引力。

但这不会造成正确性问题。`Omega(M_red)` 仍包含全部 elementary routes，只是重新允许更多 non-elementary routes，因此始终是合法 relaxation。Reduction 停止时，旧最优 dual `pi*` 已能证明扩大的 `Omega(M_red)` 中没有 route 降低当前 bound，所以刚缩减时 `LB(M_red)=LB(M_old)`。随后即使中间 RMP dual 生成一条曾被 `M_old` 禁止的 route，它也只是 `LP(M_red)` 的合法 relaxed column；完整求完 `LP(M_red)` 后 bound不会低于刚证明的值。

如果这条 route 在新的最优 primal 解中取正值，dynamic ng 外层会再次从其 cycle 做 moderate augmentation，之前删掉的某些 old elements可能被重新加入，也可能选出新的更稀疏 elements。论文接受这种 re-learning：与其让所有历史 restriction 永久拖慢每次 labeling，不如只保留当前 bound 所需的 working set，未来真正重新重要时再加回来。

因此全局 memory 在发生 reduction 时不是单调的，但 lower bound 仍保持非递减：augmentation 只缩小 route set、提高或保持 bound；reduction 在当前 dual 下保持 bound不变。算法不保证某个 memory element 永不重复加入，也没有理论上排除 shrink-regrow cycle；工程控制依赖三个措施：只在 labeling 已超过100秒时 reduction、第一次后切换为更稀疏的 moderate augmentation、第二次超过阈值就停止该节点的 dynamic refinement。作者明确报告更频繁 reduction 会耗时并损害 convergence，这正说明 re-learning 是真实代价，而不是被理论消除的问题。
