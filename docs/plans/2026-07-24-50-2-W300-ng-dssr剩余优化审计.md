# 50-2 W300 ng-DSSR 剩余优化审计

2026-07-24 基于当前主线完整日志重新拆解。当前 run 为 `765.517s`、16 个节点、`obj=bound=9019`、`valid=true`。全程 heuristic pricing 为 `268.186s/863 calls`，ng-DSSR exact 为 `297.443s/232 calls`，master LP 为 `105.388s`；其中 after-pricing LP 为 `60.843s/1186 calls`，strong lightweight trial RMP 为 `43.004s/480 calls`。

## 1. 当前最主要的结构性开销

node 8 的 87.508 秒长尾由 heuristic 37.538 秒和 exact 45.152 秒共同组成。第一次 exact 返回 169 列，后续 24 次 exact 合计只返回 86 列；每次 exact 加列后，PC 都立即重解 RMP，并从第一个 pricing engine 重新开始。后 24 个循环中，15 次 heuristic 立即失败，另外 9 次又能继续补到列。因此这里确实存在一部分重复 heuristic 开销，但不能直接跳过：本例中重新运行 heuristic 仍有相当比例能在新 dual 下找到列。

同一 dual 下继续 DSSR 批量累计基本列已经做过 A/B。它会减少少量 RMP 往返，但旧 dual 下额外强化 ng-set 和 labeling 的成本更高，完整 root 没有稳定收益，当前不应重复实现。启发式 non-best 候选扩充、自适应提前停和历史 warm-start也已有负面或不稳定证据。

## 2. midpoint probe 的真实开销

232 次 exact 的 `exactInitializeProbe` 合计 140.735 秒，但这不是全部浪费。按候选日志逐次恢复，probe 候选自身累计约 78.699 秒，其中最终选中并继续用于正式扩展的状态约 60.554 秒；明确属于未选候选的开销约 18.143 秒。只有 37/232 次 exact 测试了多个 Tmid，平均候选数 1.319，最大 3；43 次选中状态已把队列跑空，189 次为可继续扩展的 partial 状态。

node 8 中 probe 为 21.255 秒，候选执行约 13.380 秒，最终复用约 9.216 秒，明确丢弃约 4.164 秒。由此可知，probe 仍有优化空间，但理论上可直接消除的规模远小于 140.735 秒。最合理的下一步是只对 DSSR 后续轮做 A/B：上一完整轮 F/B 时间已在阈值内时，从原 Tmid 直接开始正式扩展；失衡时仍运行现有 probe。该变化不影响正确性，但可能因 ng-set 更新后平衡点变化而放大正式扩展，只能作为性能实验，不能直接设为默认。

## 3. completion bound 不应关闭

completion bound 构造合计 81.336 秒，但同一次 exact 的多轮 DSSR 已经复用同一份 bound，后续轮日志中的 build 为 0；跨 exact 时 LP dual 已变化，不能直接复用旧 bound。当前 bound 在全 run 中剪掉约 67.34% 的前向已构造扩展和 79.56% 的后向已构造扩展。关闭或改成纯 scalar 会把成本转移为更多 label、dominance 和 join，已有实验也不支持这样做。

剩余可能有量级收益的方向是把 completion bound 的 forward/backward 两个独立传播并行化。它们当前各占约一半 build 时间，理论上可把 81 秒的顺序和降到两侧最大值附近。但 PWLF segment pool、统计字段和 calculator 内部状态目前不是线程隔离设计，属于较大重构；在双进程并行实验中还会争用 CPU。静态 penalty 几何缓存、数组复用等只剩常数级收益，不应先于并行可行性审计。

## 4. join、dominance 和候选池

group-envelope prefilter 本轮跳过约 8.46 亿个潜在 label pair，最终只尝试约 755 万 pair；join 仅占 exact 的 8.98%。visit-profile、group prefilter、直接 shifted-sum、source-aware dominance、单 word 位集和 top-C 哈希加有序集合都已经接入当前 no-SRI 主线。这里没有再发现旧 dominance graph 那类全历史 label 扫描，也没有 top-C 的线性 sequence 去重和反复全排序。

继续压 join 常数最多作用于约 26.7 秒，不是当前最高优先级。按 group envelope 替代真实 label join、full-domain join、partial dominance 和路径唯一 join 都有正确性或负面性能证据，不应重开。

## 5. master LP 与 strong branching

after-pricing LP 的 1186 次重解来自小批量加列后的必要 dual 更新；当前 `resolveCurrentModel()` 复用现有模型，不是每次重建。此前同 dual 批量和 heuristic non-best 扩列都未稳定减少总时间，因此这里没有新的低风险实现冗余。

strong lightweight trial 已把列缩到约 1--3 千条，480 次 trial RMP 仍花 43.004 秒。进一步减少 `strongBranchingCandidateLimit=20` 可以近似线性降低 trial 次数，但可能增加搜索树，属于参数 A/B，不是实现修复。strong phase2 已关闭，当前没有该层冗余。

## 6. 当前建议优先级

1. 先做 DSSR 后续轮 probe 复用 A/B，只针对上一轮完整 F/B 已平衡的情况，验证能否稳定回收约 18 秒未选候选开销。
2. 若要做较大改造，单独审计 completion-bound F/B 并行化的线程隔离成本；这是剩余唯一可能带来十秒级以上稳定收益的底层方向。
3. strong candidate 20/10 做完整树 A/B，观察节省 trial LP 后是否被节点增加抵消。
4. 暂不继续修改 join、dominance、PWLF 常数、same-dual batch、warm-start、non-best heuristic 或 completion-bound 语义。

当前结论是：no-SRI ng-DSSR 的主要底层组件已经接近优化完成，剩余瓶颈更多来自列生成尾部的多次 dual 更新，而不是单个明显低效函数。后续实验必须围绕调用次数和状态复用，不能再把已经有效的大剪枝组件关闭。
