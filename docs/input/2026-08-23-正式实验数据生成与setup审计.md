# 正式实验数据生成与 setup 审计

## 1. 当前生成边界

正式输入包位于 `experiment-suite/formal`。本次只生成数据、共享 seed/solve 任务清单和审计文件，不运行 ALNS、BPC、CPLEX 或 ArcFlow。任务规模为 `20/40/50/60/80/100`，每个规模固定选择5个任务集合。`n=20/40` 共用5个40-task父实例和同一任务排列；`n=60/80/100` 共用5个100-task父实例和同一任务排列，因此分别形成严格嵌套子集；`n=50` 使用5个原生50-task实例且保持源文件任务顺序。`n<=60` 使用机器数 `2/3/4`，`n>=80` 使用 `3/4/5`。

每个任务集合生成 random/family 两套setup以及base/medium/high三个落盘时间尺度。中等倍率在每个规模内从整数5--15中固定随机选择5个互异值，高倍率等于对应中等倍率加10。每个任务集合因此形成 `2*3*3=18` 个 `.dat`，30个任务集合共540个文件。W0/W100/W300不写成三份任务数据，而由manifest在读取同一个 `.dat` 时传入；放大尺度下窗口半宽同步乘以该文件的时间倍率。

## 2. 模块划分

数据生成没有写成一个混合循环。`FormalTaskSetGenerator`只负责父实例选择、固定排列和嵌套任务集合；`FormalDueWindowGenerator`只负责由Tanaka due date、抽取后的workload比例和参考机器数生成跨机器共享的窗口中心；`FormalSetupGenerator`只生成配对的random/family setup；`FormalTimeScaleGenerator`只生成冻结倍率并缩放所有时间量；`FormalInstanceWriter`只负责写最终 `.dat`。`FormalExperimentDataGenerator`负责按上述顺序组装这些组件并写metadata，`FormalExperimentSuiteGenerator`再基于已生成实例构造三份实验manifest。各组件不调用求解器，也不读取历史求解结果。

setup校验单独放在 `FormalSetupValidator` 和 `FormalSetupAuditRunner`。前者在生成过程中直接检查内存矩阵；后者在全部文件落盘后重新读取每个 `.dat`，不复用生成器中的矩阵，并输出 `instances/post-generation-setup-audit.tsv`。这样生成逻辑和最终文件审计具有明确边界。

## 3. Setup生成与检查

random和family的最终job-to-job平均setup都以 `0.5*p_bar` 为目标，单弧上限为 `floor(p_bar)`。family数随规模取 `3/3/4/4/5/6`；任务使用固定随机种子近似均衡地分组，类内目标均值为总体目标的0.4倍，类间目标均值通过有序任务对比例配平，使闭包前总体期望仍等于random场景。两类setup对同一有序弧共用一个随机分位数，从而减少两套实例之间无关的随机差异。

原始连续setup只允许真实任务作为Floyd中间点，虚拟点0只作为起点，不能参与闭包传播。闭包后random和family分别使用一个统一尺度校准到目标均值，再向上取整并截断到上限。最终检查包括：非负性、对角线和终止列为0、最大值不超过上限、平均值误差不超过 `max(0.5,1%)`、有向三角不等式零违例、第二次Floyd零改弧；family场景还要求最终类间均值严格大于类内均值。不同机器数副本除首行机器数外必须具有相同SHA-256正文哈希。

本次正式包复审结果为：540个文件、180个任务集/setup/尺度组全部通过；最大绝对均值误差为0.032894737；三角违例、第二次Floyd改弧、setup上限超出和family内外关系反转均为0。生成时审计位于 `instances/setup-audit.tsv`，重新读盘审计位于 `instances/post-generation-setup-audit.tsv`。

## 4. 输出与复现

`instances/task-selection.tsv`记录父文件、选择种子、排列种子、源任务编号和窗口中心；`instances/scale-selection.tsv`记录每个任务集合的倍率；`instances/setup-audit.tsv`记录setup生成参数和第一次/最终审计；`instances/instances.tsv`是全部540个数据文件的索引。包根目录的 `manifest.tsv`是三份子manifest的去重并集，共3330个共享seed任务和8190个正式求解任务，其中纯调度比较4860、外包性能3240、无折扣补充90。

重新生成使用：

```powershell
java -cp target/classes Common.FormalExperimentSuiteGenerator `
  --dataRoot=data `
  --outputRoot=experiment-suite/formal `
  --sizes=20,40,50,60,80,100 `
  --casesPerSize=5 `
  --timeLimitSeconds=10800 `
  --maxNodes=100000 `
  --discountModel=masterVariables
```

只重新复查已生成setup使用：

```powershell
java -cp target/classes Common.formal.FormalSetupAuditRunner experiment-suite/formal
```

生成与审计过程不启动任何求解，因此不会消耗正式算例的3小时时限。正式求解仍应通过各子manifest或根manifest交给 `ExperimentBatchScheduler` 执行。
