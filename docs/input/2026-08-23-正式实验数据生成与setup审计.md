# 正式实验数据生成与 setup 审计

## 1. 当前生成边界

正式输入包位于 `experiment-suite/formal`。本次只生成数据、共享 seed/solve 任务清单和审计文件，不运行 ALNS、BPC、CPLEX 或 ArcFlow。任务规模为 `20/40/50/60/80/100`，每个规模固定选择5个任务集合。`n=20/40` 共用5个40-task父实例和同一任务排列；`n=60/80/100` 共用5个100-task父实例和同一任务排列，因此分别形成严格嵌套子集；`n=50` 使用5个原生50-task实例且保持源文件任务顺序。`n<=60` 使用机器数 `2/3/4`，`n>=80` 使用 `3/4/5`。

每个任务集合生成 random/family 两套setup以及base/medium/high三个落盘时间尺度。中等倍率在每个规模内从整数5--15中固定随机选择5个互异值，高倍率等于对应中等倍率加10。每个任务集合因此形成 `2*3*3=18` 个 `.dat`，30个任务集合共540个文件。W0/W100/W300不写成三份任务数据，而由manifest在读取同一个 `.dat` 时传入；放大尺度下窗口半宽同步乘以该文件的时间倍率。

## 2. 模块划分

数据生成没有写成一个混合循环。`FormalTaskSetGenerator`只负责父实例选择、固定排列和嵌套任务集合；`FormalDueWindowGenerator`只负责由Tanaka due date、抽取后的workload比例和参考机器数生成跨机器共享的窗口中心；`FormalSetupGenerator`只生成配对的random/family setup；`FormalTimeScaleGenerator`只生成冻结倍率并缩放所有时间量；`FormalInstanceWriter`只负责写最终 `.dat`。`FormalExperimentDataGenerator`负责按上述顺序组装这些组件并写metadata，`FormalExperimentSuiteGenerator`再基于已生成实例构造三份实验manifest。各组件不调用求解器，也不读取历史求解结果。

setup校验单独放在 `FormalSetupValidator` 和 `FormalSetupAuditRunner`。前者在生成过程中直接检查内存矩阵；后者在全部文件落盘后重新读取每个 `.dat`，不复用生成器中的矩阵，并输出 `instances/post-generation-setup-audit.tsv`。这样生成逻辑和最终文件审计具有明确边界。

## 3. Setup生成与检查

random和family的最终job-to-job平均setup都以 `0.5*p_bar` 为目标，单弧上限为 `floor(p_bar)`。family数随规模取 `3/3/4/4/5/6`；任务使用固定随机种子近似均衡地分组，类内目标均值为总体目标的0.4倍，类间目标均值通过有序任务对比例配平，使闭包前总体期望仍等于random场景。两类setup对同一有序弧共用一个随机分位数，从而减少两套实例之间无关的随机差异。

原始连续setup只允许真实任务作为Floyd中间点，虚拟点0只作为起点，不能参与闭包传播。闭包后random和family分别使用一个统一尺度校准到目标均值，再向上取整并截断到上限。最终检查包括：非负性、对角线和终止列为0、最大值不超过上限、平均值误差不超过 `max(0.5,1%)`、有向三角不等式零违例、第二次Floyd零改弧；family场景还要求最终类间均值严格大于类内均值。不同机器数副本除首行机器数外必须具有相同SHA-256正文哈希。

本次正式包复审结果为：540个文件、180个任务集/setup/尺度组全部通过；最大绝对均值误差为0.032894737；三角违例、第二次Floyd改弧、setup上限超出和family内外关系反转均为0。生成时审计位于 `instances/setup-audit.tsv`，重新读盘审计位于 `instances/post-generation-setup-audit.tsv`。

## 4. 输出与复现

`instances/task-selection.tsv`记录父文件、选择种子、排列种子、源任务编号和窗口中心；`instances/scale-selection.tsv`记录每个任务集合的倍率；`instances/setup-audit.tsv`记录setup生成参数和第一次/最终审计；`instances/instances.tsv`是全部540个数据文件的索引。包根目录的 `manifest.tsv`是三份子manifest的去重并集，共3330个共享seed任务和8190个正式求解任务，其中纯调度比较4860、外包性能3240、无折扣补充90。

重新生成使用：

```powershell
java -cp target/classes Common.FormalExperimentSuiteGenerator `
  --dataRoot=data `
  --outputRoot=experiment-suite/formal `
  --sizes=20,40,50,60,80,100 `
  --casesPerSize=5 `
  --timeLimitSeconds=10800 `
  --maxNodes=100000 `
  --discountModel=masterVariables
```

只重新复查已生成setup使用：

```powershell
java -cp target/classes Common.formal.FormalSetupAuditRunner experiment-suite/formal
```

生成与审计过程不启动任何求解，因此不会消耗正式算例的3小时时限。正式求解仍应通过各子manifest或根manifest交给 `ExperimentBatchScheduler` 执行。

## 5. 生成结果复核

2026-08-23进一步按数据文件、实验场景和求解任务三个层次复核。物理输入共540个 `.dat`，即6个规模、每规模5个任务集合、2类setup、3档时间尺度和3个机器数。无外包实验在这些文件上再交叉3个窗口，形成1620个场景和4860个算法求解任务。外包性能实验不另造任务数据，只使用其中180个base尺度文件，交叉3个窗口和3档价格，形成1620个经济场景；两种外包表示共3240个求解任务。数量折扣实验再为n50增加90个中价无折扣任务。因此“有外包”总计3330个求解任务，但仍然复用同一批base `.dat`，不能把3330理解成3330个独立任务数据文件。

40、50和100任务Tanaka目录各有125个候选文件。生成器先按文件名排序，再分别用固定父规模种子打乱并无放回取前5个，不读取任务特征或求解结果。40-task选中 `024/069/018/012/039`，分别生成嵌套的n20/n40；50-task选中 `060/091/049/109/062`，保持原任务顺序；100-task选中 `037/012/031/057/095`，分别生成嵌套的n60/n80/n100。嵌套组对父实例任务再使用case级固定种子排列，较小规模取排列前缀。

setup的硬约束符合冻结口径。30个base任务集合中，random和family的最终均值相对 `0.5*p_bar` 的最大绝对误差均为0.001315789；全部540个缩放文件重新读盘后，最大绝对误差为0.032894737。最大setup未超过 `floor(p_bar)`，最终三角违例和二次Floyd改弧均为0，跨机器副本正文一致。

family结构则只部分达到原意。最终类间/类内均值比在每个规模的5例平均值依次为 `2.03/1.61/1.39/1.37/1.30/1.19`，对应n20/40/50/60/80/100；最小值为1.165，仍满足类间大于类内，但大规模下差异已经较弱。原因是连续Floyd把大量直接弧替换为多段最短路径，family场景闭包后均值只剩原始均值的约26%--62%，随后统一放大只能恢复总体均值，不能恢复原来的类内/类间比例。因此当前实现数学上正确，也与“先Floyd、后校准”的讨论一致，但若论文希望random/family在所有规模上都代表强弱明显的结构差异，现有检查条件 `betweenMean>withinMean` 过弱，正式长跑前应单独决定是否接受这种随规模衰减的family强度。

## 6. W、due-window中心与family setup的进一步说明

W不是求解器在内存中随机生成的参数，也不写成三份重复的任务文件。每个 `.dat` 只保存加工时间、due-window中心、早到/迟到权重和setup矩阵；manifest为每个求解场景固定写入 `dueWindowHalfWidth`。`FormalExperimentRunner`加载数据后，以文件中的中心 `c_j` 构造

\[
d_j^e=\max\{0,c_j-W\},\qquad d_j^l=c_j+W.
\]

base尺度使用 `W=0/100/300`，medium/high尺度使用 `W=g\times(0/100/300)`，其中时间倍率 `g` 已经固化在对应 `.dat` 中。这样同一任务、setup和时间尺度只保存一次，三个窗口场景仍由manifest完整确定，且三种算法读取完全相同的数据和W。

当前due-window中心也不是直接保留Tanaka源实例的due date。设抽取后任务总加工量与父实例总加工量之比为 `r`，参考机器数为 `m_ref`，其中 `n<=60` 取3、`n>=80` 取4，则当前生成规则为

\[
c_j=\left\lceil\frac{\operatorname{round}(d_j^{Tanaka}r)}{m_{ref}}\right\rceil.
\]

乘 `r` 是为了避免从父实例抽取较小任务子集后仍沿用原父实例的过晚due date；除以参考机器数是把单机时间轴转换到并行机背景。不同实际机器数 `m` 共用同一组中心，因此机器数变化只代表内部产能变化，不会同时改变交期。若改为原始due date原样保留，既会取消子集负荷校正，也会取消并行机时间轴压缩，实验含义将发生整体变化。

family setup当前的主要问题不是三角不等式或总体均值，而是Floyd最短路随着任务数增加而提供越来越多的跨family绕行路径。闭包前类间/类内目标均值比约为2.8--3.2，闭包后n100平均只剩1.19，因此继续提高闭包前类间均值不能稳定解决大规模结构衰减。

当前更合适的待确认方案是先生成并闭包一个配对的random基础有向度量 `D`，然后直接定义family矩阵

\[
s_{ij}^{F}=aD_{ij}+b\,\mathbf{1}\{f(i)\ne f(j)\},\qquad i,j\ge1,
\]

起点弧保持 `s_{0j}^{F}=aD_{0j}`，终止列仍为0。基础度量与family离散度量之和仍满足有向三角不等式，统一向上取整和上限截断也保持该性质，因此不需要再用Floyd破坏family结构。参数 `a,b` 可通过确定性校准同时满足最终总体均值约为 `0.5\bar p`、单弧上限为 `\lfloor\bar p\rfloor`，并把最终类间/类内均值比固定在例如2.0。random和family仍共用同一基础度量与总体均值，差异只来自family结构。该方案目前仅为分析结论，尚未修改生成器或重建正式数据；确认后还应把family验收条件从简单的 `betweenMean>withinMean` 改成围绕目标比例的数值容差。

2026-08-23又使用现有30个base任务集合做了不写文件的静态试算。试算直接使用每个任务集合已经闭包且满足三角不等式的random矩阵作为 `D`，目标总体均值仍取 `0.5\bar p`，目标类间/类内比取2.0，并在最终向上取整后用共同尺度修正总体均值。结果如下：

| n | 最终均值/`p_bar` | family比最小值 | family比平均值 | family比最大值 | setup触顶率 |
|---:|---:|---:|---:|---:|---:|
| 20 | 0.5000 | 1.953 | 1.964 | 1.973 | 0 |
| 40 | 0.5000 | 1.960 | 1.964 | 1.968 | 0 |
| 50 | 0.5001 | 1.961 | 1.966 | 1.972 | 0 |
| 60 | 0.4999 | 1.961 | 1.966 | 1.971 | 0 |
| 80 | 0.5000 | 1.960 | 1.966 | 1.970 | 0 |
| 100 | 0.5000 | 1.962 | 1.964 | 1.967 | 0 |

这说明目标比2.0在当前 `0.5\bar p` 均值和 `\bar p` 上限下具有充足余量，整数化后也不会随规模衰减。若确认修改，推荐只替换family生成分支：random生成和校准口径保持不变；family复用random闭包前的连续度量，按连续均值直接计算 `a,b`，再用一个共同尺度校准整数总体均值；验收要求改为总体均值容差、三角违例为0、二次Floyd改弧为0，并要求最终family比落在 `[1.9,2.1]`。不建议采用“继续增大闭包前类间均值”“只对family内部做Floyd”或“闭包后乘大跨family弧”的方案：前者仍随规模衰减，后两者不能稳定保证全局有向三角不等式。

random分支无需随之重写。现有30个base random矩阵的setup变异系数在各规模平均约为0.332--0.356，各规模最小/最大样本仍为0.320--0.389，且零setup比例为0，没有出现随任务规模明显同质化的问题。因此推荐保持random的截断正态、真实任务Floyd和总体均值校准，只让family从同一个已闭包基础度量派生。

为避免正式实现引入不必要的 `a,b` 双参数校准，优先方案进一步简化为固定换族setup。设已经生成并校准好的random整数度量为 `D`，直接令跨family弧临时增加 `Delta=0.5*p_bar`，类内弧不变，然后对整个family矩阵统一乘一个尺度，使最终job-to-job平均值重新等于 `0.5*p_bar`，最后向上取整并截断到 `floor(p_bar)`。即实现上只需要“复制random矩阵、跨族加固定值、整体归一化”三步。起点弧只参与整体缩放，不增加换族setup；生成后不再Floyd，只运行现有三角审计。

该简化方案在同一30组base任务集合上的最终均值比为0.4997--0.5002，类间/类内比总体为1.932--2.133，setup触顶率仍为0。它保留了前述度量和三角性质，但参数解释更直接：换family额外增加一笔等于random平均setup的准备时间；整体归一化保证random/family只比较结构而不比较总强度。因此后续实现应优先采用该固定 `Delta` 方案，family比只作为生成结果审计，建议验收范围放宽为 `[1.85,2.15]`，不再把精确命中2.0作为生成目标。

用户进一步提出family差异应达到约4--5倍，以保证结构在结果中清楚可见。对相同30组base任务集合补做固定换族setup试算：取 `Delta=1.5*p_bar` 时，最终类间/类内比为3.75--4.10；取 `Delta=2*p_bar` 时为4.64--5.10。两档最终总体均值仍约为 `0.5*p_bar`，零setup率和触顶率均为0。后者对应的最终类内均值约为 `0.12--0.14*p_bar`、类间均值约为 `0.57--0.67*p_bar`，属于清晰的强family结构，但总体setup强度没有提高。若论文实验希望random/family形成明确对照，当前更推荐固定 `Delta=2*p_bar`，并把生成验收范围设为约 `[4.5,5.2]`；该选择尚待确认，未修改生成器。

## 7. VRP度量数据的生成方式与三角不等式保证

进一步核对VRP benchmark的生成方式后可以确认，文献通常不是先逐弧独立生成距离再做Floyd闭包，而是先生成具有空间结构的客户坐标，再由坐标距离得到完整距离矩阵。Uchoa等（2017）的CVRP benchmark在 `[0,1000]^2` 网格中生成客户：R类把客户放在随机网格点；C类先随机选择3--8个cluster seeds，再按随距离指数衰减的概率把其他客户吸引到seed周围；RC类一半采用clustered生成、一半随机生成。Dabia、Lai和Vigo（2019）的外包VRP实验直接使用修改后的Solomon数据，并沿用R/C/RC三类地理分布，没有重新独立生成弧成本。这些构造的共同点是：random/clustered结构先作用于底层空间，距离矩阵随后由同一个度量规则计算，因此连续欧氏距离天然满足三角不等式。

该文献做法不能不加区分地直接复制。VRP精确算法常按TSPLIB规则把欧氏距离四舍五入到最近整数，但最近整数取整并不严格保持三角不等式。例如三个共线或近共线点的连续距离可能为 `sqrt(2), sqrt(2), sqrt(8)`，最近整数分别为1、1、3，得到 `3>1+1`。本问题使用整数时间且模型明确假设setup满足三角不等式，因此若采用坐标法，应定义

\[
s_{ij}=\left\lceil \gamma\lVert x_i-x_j\rVert_2\right\rceil,
\]

而不是四舍五入。向上取整保持三角不等式：若 `x<=y+z`，则 `ceil(x)<=ceil(y)+ceil(z)`。统一正比例缩放同样保持三角性质；对非负度量统一截断为 `min(C,s_ij)` 也保持三角性质。

当前提出的“基础有向度量加换族setup”同样不是依赖审计来保证正确，而是由构造本身保证。设random基础矩阵 `D` 已满足有向三角不等式，定义

\[
\delta_{ij}=\mathbf 1\{f(i)\ne f(j)\},\qquad
s^F_{ij}=\gamma\left(D_{ij}+\Delta\delta_{ij}\right).
\]

family指示距离本身满足 `delta_ij<=delta_ik+delta_kj`：若任务 `i` 和 `j` 属于不同family，中间任务 `k` 不可能同时与二者属于同一family。因此 `D+Delta*delta` 是两个度量的非负加权和，必然满足三角不等式；统一缩放、向上取整和统一上限截断后仍然成立。生成后的三角审计只是检查代码实现、整数化和文件写入是否符合这个数学构造，不是用“验证通过”替代三角性质的来源。也就是说，不再做第二次Floyd是有严格依据的，不是先随便生成再期待审计碰巧通过。

两种方案相比，完全照搬VRP的坐标法最容易引用和解释，但会得到对称setup，不能覆盖本文允许的有向序列相关setup；cluster半径、seed位置和中心距离也会新增一组几何参数。当前更适合本文的是保留已经满足三角不等式的有向random基础矩阵，再叠加family离散度量。它保留有向性，使random/family共享同一基础随机结构和总体均值，并能稳定控制类间/类内比。VRP文献在这里提供的是“先构造底层度量，再生成矩阵”的设计依据，而不是要求本文必须改用二维欧氏距离。

截至本节记录时，正式生成器仍使用原来的Floyd family分支；上述无Floyd family构造尚未落地，正式数据也没有据此重建。后续若实施，应以构造证明为正确性依据，并继续保留三角违例、二次Floyd改弧、均值和family比审计作为实现回归检查。

参考：Uchoa et al. (2017), *New benchmark instances for the Capacitated Vehicle Routing Problem*, https://doi.org/10.1016/j.ejor.2016.08.012；Dabia, Lai, and Vigo (2019), *An Exact Algorithm for a Rich Vehicle Routing Problem with Private Fleet and Common Carrier*, https://doi.org/10.1287/trsc.2018.0852。
