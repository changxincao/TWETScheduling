# 外包 TWET 调度论文整体框架与实验设计

## 1. 当前结论

当前更合适的论文主线不是单独证明 ng-DSSR 在纯调度 benchmark 上全面优于 time-indexed，而是研究带 due window、序列相关 setup 和聚合外包价格的并行机调度，并给出一套精确 branch-and-price 框架。ng-DSSR 应作为这套框架中面向连续时间和大时间尺度的内部列定价方法，而不是整篇论文唯一的研究问题。

这样定位有三个好处。第一，问题本身相对纯 TWET 调度发生了实质变化：任务去向、内部排序和聚合外包价格相互耦合。第二，当前代码已经实现了两种具有明确结构差异的外包建模方式，可以形成模型与算法层面的比较。第三，ng-DSSR 不再需要在所有实例上压过 time-indexed，只需要证明它消除了后者对离散时间范围的伪多项式依赖，并在相应实例区域内形成稳定优势。

这个定位也有明确边界。论文不能把“加入外包”本身当成充分创新，更不能只做参数实验。需要通过文献综述确认“并行机 TWET/due-window + 序列相关 setup + 聚合或数量折扣外包成本 + 精确列生成”这一组合是否已有直接研究，并明确现有工作缺少的是问题结构、分解方式还是精确算法。

## 2. 参考论文的真实做法

参考论文 `An Exact Algorithm for a Rich Vehicle Routing Problem with Private Fleet and Common Carrier` 研究私人车队与公共承运商联合决策。它不是只采用“VRP 列 + 外包列”一种形式，而是提出并比较两套 set-partitioning 模型。

SP1 同时使用私人路径列和公共承运商服务集合列。主问题中的两类列共同覆盖客户，因此需要分别求解私人路径定价和外包集合定价。外包定价本质上是在数量折扣运价下选择一个客户子集。该模型的根节点下界较强，但高 dual 客户可能同时出现在两类列中，容易产生对称性和退化，而且每轮列生成需要处理两个定价问题。

SP2 只把私人路径列化，客户是否交给公共承运商以及运价分段变量显式留在主问题中，因此每轮只需要私人路径定价。它的根节点下界略弱，但论文实验中整体更快、求解实例更多。论文的主要算法结论不是“列越多越强越好”，而是更强松弛、对称性、定价成本和分支结构之间存在权衡。

论文 25-customer 汇总结果也直接支持这一点：SP1 的平均 root LB 略高于 SP2，但平均时间约为 `158s` 对 `50s`，求得最优的实例数为 `124` 对 `131`。此外，作者实现过 ng-path relaxation 和 cover inequalities，但认为效果不理想，未纳入正式计算结果。这不能直接否定当前 TWET 的 ng-DSSR，因为问题、连续时间 PWLF 定价和算法目标都不同；它只说明论文中必须用当前问题上的机制实验建立 ng-DSSR 的适用边界，不能借用 VRP 文献替代实证。

当前 TWET 项目已经存在直接对应关系：

1. `outsourcingModel=columns` 对应 SP1 思路。内部机器序列和外包任务集合都是列，`OutsourcingPricingEngine` 求解外包子集定价，并使用 outsourcing membership 分支。
2. `outsourcingModel=masterVariables` 对应 SP2 思路。内部机器序列仍为列，单任务外包变量和 tariff segment 变量留在 RMP，并使用 tariff segment、机器数和 arc 分支。

因此，参考论文最值得借鉴的不是把 VRP 结构原样移植到调度，而是围绕同一外包决策构造两种分解，并通过实验解释“较强的双列族松弛为什么未必带来更快的完整求解”。

## 3. 建议的论文研究问题

论文可以围绕三个研究问题展开。

### RQ1：如何精确建模和求解带聚合外包价格的 due-window 并行机调度

任务可以安排到内部机器，也可以交给外部供应商。内部任务具有 due-window earliness/tardiness 成本、序列相关 setup time 和 setup cost；外包任务不进入内部序列，其成本由外包任务集合的累计 baseline 和分段价格函数决定。核心耦合是：任务去向改变内部机器负载和序列，外包任务之间又通过数量折扣或聚合价格相互影响。

### RQ2：显式外包变量和外包集合列哪一种分解更有效

两种模型表达同一整数问题，但 LP 松弛、对称性、每轮定价负担、分支对象和 repair 难度不同。论文应比较它们的完整求解表现，而不只比较根节点下界。

### RQ3：连续时间 ng-DSSR 定价在什么情况下优于 time-indexed 定价

time-indexed 方法在时间范围较小、整数时间图较紧时很强，而且可以自然接入图 fixing 和 SRI；其主要缺点是状态和弧数量随离散时间范围增长。ng-DSSR 不依赖逐时刻展开，理论优势是对时间数值尺度更稳定，但其 label、completion bound、DSSR 和 join 成本随任务规模和窗口宽度增长。论文应识别二者的适用区域，而不是提出“ng-DSSR 始终更快”的错误命题。

## 4. 建议的贡献表述

论文可以形成四项相互支撑、但边界清楚的贡献。

1. 提出带 due-window、序列相关 setup 和聚合外包价格的并行机调度问题，并说明其业务场景与现有 rejection、order acceptance 和简单逐任务外包成本模型的区别。
2. 给出两套精确分解：显式外包主变量模型和外包集合列模型，并设计与各自变量结构匹配的定价、分支和可行性修复流程。
3. 为内部机器列设计连续时间 ng-DSSR/PWLF 定价，结合 completion bound、source-aware dominance 和双向拼接，避免 time-indexed 方法对时间范围的线性扩张。
4. 通过计算实验给出模型选择、定价方法选择和外包策略的可解释结论。

其中第 3 项的合适表述是“horizon-robust continuous-time pricing”或“避免离散时间范围扩张”，而不是“全面优于 time-indexed”。现有结果已经表明，小时间范围和较紧窗口下 time-indexed 可能明显更快；时间范围放大后，time-indexed 的剩余时空弧和扫描量近似随范围增长，而 ng-DSSR 的增长更缓。这正好可以形成有边界的算法结论。

## 5. 算法框架

建议统一描述一套 branch-and-price 主框架，再分别替换两个维度。

第一个维度是外包分解：

1. Explicit outsourcing：内部机器列 + 显式任务外包变量 + tariff segment 变量。
2. Columnized outsourcing：内部机器列 + 外包任务集合列。

第二个维度是内部机器定价：

1. Time-indexed pricing：适用于整数时间和相对较小的 horizon，可结合时空弧 fixing 与 SRI。
2. Continuous-time ng-DSSR pricing：不逐时刻展开，最终通过 DSSR 恢复 elementary 列，适用于较大的时间范围。

不建议把这四种组合都作为同等重要的主算法。正文主算法可以采用整体表现最好的外包分解和 ng-DSSR 内部定价；另一种外包分解用于核心 formulation comparison；time-indexed 作为强基线和小时间区域的替代实现。若实验表明 explicit outsourcing 明显更优，最终算法就以 explicit + ng-DSSR 为主，columnized 作为模型比较对象。

## 6. 实验设计

### 6.1 正确性与小规模验证

先用小规模实例验证两种外包模型和两种内部定价的整数最优值一致，并与 compact MILP、ArcFlow 或可直接求解的小规模模型对照。至少报告最优目标、内部序列、外包集合和目标分解。该部分的目的不是比较速度，而是证明两种分解确实在求解同一个问题。

### 6.2 纯调度下的内部定价机制比较

该部分关闭外包，只比较 ng-DSSR 和 time-indexed，回答 RQ3。它是机制实验，不应包装成对外部 benchmark 的 state-of-the-art 比较。

建议分开控制三个因素：

1. 任务规模：例如 `n=40/50/60`，机器数使用 `m=2/3`。
2. due-window 宽度：使用窄、中、宽三个水平。宽度应相对实例时间尺度定义，避免固定 `W=100` 在不同尺度下代表不同紧度。
3. 纯时间尺度：取 `alpha=1/5/10`，压力测试可在附录加入 `20`。processing time、setup time、due-window 端点和 horizon 同比乘以 `alpha`，同时调整惩罚函数使 `f'_j(alpha t)=f_j(t)`，从而保持序列成本和最优解结构不变。这个实验才真正隔离 time-indexed 的数值尺度敏感性，不能让初始上界或成本同时发生无关变化。

比较指标包括：求解成功数、总时间、root 时间、root bound/gap、节点数、master LP 时间、exact pricing 次数与时间、图状态/弧数、label 与 join 数、列池大小、峰值内存，以及 time-indexed 生成列中的 elementary/non-elementary 比例。

正文只需要展示能说明 crossover 的代表性表和性能曲线。已有结果可以作为预实验依据，但正式实验必须使用固定代码版本、统一 runner、相同初始解/列和相同时间限制重跑。

### 6.3 两种外包分解的核心比较

这是整篇论文最重要的算法实验。固定相同的内部定价方法、初始上界和随机种子，比较 explicit outsourcing 与 columnized outsourcing。

除通用求解指标外，还应报告：

1. 根节点 LP bound 和列生成轮数。
2. 内部定价和外包定价各自的调用次数与耗时。
3. 内部列数、外包集合列数和正值列数。
4. tariff segment、机器数、arc 和 outsourcing membership 各类分支次数。
5. strong-branching repair 次数、Phase-I 成功率和长尾。
6. 相同客户/任务同时出现在内部列和外包列造成的退化迹象，例如 RMP 迭代数、列池增长和大量小 reduced-cost 列。

该实验应回答：双列族是否给出更强 root bound；额外强度能否抵消第二个 pricing、对称性和 membership branching 的成本；哪一种模型在不同外包比例下更适合。

### 6.4 关键算法组件消融

不需要把所有工程优化都写成 ablation。只保留能够对应论文方法贡献的组件：

1. ng-DSSR 的 source-aware dominance。
2. completion bound 及其 arc fixing。
3. time-indexed root preprocessing/hybrid seed 是否启用。
4. strong branching 与普通分支。

Tmid probe、位集内联、候选池维护和 PWLF 常数优化可以合并为实现说明或附录，不宜占据主实验表。SRI 可作为 time-indexed 强基线的一部分，单独报告 no-cut 与 SRI 的成本和收益；由于当前 no-SRI ng-DSSR 的 source-aware dominance 与 SRI 状态不兼容，不应为了形式对称强行把慢速 SRI 版本作为主算法。

### 6.5 外包机制与管理启示

至少需要一组实验说明外包结构本身带来了什么，而不只是让算法更复杂。建议研究三个因素：

1. 外包价格水平：便宜、平衡、昂贵，参数应校准到“几乎全外包”“内部外包并存”“几乎不外包”之间的可解释区域。
2. 外包价格结构：逐任务线性价格与聚合数量折扣价格。该比较可以直接证明聚合 tariff 建模的必要性。
3. 内部产能紧张程度：机器数或 workload-to-capacity ratio 的两至三个水平。

可报告外包任务比例、内部机器利用率、总成本及其内部 TWET/setup/外包分解、早到/窗内/迟到任务比例，以及不同任务被外包的规律。due-window 宽度也可进入这一部分，因为它既影响算法，也影响外包决策。

setup time 和 setup cost 暂时不需要做完整敏感性分析。正文给出一个有业务解释的基准生成规则，并在少量代表性实例上检查结论不依赖某个极端设定即可。只有在后续发现 setup 强度显著改变外包选择或两种定价方法的 crossover 时，才把它升级为正式实验因素。

## 7. 实例矩阵与计算预算

不要把所有因素做成完整笛卡尔积。建议拆成相互正交的实验块：

1. 定价尺度实验：无外包，只变 `n/m`、窗口相对宽度和时间尺度。
2. 外包分解实验：固定一至两个代表性时间尺度，只变外包模型、外包价格水平和折扣结构。
3. 管理实验：固定最佳算法，只变价格、产能和窗口宽度。
4. 消融实验：只在代表性的容易、中等、困难实例子集上执行。

随机 ALNS 会影响初始上界和列。正式对比应使用 common random numbers：同一实例、同一 seed、同一初始列。若成本允许，每个随机场景使用三个 seed；若完整 BPC 太贵，则主结果固定一个公开 seed，并在代表性子集上做多 seed 稳健性检查。

建议统一时间限制并同时报告未完成实例的最终 gap。只比较平均时间会偏向容易实例，应同时报告 solved count、shifted geometric mean、最终 gap 分布和性能剖面。

## 8. 论文结构

建议正文按以下顺序组织：

1. 引言：业务决策、现有研究缺口、贡献和主要发现。
2. 文献综述：TWET/due-window 调度、外包或 rejection/order acceptance、聚合价格、branch-and-price 与连续/离散时间定价。
3. 问题定义与两种分解模型。
4. 通用 branch-and-price 框架：RMP、分支、repair 和上界。
5. 定价算法：内部 time-indexed 基线、连续时间 ng-DSSR、外包集合定价及主要加速。
6. 计算实验：验证、定价 crossover、外包模型比较、消融和管理启示。
7. 结论：明确适用区域和仍未处理的扩展。

可考虑的题目方向为：

`Exact branch-and-price for parallel-machine due-window scheduling with aggregate outsourcing tariffs`

或：

`Horizon-robust branch-and-price for due-window scheduling with contract manufacturing`

如果实际场景是生产外协，应使用 subcontracting/contract manufacturing，而不是照搬参考论文的 common carrier 术语。参考论文提供的是分解思想，不代表当前调度问题也应解释成运输承运商。

## 9. 当前风险与下一步

当前最大的论文风险不是 ng-DSSR 在小时间实例上慢，而是问题创新边界和外包数据生成尚未系统验证。下一步应优先完成：

1. 系统文献检索，确认问题组合及两种分解相对现有 scheduling-with-outsourcing 文献的真实缺口。
2. 固定两种外包模型完全一致的整数成本口径，做小规模最优值交叉验证。
3. 设计外包参数校准程序，避免所有实例都退化为全外包或不外包。
4. 选定目标期刊后，按期刊风格决定算法细节与管理实验的篇幅。偏 COR/EJOR 时突出模型、精确算法和计算证据；偏运输或运营管理期刊时必须进一步强化业务场景和决策洞见。

本记录采用 OR-Writing 的“问题—方法—证据—边界”结构，并结合 research-proposal 写作规则，将研究问题、模型变量、算法贡献和验证证据一一对应。后续写引言前仍需建立正式 contribution ledger：每一项贡献必须对应一个明确文献缺口、正文位置、实验或定理证据以及不应超过的结论边界。
