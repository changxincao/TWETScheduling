# 第三机 JVM 原生崩溃诊断

## 1. 当前结论

第三机 `DESKTOP-AS7L732` 本次失败不是 Java 堆内存不足，也不是 `insertLabel()` 抛出的普通 Java 异常。JVM 在 C2 编译后的 Java 代码中发生 `EXCEPTION_ACCESS_VIOLATION`，并试图执行不可执行地址。结合该主机此前三份 `hs_err`，当前最合理的判断是：第三机存在 JVM、CPU、内存或 native 组件层面的不稳定，优先怀疑 i9-14900K 平台稳定性和偏旧的 JDK 21.0.7；现有证据不支持把问题归因于某一个 TWET Java 方法。

本次失败任务为 `pricing-n080-set04-m5-family-medium-wnarrow-f4-time_indexed_sri`，运行约 `12271.8s` 后退出码为 1。调度器按失败任务处理并继续后续任务，失败项本身没有可作为正式结果的完成输出。

## 2. 本次崩溃证据

崩溃文件为远端：

`D:\ccxWork\work1\experiments\20260928-balanced-n80-ti-5h\hs_err_pid4136.log`

关键信息如下：

1. Oracle JDK `21.0.7+8`；
2. `EXCEPTION_ACCESS_VIOLATION (0xc0000005)`；
3. 异常类型为 DEP execution violation，即 JVM 试图跳转到不可执行地址；
4. 当前 PC 位于 C2 编译的 `TimeIndexedGraphRank1CutPricingEngine$Rank1CutSolver.insertLabel(...)`；
5. JVM 状态正常，不在 safepoint；
6. G1 堆约使用 `2.50 GB / 4.28 GB`，最大堆约 `30.2 GB`，系统仍有约 `84 GB` 可用内存，不是 OOM；
7. `insertLabel()` 是普通 Java `ArrayList` 与 dominance 操作，不使用 `Unsafe`、FFM 或本地内存。常规数组或下标错误应形成 Java 异常，不应形成 DEP 原生崩溃。

因此，`insertLabel()` 只是本次出错时正在执行的位置，不等于根因位于该方法。

## 3. 同机历史交叉证据

第三机当前共发现四份 `hs_err_pid*.log`，都使用 JDK 21.0.7、i9-14900K 和微码 `0x133`：

1. 2026-09-14：C2 编译的 `HEU.Solution.merge3Segments` 中非法读；
2. 2026-09-16：解释执行的 `java.util.ArrayList.add` 中非法读；
3. 2026-09-22：解释执行的 `java.util.ArrayList.add` 中另一地址非法读；
4. 2026-09-30：C2 编译的 `insertLabel` 中 DEP 执行异常。

崩溃位置跨越项目方法、JDK 集合方法、解释器和 C2 编译代码，非法地址也不相同。这种分散模式与单一 Java 逻辑错误不符，更像底层状态被随机破坏。第一机使用 i9-12900 和 Oracle JDK 21.0.3，在对应目录中未发现 `hs_err`，同类算法和 CPLEX 负载可以持续运行，也进一步指向第三机特有的平台或运行时问题。

第三机最近 30 天未查到 WHEA 事件，但这不能排除 CPU/RAM 不稳定。用户态错误跳转、JIT 代码损坏或短暂计算错误并不一定产生可见 WHEA 记录。

## 4. 风险排序

当前按证据强弱排序：

1. 第三机 CPU/RAM/主板平台不稳定，尤其是 i9-14900K 已知的 13/14 代桌面处理器 Vmin Shift 风险；
2. JDK 21.0.7 的 JVM/JIT 缺陷。该版本已明显落后于当前 JDK 21 更新，后续版本包含多项 C2 crash 和 use-after-free 修复；
3. CPLEX 或其他 native DLL 破坏进程内存。当前没有崩溃帧直接落在 CPLEX 中，但不能仅凭栈完全排除；
4. `insertLabel()` 自身 Java 逻辑导致原生崩溃，现有证据最低。

第三机为 Dell OptiPlex Tower Plus 7020，当前 BIOS `1.23.1`；Dell 已发布更新的 `1.26.1`。微码 `0x133` 表明已有较新微码，但微码和 BIOS 主要防止继续进入不稳定工作点，不能保证逆转此前可能已经发生的硅退化。

## 5. 建议验证顺序

为避免同时改变多个因素，建议按以下顺序做隔离验证：

1. 保留四份 `hs_err`，不针对 `insertLabel()` 打业务补丁；
2. 在独立目录、相同 JAR、相同配置和相同 seed 下，仅把失败任务改用最新 JDK 21 更新版复跑，旧正式批次和旧 JDK 不覆盖；
3. 若新版 JDK 仍在不同位置随机原生崩溃，平台或 native 内存破坏的概率显著上升；
4. 当前批次结束并取得用户明确许可后，升级 Dell BIOS，确认 Intel Default Settings，再运行 Dell 预启动诊断、MemTest86 和 CPU 稳定性测试；
5. 若最新 JDK、最新 BIOS 和默认功耗电压下仍复现，应按硬件不稳定处理，考虑 CPU/RAM 交叉替换或保修；
6. `-XX:TieredStopAtLevel=1` 或定向排除 `insertLabel` C2 编译只能作为诊断。由于历史崩溃还发生在解释执行的 `ArrayList.add`，即使关闭 C2 后不再复现，也不能单独证明项目代码有错或硬件无问题。

当前不修改正式算法代码，也不把此次失败解释成 TI+SRI 算法错误。完成结果仍按原有目标值、可行性与一致性校验使用；失败任务必须重跑，不能纳入正式统计。
