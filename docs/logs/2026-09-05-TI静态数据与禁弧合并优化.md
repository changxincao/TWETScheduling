# TI静态数据与禁弧合并优化

2026-09-05。本次只消除前次审查确认的三处重复计算，不修改定价集合、dominance、证书、分支策略或正式配置。没有更新远端，也没有启动完整树性能实验。

1. Node禁弧增量按(from,to)批量合并。原forbidden存储使用BitSet.or；allowed-complement存储在原horizon内使用andNot，原horizon之外的新增禁弧仍保存为overlay。计数采用合并前后cardinality差，保持long累计、重复合并幂等和父子节点隔离。小域扁平输入的解码仍保留原流程，不能把分段后端的收益推广到所有入口。补集初次构造仍采用原方法，避免稀疏允许尾部持有不必要的大位集容量。

2. TI arc-fixing复用所属pricing engine的静态penaltyByJobTime和durationByArc。PC、Tree及临时root预处理的三个主线调用点均已接入；原静态入口保留作兼容回退。当前dual产生的reduced cost、分支兼容性、graphWindow和F/B距离仍按调用重新计算。共享罚值包含更宽时间范围，但每次转移仍检查当前有效窗口，不会恢复已删除的状态。缓存不跨Data对象、不引入全局缓存。

3. TI+SRI同一次pricing调用中，启发式未返回列后转exact，复用只读窗口、弧reduced cost、禁弧lookup、cut scope/memory和packed masks。exact仍新建labels、buckets、候选池、计数及证书状态，packed scratch独立分配；不继承启发式labels，不跳过exact闭合。不跨LP/dual更新缓存。

## 验证

TWETBPC全包javac编译通过，仅保留已有deprecated提示。以下七项测试全部通过：TimeIndexedGraphOptimizationTest、TimeIndexedReuseTest、AfterCutPhaseOneRepairTest、BestBpcProfilesTest、NgDssrMidpointProbePolicyTest、NgDssrMinimumRepeatedSegmentUpdateTest、NgDssrJoinExtensionBoundaryTest。

新增禁弧测试以逐点更新为独立对照，覆盖40组四轮、63/64/127/130边界、稀疏和稠密初始集合、扁平和分段输入、原horizon之外增量、缩小horizon、重复更新和父子复制。新增缓存测试对比静态重建与缓存fixing的禁弧、窗口及计数，并确认静态罚值未被修改。rank-1测试覆盖packed开关、Phase-I开关及两组dual，共8组；复用与重建的exact证书、返回序列和成本一致，同时检查scratch未共享，并验证公开price入口的fallback。

## 局部计时

微测试脚本位于test-results/redundancy-after/ArcMergeBenchmark.java；同一脚本分别加载修改前后classes。41×41个任务对，原horizon=2000，分段增量定义域horizon=1300000，每个任务对加入0..2050，约345万位。输入生成不计时，预热2次、计时5次，并检查最终禁弧计数一致。

修改前五次为23.492、22.5714、21.6452、21.3098、21.9197ms，中位数21.9197ms；修改后为0.539、0.5297、0.3649、0.3175、0.3004ms，中位数0.3649ms。该局部合并约快60倍，但不代表fixing或整棵树快60倍。静态数据和rank-1复用尚无独立整体求解加速比例；目前证据是重复构造已消除且回归等价。
