## 2026-09-11当前版本复核

针对n40 family Cluster结果中TI+SRI pricing爆炸的问题，再次检查当前源码和正式profile。Algorithms 1--6对应的一元/三元`1/2` rank-1 cut、arc limited memory、同base memory union、前后向residual、join补偿、cut-aware dominance、inactive删除和2% tailing-off仍保持原实现，相关源码无未提交改动。重新运行上述七项回归，全部通过。

本次爆炸不能据此解释为cut公式或接线错误，但也不能称完整BCP与论文逐项相同。当前仍使用忽略active-SRI contribution的安全松弛arc fixing，而论文Algorithm 7使用SRI-aware fixing；当前active-SRI流程不使用论文的automatic dual smoothing；当前额外限制最多8轮、每个任务最多参与20个base cut；exact bucket逐项扫描而非按reduced cost排序。当前每轮50个一元和75个三元cut上限、inactive删除及tailing-off与论文一致。上述差异中，较弱fixing、缺少active-SRI smoothing和bucket扫描方式都可能放大大量cut下的pricing时间，但尚无隔离A/B能把本轮爆炸归因于某一项。

## Cut数量与后续方案

当前每轮最多50条一元和75条三元cut，与论文一致；`maxSubsetRowCutsPerNode`默认无限，但正式profile额外设置`maxCutRounds=8`和每个任务最多参与20个base cut，因此最多新增base的总体口径反而比只依赖inactive删除与2% tailing-off的论文流程更保守。当前慢例出现约120--176条active cuts，不能据此判断当前比论文加入更多；论文没有报告可直接配对的逐节点active-cut数量。

若后续优化，不应先换一种更高阶non-robust cut，而应先改cut选择与生命周期。最小风险方案是保留一元/三元rank-1定义，只减少同时active的低收益cut：按normalized violation、与现有cut的相似性、影响的正值列范围和预估pricing footprint选择小而多样的batch；对连续多轮dual接近0、长期松弛的cut做aging，并允许以后重新分离；必要时只在根部或浅层使用较大cut batch。family数据还可避免同一family连续加入大量高度局部的scope。以上均不改变有效不等式或exact pricing证书，但会在bound强化和pricing状态数之间重新取舍，必须按最终时间而非root bound单独A/B。

若要求不增加pricing residual维数，则需要robust、可加到arc reduced cost上的不等式。当前尚未找到能够等价替代SRI重叠覆盖作用的通用robust cut；Cluster branching能处理family aggregate分数性且不增加pricing状态，是当前已验证的更实际替代，但它不是cut，也不能消除全部族内SRI结构。

当前配置没有active-cut总数硬上限。`maxSubsetRowCutsPerNode`默认是`Integer.MAX_VALUE`；实际保护只有每轮最多50个一元和75个三元、最多8轮、每个任务最多参与20个active base，以及零dual inactive删除。因此120--176条cut同时active符合当前逻辑。历史50-3放大时间实验中，active cuts为`0--20/21--50/51--100/>100`时，平均单次rank-1 pricing约为`3.21/3.47/7.75/14.07s`，显示约64条以后pricing成本已明显非线性增长。若继续A/B，最直接的方案是在新增base前设置active-base cap，首个候选值可取64；达到上限后仍允许同base memory union和inactive删除，不再新增scope。该限制只削弱LP，不影响exactness，但是否降低总时间仍需与节点增量一起评价。
