# ALNS 初始上界稳定性与效率审计

## 1. 当前结论

当前初始上界的波动不应只归因于 Cmax。ALNS 虽然在 runner 中重置了随机种子，但默认同时使用 60 秒墙钟上限，因此机器负载、JIT 和并行实验会改变 60 秒内实际完成的迭代数。随机流起点相同不等于执行到同一个随机位置，最终 best 仍可能不同。严格比较 time-indexed 与 ng-DSSR 时，应固定并复用同一个 incumbent/初始列，或者另做固定迭代预算的 seed-only 对照，不能把两次独立 ALNS 的上界差异算到 pricing 算法上。

代码审计还发现一个明确的 ALNS 搜索逻辑错误：删除比例初始为 0.05--0.20，连续无改进后本应逐步放大；但当前只有在 `curRemoveRatioU * (1 + increaseRate) >= maxRemRatio` 时才更新。初始状态下 `0.2 * 2.5 = 0.5 < 0.6`，条件不成立，因此删除比例不会从 0.20 放大到 0.50，后续检查仍然重复同一结果。实际搜索长期停留在小扰动，`remRatioChangeN` 也不会增长。这会增加陷入初始局部最优的概率，并放大有限时间内的上界差异。

当前默认关闭模拟退火，只接受不劣于 current 的候选；三个 removal 和三个 insertion 算子均匀随机选择，没有基于历史收益调整权重。因此当前实现更准确地说是随机 ruin-and-recreate + VND，而不是具有算子权重学习的完整 ALNS。该设计本身不影响可行性，但在删除比例自适应失效后，搜索多样性更弱。

## 2. 已确认的计算热点

每轮 ALNS 都先复制 current。`Solution.copy()` 深拷贝序列、成本和累计时长数组，但一维和高维 PWLF 缓存主要共享引用，因此复制不是最重部分。随后 `tmpSol.calCost()` 会逐机重建 forward/backward 一维函数，以清除 VND 局部上界截断留下的成本口径；进入 `EngineVND` 后，又逐机调用 `updateInformationM()`，除一维函数外还重建二维片段函数、累计时长和硬窗口摘要。两次处理服务于不同语义，目前不能直接删掉，但它们使单轮代价较重，也使 60 秒墙钟能完成的迭代数对机器负载敏感。

repair 算子中有三处明确的实现低效，但优先级低于删除比例错误和实验可复现性：

1. `RegretKInsertion(2)` 为每个待插任务创建全部插入位置列表并完整排序，实际只需要最优和次优两个位置。可以用两个固定槽位单次扫描，严格保持现有 tie-break。
2. `RandomizedInsertion(4)` 同样收集并排序全部位置，但只从前四个选择；可以维护固定大小 top-4。
3. `RandomRemoval` 每删除一个任务都重新扫描全部机器并重建候选列表；可以一次性展平当前任务并无放回抽样。`ShawRemoval` 的静态任务距离也可预计算，并用布尔数组代替 `removed.contains()`。

这些优化主要提高单位时间内的迭代数，不保证直接改善最终上界。由于默认停止条件含墙钟，任何常数优化都会改变随机流实际推进位置，所以应先增加 ALNS 级统计，再做固定 seed/固定迭代数 A/B。

## 3. 建议的验证顺序

第一步只增加低开销统计：停止原因、完成迭代数、best 更新次数和时间点、各 removal/insertion 被选次数与改进次数、最终删除比例。这样可以确定同一个 seed 的上界波动究竟来自迭代数差异，还是算子轨迹本身发生变化。

第二步单独修正删除比例放大条件，用固定迭代数、固定 seed 对比当前版本和修正版。成功标准不是单个算例更好，而是多个 50/60 规模算例上 best 的中位数不退化、差 seed 尾部改善，并确认删除比例确实按 0.20 -> 0.50 -> 0.60 变化。

第三步才优化 regret/randomized insertion 的 top-k 维护。必须逐次对拍所选 job、machine、position 和 delta，保证 tie-break 与当前排序严格一致，再比较每 100 次 ALNS 迭代耗时。Random/Shaw removal 的小优化放在其后。

算子自适应权重、模拟退火和更复杂的接受策略会改变搜索语义，当前没有证据支持直接启用，不应与上述实现修复混在同一次实验中。
