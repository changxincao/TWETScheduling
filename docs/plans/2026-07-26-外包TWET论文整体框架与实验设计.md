# 外包 TWET 调度论文整体框架与实验设计

## 1. 当前结论

当前更合适的论文主线不是单独证明 ng-DSSR 在纯调度 benchmark 上全面优于 time-indexed，而是研究带 due window、序列相关 setup 和聚合外包价格的并行机调度，并给出一套精确 branch-and-price 框架。ng-DSSR 应作为这套框架中面向连续时间和大时间尺度的内部列定价方法，而不是整篇论文唯一的研究问题。

这样定位有三个好处。第一，问题本身相对纯 TWET 调度发生了实质变化：任务去向、内部排序和聚合外包价格相互耦合。第二，当前代码已经实现了两种具有明确结构差异的外包建模方式，可以形成模型与算法层面的比较。第三，ng-DSSR 不再需要在所有实例上压过 time-indexed，只需要证明它消除了后者对离散时间范围的伪多项式依赖，并在相应实例区域内形成稳定优势。

这个定位也有明确边界。论文不能把“加入外包”本身当成充分创新，更不能只做参数实验。需要通过文献综述确认“并行机 TWET/due-window + 序列相关 setup + 聚合或数量折扣外包成本 + 精确列生成”这一组合是否已有直接研究，并明确现有工作缺少的是问题结构、分解方式还是精确算法。

## 2. 参考论文的真实做法

参考论文 `An Exact Algorithm for a Rich Vehicle Routing Problem with Private Fleet and Common Carrier` 研究私人车队与公共承运商联合决策。它不是只采用“VRP 列 + 外包列”一种形式，而是提出并比较两套 set-partitioning 模型。

SP1 同时使用私人路径列和公共承运商服务集合列。主问题中的两类列共同覆盖客户，因此需要分别求解私人路径定价和外包集合定价。外包定价本质上是在数量折扣运价下选择一个客户子集。该模型的根节点下界较强，但高 dual 客户可能同时出现在两类列中，容易产生对称性和退化，而且每轮列生成需要处理两个定价问题。

SP2 只把私人路径列化，客户是否交给公共承运商以及运价分段变量显式留在主问题中，因此每轮只需要私人路径定价。它的根节点下界略弱，但论文实验中整体更快、求解实例更多。论文的主要算法结论不是“列越多越强越好”，而是更强松弛、对称性、定价成本和分支结构之间存在权衡。

论文 25-customer 汇总结果也直接支持这一点：SP1 的平均 root LB 略高于 SP2，但平均时间约为 `158s` 对 `50s`，求得最优的实例数为 `124` 对 `131`。此外，作者实现过 ng-path relaxation 和 cover inequalities，但认为效果不理想，未纳入正式计算结果。这不能直接否定当前 TWET 的 ng-DSSR，因为问题、连续时间 PWLF 定价和算法目标都不同；它只说明论文中必须用当前问题上的机制实验建立 ng-DSSR 的适用边界，不能借用 VRP 文献替代实证。

当前 TWET 项目已经存在直接对应关系：

1. `outsourcingModel=columns` 对应 SP1 思路。内部机器序列和外包任务集合都是列，`OutsourcingPricingEngine` 求解外包子集定价，并使用 outsourcing membership 分支。
2. `outsourcingModel=masterVariables` 对应 SP2 思路。内部机器序列仍为列，单任务外包变量和 tariff segment 变量留在 RMP，并使用 tariff segment、机器数和 arc 分支。

因此，参考论文最值得借鉴的不是把 VRP 结构原样移植到调度，而是围绕同一外包决策构造两种分解，并通过实验解释“较强的双列族松弛为什么未必带来更快的完整求解”。

## 3. 建议的论文研究问题

论文可以围绕三个研究问题展开。

### RQ1：如何精确建模和求解带聚合外包价格的 due-window 并行机调度

任务可以安排到内部机器，也可以交给外部供应商。内部任务具有 due-window earliness/tardiness 成本、序列相关 setup time 和 setup cost；外包任务不进入内部序列，其成本由外包任务集合的累计 baseline 和分段价格函数决定。核心耦合是：任务去向改变内部机器负载和序列，外包任务之间又通过数量折扣或聚合价格相互影响。

### RQ2：显式外包变量和外包集合列哪一种分解更有效

两种模型表达同一整数问题，但 LP 松弛、对称性、每轮定价负担、分支对象和 repair 难度不同。论文应比较它们的完整求解表现，而不只比较根节点下界。

### RQ3：连续时间 ng-DSSR 定价在什么情况下优于 time-indexed 定价

time-indexed 方法在时间范围较小、整数时间图较紧时很强，而且可以自然接入图 fixing 和 SRI；其主要缺点是状态和弧数量随离散时间范围增长。ng-DSSR 不依赖逐时刻展开，理论优势是对时间数值尺度更稳定，但其 label、completion bound、DSSR 和 join 成本随任务规模和窗口宽度增长。论文应识别二者的适用区域，而不是提出“ng-DSSR 始终更快”的错误命题。

## 4. 建议的贡献表述

论文可以形成四项相互支撑、但边界清楚的贡献。

1. 提出带 due-window、序列相关 setup 和聚合外包价格的并行机调度问题，并说明其业务场景与现有 rejection、order acceptance 和简单逐任务外包成本模型的区别。
2. 给出两套精确分解：显式外包主变量模型和外包集合列模型，并设计与各自变量结构匹配的定价、分支和可行性修复流程。
3. 为内部机器列设计连续时间 ng-DSSR/PWLF 定价，结合 completion bound、source-aware dominance 和双向拼接，避免 time-indexed 方法对时间范围的线性扩张。
4. 通过计算实验给出模型选择、定价方法选择和外包策略的可解释结论。

其中第 3 项的合适表述是“horizon-robust continuous-time pricing”或“避免离散时间范围扩张”，而不是“全面优于 time-indexed”。现有结果已经表明，小时间范围和较紧窗口下 time-indexed 可能明显更快；时间范围放大后，time-indexed 的剩余时空弧和扫描量近似随范围增长，而 ng-DSSR 的增长更缓。这正好可以形成有边界的算法结论。

## 5. 算法框架

建议统一描述一套 branch-and-price 主框架，再分别替换两个维度。

第一个维度是外包分解：

1. Explicit outsourcing：内部机器列 + 显式任务外包变量 + tariff segment 变量。
2. Columnized outsourcing：内部机器列 + 外包任务集合列。

第二个维度是内部机器定价：

1. Time-indexed pricing：适用于整数时间和相对较小的 horizon，可结合时空弧 fixing 与 SRI。
2. Continuous-time ng-DSSR pricing：不逐时刻展开，最终通过 DSSR 恢复 elementary 列，适用于较大的时间范围。

不建议把这四种组合都作为同等重要的主算法。正文主算法可以采用整体表现最好的外包分解和 ng-DSSR 内部定价；另一种外包分解用于核心 formulation comparison；time-indexed 作为强基线和小时间区域的替代实现。若实验表明 explicit outsourcing 明显更优，最终算法就以 explicit + ng-DSSR 为主，columnized 作为模型比较对象。

## 6. 实验设计

### 6.1 正确性与小规模验证

先用小规模实例验证两种外包模型和两种内部定价的整数最优值一致，并与 compact MILP、ArcFlow 或可直接求解的小规模模型对照。至少报告最优目标、内部序列、外包集合和目标分解。该部分的目的不是比较速度，而是证明两种分解确实在求解同一个问题。

### 6.2 纯调度下的内部定价机制比较

该部分关闭外包，只比较 ng-DSSR 和 time-indexed，回答 RQ3。它是机制实验，不应包装成对外部 benchmark 的 state-of-the-art 比较。

建议分开控制三个因素：

1. 任务规模：例如 `n=40/50/60`，机器数使用 `m=2/3`。
2. due-window 宽度：使用窄、中、宽三个水平。宽度应相对实例时间尺度定义，避免固定 `W=100` 在不同尺度下代表不同紧度。
3. 纯时间尺度：取 `alpha=1/5/10`，压力测试可在附录加入 `20`。processing time、setup time、due-window 端点和 horizon 同比乘以 `alpha`，同时调整惩罚函数使 `f'_j(alpha t)=f_j(t)`，从而保持序列成本和最优解结构不变。这个实验才真正隔离 time-indexed 的数值尺度敏感性，不能让初始上界或成本同时发生无关变化。

比较指标包括：求解成功数、总时间、root 时间、root bound/gap、节点数、master LP 时间、exact pricing 次数与时间、图状态/弧数、label 与 join 数、列池大小、峰值内存，以及 time-indexed 生成列中的 elementary/non-elementary 比例。

正文只需要展示能说明 crossover 的代表性表和性能曲线。已有结果可以作为预实验依据，但正式实验必须使用固定代码版本、统一 runner、相同初始解/列和相同时间限制重跑。

### 6.3 两种外包分解的核心比较

这是整篇论文最重要的算法实验。固定相同的内部定价方法、初始上界和随机种子，比较 explicit outsourcing 与 columnized outsourcing。

除通用求解指标外，还应报告：

1. 根节点 LP bound 和列生成轮数。
2. 内部定价和外包定价各自的调用次数与耗时。
3. 内部列数、外包集合列数和正值列数。
4. tariff segment、机器数、arc 和 outsourcing membership 各类分支次数。
5. strong-branching repair 次数、Phase-I 成功率和长尾。
6. 相同客户/任务同时出现在内部列和外包列造成的退化迹象，例如 RMP 迭代数、列池增长和大量小 reduced-cost 列。

该实验应回答：双列族是否给出更强 root bound；额外强度能否抵消第二个 pricing、对称性和 membership branching 的成本；哪一种模型在不同外包比例下更适合。

### 6.4 外包机制与灵敏度分析

参考论文的管理分析主要改变三类因素：车辆固定成本、是否允许外包、是否提供数量折扣；同时比较随机、聚类和混合客户分布，说明同一个价格变化会因业务结构不同而产生不同结果。当前调度问题没有车辆固定成本，不应机械照搬。更合适的对应关系如下。

1. **是否允许外包。** 比较 no-outsourcing 与 outsourcing，回答外包是否真正降低总成本、缓解内部拥挤，以及它怎样改变内部机器序列。该组是外包价值基线，不需要设置很多水平。
2. **外包价格水平。** 对 baseline outsourcing cost 使用低、中、高三个乘数。参数先通过小规模预实验校准，使三个水平分别接近“外包较多”“内外部并存”“外包较少”，避免结果退化为全外包或完全不外包。
3. **数量折扣强度。** 固定 tariff breakpoint 相对总 baseline 的位置，比较无折扣、中等折扣和强折扣。无折扣使用第一段单位价格贯穿全域；中等和强折扣只改变后续分段斜率。正文不需要同时穷举 breakpoint、段数和每段斜率，否则无法解释是哪一个因素产生影响。
4. **内部产能紧张程度。** 使用机器数或 workload-to-capacity ratio 的两至三个水平，替代参考论文的车辆固定成本实验。它回答内部资源越紧张时，企业是否更依赖外包，以及数量折扣是否会放大这种转移。
5. **due-window 拥挤结构。** 除窗口宽度外，区分窗口中心分散、中心聚集和混合三类实例。在总工作量和窗口宽度近似相同的条件下，中心聚集表示大量任务争夺同一时间段，最接近参考论文中 clustered customers 的作用。应重点观察“折扣强度 × 窗口聚集程度”的交互：聚集实例中，外包一组任务可能同时缓解内部拥挤，因此数量折扣更可能触发成组外包；分散实例中，折扣可能只改变成本而很少改变任务去向。

due-window 宽度已经用于 ng-DSSR/time-indexed 的算法比较，但在本节可以复用同一批最优解做管理解释，不需要再生成一套重复实验。任务规模 `n` 和机器数 `m` 首先是计算难度因素，其中机器数只有在解释内部产能时才作为管理变量。

可报告外包任务比例、机器利用率、总成本及其内部 TWET/setup/外包分解、早到/窗内/迟到任务比例、外包任务的 due-window 位置和 processing workload。建议增加两个结构性指标：外包前后内部最大时间拥挤度，以及被外包任务是否集中在同一 due-window cluster。这样才能产生比“外包越便宜，外包越多”更有价值的结论。

earliness/tardiness 权重比例可以作为备选灵敏度，因为拖期惩罚较高时外包可能主要用于避免迟到；但它不是参考论文的核心参数，也容易扩大实验规模。只有当基准结果显示外包任务明显集中在迟到侧时，再增加 `w_T/w_E` 的低、中、高三档。setup time 和 setup cost 暂时不做完整灵敏度分析，只给出一个有业务解释的基准生成规则。

## 7. 实例矩阵与计算预算

不要把所有因素做成完整笛卡尔积。建议拆成相互正交的实验块：

1. 定价尺度实验：无外包，只变 `n/m`、窗口相对宽度和时间尺度。
2. 外包分解实验：固定一至两个代表性时间尺度，只变外包模型、外包价格水平和折扣结构。
3. 灵敏度实验：固定最佳算法，分块研究外包价格与折扣，以及产能与 due-window 拥挤结构；不做四个因素的完整笛卡尔积。

随机 ALNS 会影响初始上界和列。正式对比应使用 common random numbers：同一实例、同一 seed、同一初始列。若成本允许，每个随机场景使用三个 seed；若完整 BPC 太贵，则主结果固定一个公开 seed，并在代表性子集上做多 seed 稳健性检查。

建议统一时间限制并同时报告未完成实例的最终 gap。只比较平均时间会偏向容易实例，应同时报告 solved count、shifted geometric mean、最终 gap 分布和性能剖面。

## 8. 论文结构

建议正文按以下顺序组织：

1. 引言：业务决策、现有研究缺口、贡献和主要发现。
2. 文献综述：TWET/due-window 调度、外包或 rejection/order acceptance、聚合价格、branch-and-price 与连续/离散时间定价。
3. 问题定义与两种分解模型。
4. 通用 branch-and-price 框架：RMP、分支、repair 和上界。
5. 定价算法：内部 time-indexed 基线、连续时间 ng-DSSR、外包集合定价及主要加速。
6. 计算实验：验证、定价 crossover、外包模型比较和外包灵敏度分析。
7. 结论：明确适用区域和仍未处理的扩展。

可考虑的题目方向为：

`Exact branch-and-price for parallel-machine due-window scheduling with aggregate outsourcing tariffs`

或：

`Horizon-robust branch-and-price for due-window scheduling with contract manufacturing`

如果实际场景是生产外协，应使用 subcontracting/contract manufacturing，而不是照搬参考论文的 common carrier 术语。参考论文提供的是分解思想，不代表当前调度问题也应解释成运输承运商。

## 9. 当前风险与下一步

当前最大的论文风险不是 ng-DSSR 在小时间实例上慢，而是问题创新边界和外包数据生成尚未系统验证。下一步应优先完成：

1. 系统文献检索，确认问题组合及两种分解相对现有 scheduling-with-outsourcing 文献的真实缺口。
2. 固定两种外包模型完全一致的整数成本口径，做小规模最优值交叉验证。
3. 设计外包参数校准程序，避免所有实例都退化为全外包或不外包。
4. 选定目标期刊后，按期刊风格决定算法细节与管理实验的篇幅。偏 COR/EJOR 时突出模型、精确算法和计算证据；偏运输或运营管理期刊时必须进一步强化业务场景和决策洞见。

本记录采用 OR-Writing 的“问题—方法—证据—边界”结构，并结合 research-proposal 写作规则，将研究问题、模型变量、算法贡献和验证证据一一对应。后续写引言前仍需建立正式 contribution ledger：每一项贡献必须对应一个明确文献缺口、正文位置、实验或定理证据以及不应超过的结论边界。

## 10. 当前阶段决策

截至 2026-07-26，算法主线已经确定，短期不再围绕论文实验继续增加新的定价、占优、分支或修复变体。当前应先保持已有 branch-and-price、ng-DSSR/time-indexed 内部定价和两种外包建模路径稳定，并完成外包问题口径与小规模正确性对齐。

前述灵敏度因素只是后续可选实验方向，不代表已经确定最终实验矩阵。外包价格、折扣、产能和 due-window 结构如何取值，以及算例如何生成，统一留到下一阶段单独设计。届时先根据问题叙事和基准数据确定可解释的参数口径，再做少量预实验校准，避免现在反向根据求解表现调整问题数据。

## 11. 可执行的正式实验矩阵

### 11.1 基础算例面板

正式数据继续以当前 Tanaka 派生数据为基础。算法对照使用 `n=40/50/60` 和
`m=2/3`，其中 60 个任务作为正文中的最大规模，不再为了显示规模而扩到当前算法
基本无法稳定闭合的 100 个任务。40 和 50 个任务直接使用现有 125 组源数据；60 个
任务从同编号的 100-job 源实例中用固定种子抽取 60 个任务，并按抽取前后总
processing workload 的比例缩放 due-date center，避免直接截断后 due date 相对
过晚。

每个规模先选 5 个基础实例。选择不能参考求解时间或 gap，而应按源实例的归一化
due-date center 和 spread 分层后确定，使紧、中、松的原始时间结构均被覆盖。正式
生成后冻结实例清单和随机种子。每个源实例只生成一份 setup 矩阵，并在 `m=2/3`
之间复用；机器数只改变 due-date center 的并行机缩放和机器容量，不能同时改变
setup 随机数。setup time 的闭包后平均值固定为平均 processing time 的 0.5 倍，
并满足有向三角不等式。setup cost 固定使用当前实验口径
`kappa_ij=20*s_ij`，本论文不再对 setup 强度做完整灵敏度分析。

### 11.2 小规模正确性验证

从基础数据中确定性抽取 `n=8/10/12` 的子实例，取 `m=2/3`、每个组合 5 个实例，
共 30 个小规模问题。对每个问题比较 compact exact model、SC-M 和 SC-C，并分别
用 ng-DSSR 与 time-indexed 内部定价。该组只检查最优目标、内部序列、外包集合和
成本分解是否一致，不用于宣称速度优势。

### 11.3 ng-DSSR 与 time-indexed 的纯调度比较

该部分关闭外包，使用 `n=40/50/60`、`m=2/3` 和每格 5 个基础实例，共 30 个基础
问题。窗口宽度不再直接写固定的 `W=100/300`，而使用实例平均 processing time
`p_bar` 定义 half-width：

1. 窄窗口：`h=0`；
2. 中等窗口：`h=2*p_bar`；
3. 宽窗口：`h=6*p_bar`。

这三个水平在当前数据上大致对应历史使用的 `W=0/100/300`，但能随实例 processing
尺度变化。时间尺度实验固定中等窗口，使用 `alpha=1/5/10`。对
`p_j`、`s_ij`、due-window 两端和 horizon 同比乘以 `alpha`，setup cost 和
TWET penalty 也按相同比例变化，使所有固定序列的目标值整体同比缩放，且不加入
jitter。窗口实验在 `alpha=1` 下有 3 个变体；尺度实验只补充
`alpha=5/10` 两个变体，因此每个基础问题共 5 个而不是 9 个变体。

正式主比较使用同一 no-cut branch-and-price 框架，仅替换 ng-DSSR 和 time-indexed
内部 exact pricing，总计 150 个派生实例、300 次求解。time-indexed+SRI 是更强但
机制不同的基线，只在 `alpha=1`、中等窗口、`n=40/50` 的代表性子集上报告，不能
混入纯定价 crossover 的主统计。

### 11.4 两种外包分解的比较

该部分使用 `n=40/50`、`m=2/3`、每格 5 个基础实例，共 20 个基础问题；60 个任务
暂不进入外包 formulation comparison，避免第二个外包列族的长尾掩盖模型差异。
内部定价统一使用前一部分确定的主配置。

定义任务的原始外包成本为 `b_j=rho*p_j`。令
`B_all=sum_j b_j`，tariff breakpoints 固定在 `0.25B_all` 和 `0.50B_all`。先在独立 pilot
实例上校准一个全局中等单位价格 `rho*`，使中位实例出现内部与外包并存；校准后对
所有正式实例固定，不允许逐实例调价。价格水平取
`0.8rho* / rho* / 1.2rho*`。折扣斜率相对首段分别为：

1. 无折扣：`(1.00,1.00,1.00)`；
2. 中等折扣：`(1.00,0.85,0.70)`；
3. 强折扣：`(1.00,0.70,0.45)`。

SC-M/SC-C 核心比较不跑完整 `3x3`，只取四个有明确作用的制度：
高价无折扣、中价无折扣、中价强折扣、低价中等折扣。这样得到 80 个外包实例，
两种 formulation 共 160 次正式求解。

### 11.5 外包管理灵敏度

灵敏度只使用最终表现更好的 formulation 和内部定价方法。为控制预算，价格与折扣
的完整 `3x3` 交互固定在 `n=40,m=2` 的 5 个基础实例上，共 45 次求解。机器容量
效应只在中价、中等折扣下比较 `m=2/3`；due-window 拥挤效应只比较原始 center
结构与聚集结构，不再增加第三种人工分布。

聚集结构保持每个任务的窗口宽度不变，只把 due-window center 向若干固定分位点
收缩。建议使用两个 cluster center，并令新 center 为原 center 与最近 cluster
center 的加权平均，聚集权重固定为 0.75。cluster center、权重和任务归属只由原始
due dates 决定，不能根据外包结果调整。

### 11.6 公平性和报告口径

同一派生实例的所有算法必须使用同一个预先保存的 ALNS incumbent、初始列、随机
种子和列成本。正式 wall-clock 比较在空闲机器上顺序运行，每次 CPLEX 使用一个
线程；并行启动只用于开发阶段监测，不能作为论文时间。建议统一 7200 秒时限，
预处理计入总时间并单独报告。

主指标为 solved count、总时间、root 时间与 gap、最终未解 gap、节点数、master
LP 时间、heuristic/exact pricing 时间及次数、强分支 trial 时间、列池峰值和内存。
外包比较另外报告外包比例、内部 TWET/setup 成本、外包成本、两类列数、外包定价
时间和各类分支次数。时间统计同时给 solved-instance shifted geometric mean，
不能只报算术平均。

## 12. Dabia et al. 外包 VRP 论文的实验配置与结论

参考论文使用 Liu and Shen (1999) 修改后的 Solomon 异构车队带时间窗算例。客户数
分别为 25、50 和 100，每个规模 168 个实例，共 504 个。实例分为 R、C、RC 三类
空间结构及 type 1/type 2 两类时间窗，其中 R 为随机分布、C 为聚类分布、RC 为
混合分布，type 1 时间窗较紧，type 2 时间窗较宽且每条路径通常服务更多客户。
车型数量随 Solomon 类别变化：R1、C1、RC1、R2、C2、RC2 分别有 5、3、4、4、4、6
种车型；每种车型在 Dabia et al. 的实验中最多可用 3 辆。每个原问题另有 a/b/c 三档
车辆固定成本，分别对应高、中、低固定成本；a/b/c 是同一车型集合的成本档位，不是三种
车型。

公共承运商按总外包数量采用四段数量折扣。断点统一为 200、400 和 600，但三类
空间结构使用不同单价：R 为 5.00/4.50/4.00/3.50，RC 为
3.50/3.00/2.50/2.00，C 为 2.00/1.50/1.00/0.50。论文据此表达随机分散客户的
承运成本高于聚类客户。算法由 Java 实现，master LP 使用 Gurobi 6.5.1，运行平台
为 2.8 GHz Intel Core i7，统一时限 1 小时；初始上界为外包全部订单，同时最多
保留 50 条 active generalized subset-row inequalities。

论文首先只在 25-customer 实例上比较两种 formulation。SP1 同时把私人车路径和
公共承运商客户子集列化，需要两个 pricing problems；SP2 只列化私人车路径，把
外包决策和 tariff 留在 master 中。两者均开启 cuts 和 strong dominance。SP1
的平均 root LB 为 676、平均树规模为 4.2，强于 SP2 的 673 和 6.5；但 SP1 平均
时间为 158 秒、求得 124 个最优解，而 SP2 为 50 秒、求得 131 个。结论是 SP1
松弛更强，但双列族定价和外包子集的对称性抵消了下界优势，SP2 整体更高效。

第二组实验在全部规模上比较 SP2 是否加入 generalized subset-row inequalities，
两边都使用 strong dominance。25-customer 下，无 cuts/有 cuts 分别为
111/76 秒、127/131 个最优解、root LB 663.4/666.2、平均节点 55/31；50-customer
下分别为 387/193 秒、85/92 个、1201.6/1205.8、174/104；100-customer 下分别为
361/238 秒、47/49 个、2142.5/2144.7、11/8。论文据此认为 cuts 能稳定提高 root
bound、缩小分支树并把平均时间降低三分之一以上。

第三组实验比较 pricing dominance。SP2 加 cuts 时，weak dominance 求得 127 个
最优解、平均 149 秒；strong dominance 求得 131 个、平均 49 秒。strong
dominance 整体约只需三分之一时间，但少数实例会因额外 dominance 计算开销而变慢。

管理分析没有做完整全因子灵敏度，而是选择代表实例讨论三件事。第一，车辆固定成本
升高时，随机分散实例的方案变化较小，因为行驶成本占主导；聚类实例可能改为把整个
客户簇外包。第二，与禁止外包相比，允许外包会把偏远或时间窗不方便的客户交给承运商，
使私人车路径更紧凑、交叉更少。第三，数量折扣实验把单价固定为最高档，即 R=5.00、
RC=3.50、C=2.00，和原四段折扣比较；折扣对随机实例结构影响较小，对聚类实例影响
明显，更容易促成整簇外包。

完整算法最终在 504 个实例中证明 272 个最优，其中 25-customer 的求解率超过 80%。
该实验设计真正支持的结论是：master 中显式外包的 SP2 虽然 LP 稍弱，但比双列族 SP1
更实用；subset-row cuts 和 strong dominance 是主要算法改进；外包和折扣的结构效应
依赖客户聚集程度。论文没有系统改变所有 tariff 参数，也没有证明这些管理结论对全部
实例都成立，其管理部分本质上是代表算例分析。

| 实验 | 算例与对照 | 主要结果 | 论文得到的结论 |
| --- | --- | --- | --- |
| SP1 与 SP2 | 仅 25-customer；两者均使用 cuts 和 strong dominance | SP1/SP2：root LB 676/673，平均树 4.2/6.5，时间 158/50 秒，最优数 124/131 | 双列族 SP1 松弛略强，但外包 pricing 的成本和对称性更大；显式外包的 SP2 总体更高效 |

## 13. Setup 结构、外包成本与 setup cost 的文献口径

VRP 中 R/C/RC 客户分布首先改变的是客户间行驶弧。调度中最接近的对应物不是
due-window 宽度，而是 product/job family 造成的 setup 弧结构。Sourd (2005) 的
earliness-tardiness setup 模型把任务分到若干 machine states/product groups，同组
任务之间 setup time/cost 为零，跨组 setup 由两个 group-level 矩阵给出；文中明确
指出 setup 考虑会推动同族任务成组加工，而 distinct due dates 又会推动任务按交期
分散，两者存在结构冲突。该文实验使用 `q=2/3/4` 个 group，并分别生成 short
`U[10,20]` 和 long `U[100,200]` 的 setup time/cost 矩阵；上下界比例保证两个矩阵
各自满足三角不等式。family setup 文献也普遍用“同族切换可忽略、跨族发生 major
setup”表达产品聚类。

如果需要把 VRP 的空间结构类比到调度，当前论文可以定义两类 setup 结构，但不能把
它们说成调度文献已有的 R/C 标准分类：

1. `R-like`：使用当前 job-level 随机有向三角 setup metric。
2. `C-like`：把任务分到 `q` 个 product families，同族 setup 很小或为零，跨族
   使用 family-level 有向三角 metric。

两类矩阵在生成后应统一归一化到相同的
`mean setup / mean processing`，从而只比较结构，不把“聚类”与“setup 更大”混在
一起。参考 VRP 论文中的 RC 没有揭示独立于聚类程度的新机制，主要是 R 与 C 之间的
过渡。因此当前正式实验不设置 RC；如果后续需要展示连续的聚类强度，再用 random
metric 与 family metric 的非负线性组合构造 RC-like 补充实例。setup 结构与
due-window center 聚集也不是同一件事：前者改变换型弧，后者改变时间拥挤。

外包调度文献没有唯一的成本生成规则。Lee and Sung (2008) 独立生成
`p_j~U[1,10]` 和 `o_j~U[1,30]`；Safarzadeh and Kianfar (2019) 也从独立均匀分布
生成 operation outsourcing cost，再通过预实验选择 objective weights，使实例分别
出现低、中、高外包率。另一些 rejection/outsourcing 模型直接假设外包成本与加工
时间成比例，或对同一机器采用固定的 outsourcing-cost/processing-time ratio。

当前模型中的 `b_j` 是任务 `j` 单独外包时的原始货币成本，
`B(O)=sum_{j in O}b_j` 是外包集合的原始总外包成本，折扣后的实际支付才是
`G(B(O))`。因此实验中可以使用可控的比例生成规则
`b_j=rho*p_j`。模型本身仍允许任意异质的 `b_j`，论文的问题定义不需要假设它与
加工时间成比例；比例关系只是正式算例的生成规则，用来清楚控制外包与内部调度之间
的权衡。若需要补充随机性，可使用 `b_j=rho*p_j*xi_j` 且令 `xi_j` 在 1 附近小幅
波动，但不作为主实验。

令 `B_all=sum_j b_j`，tariff breakpoint 使用 `0.25B_all` 和 `0.50B_all`，而不是
使用 processing workload 作为 `G` 的输入。无折扣时 `G(B)=B`；有折扣时只降低后续
分段的边际支付率。价格水平由 `rho` 控制，并在独立 pilot 集上校准一个全局
`rho*`，正式实例统一使用 `0.8rho* / rho* / 1.2rho*`，不能逐实例调价。

setup cost 与 setup time 在业务上可以成比例，也可以分离。如果 setup 成本主要是
机器占用和人工时间，`kappa_ij=lambda_ij*s_ij` 合理。`lambda_ij` 可以固定为统一
单位时间费率，也可以在一个窄区间内按弧生成，以表示不同换型组合的人工、材料或
能源费率。任意变化的 `lambda_ij` 不保证 setup cost 仍满足三角不等式，但当前问题
只要求 setup time 满足三角不等式，算法也已经按一般 setup cost 处理。
如果还包含清洗材料、能源、报废、刀具磨损或外部技术人员费用，两者不必成比例。
Sourd (2005) 就把 setup time 和 setup cost 作为两个独立的 group-level 矩阵分别
生成。当前论文不把 setup cost/time 关系作为灵敏度因素，只需要固定一种可解释的
比例生成规则，并在全部正式实例中保持不变。

## 14. 精简后的正式实验主线

Dabia et al. 只说明 tariff 按“客户位置越随机分散，公共承运商收费越高”的原则设置，
没有解释断点为何恰好取 200/400/600，也没有给出费率的市场数据、估计过程或校准实验。
因此这些参数只能作为该文的情景设定，当前论文不直接照搬其绝对数值，而是按
`B_all` 的比例设置断点，并用独立 pilot 集校准统一的价格尺度。

当前论文不再比较 SRI、dominance 或固定成本。SRI 和 dominance 是求解器内部组件，
不是本文需要单独验证的研究问题；调度模型也没有与车辆固定成本对应的自然决策参数。
最终实验围绕以下四部分组织。

1. **基础实例面板。** 使用两类 setup 结构，即随机 job-level setup 和
   family-clustered setup；每类再设置窄、中、宽三类 due window。不同结构下保持
   processing workload、平均 setup 强度和 due-window 宽度口径可比。RC-like 不进入
   正式面板。
2. **内部定价算法比较。** 在关闭外包的同一基础面板上比较 ng-DSSR 与 time-indexed；
   时间尺度放大实验作为单独区块，用于说明两种方法随 horizon 增长的扩展性差异，
   不与全部 setup/window 因素做完整笛卡尔积。
3. **外包建模方式比较。** 在代表性的规模、setup 结构和 due-window 水平上比较
   master 显式外包与外包集合列化。该部分回答 formulation 选择问题，不重复比较
   SRI、dominance 等内部开关。
4. **外包价格与数量折扣。** 模型允许任意 `b_j`，正式算例使用
   `b_j=rho*p_j`。价格效应在无折扣下比较低、中、高三个 `rho`；折扣效应固定
   `rho=rho*`，比较无折扣、中等折扣和强折扣。两组分别进行，不跑完整 `3x3`。

“是否允许外包”暂不作为独立实验因素。关闭外包的纯调度最优解已经由内部定价比较
得到，后续可以直接把同一实例的外包解与该结果配对，报告成本下降、被外包任务比例、
内部 TWET/setup 成本变化以及内部序列结构变化。只有当这些配对结果出现稳定且可解释
的规律时，才把它提升为正文管理结论；否则只作为基础结果报告。

## 15. 2026-08-19 按论文小节重新收口的实验设计

### 15.1 纯调度算法比较

纯调度部分应比较 compact CPLEX 模型和三套固定 BPC：ng-DSSR、time-indexed no-cut、
time-indexed rank-1/SRI。四种方法使用同一实例、时间限制和单线程；BPC 复用同一初始列
快照，compact 模型在可接入时使用同一 incumbent 作为 MIP start。CPLEX 不只用于小规模
正确性验证，也可进入主表；对无法闭合的实例报告 10800 秒时的最终 gap，而不能只在其
能求最优的小实例上比较时间。

基础面板使用 `n=40/50/60`、`m=2/3`，每个 `(n,m)` 分层选 5 个源 case。原始时间尺度
下比较 `h=0/2p_bar/6p_bar` 三种窗口。纯时间尺度扩展只固定中等窗口，在代表性的
`n=40/50` 面板补 `alpha=5/10`；该区块的核心是 ng-DSSR 与 no-cut time-indexed，
CPLEX 和 SRI 是否扩到大时间尺度由原始尺度结果和计算预算决定。这样既能给出四种精确
方法的完整基准，也不会让所有算法、窗口、时间尺度和规模形成没有解释价值的全因子。

### 15.2 两种外包 formulation 的统一性能面板

外包性能比较固定内部机器定价为 ng-DSSR，比较 `columns` 与 `masterVariables`。使用
`n=40/50`、`m=2/3`、每格 5 个源 case、中等 due window 和原始时间尺度，共 20 个基础
问题。两种 formulation 不只在一个任意外包价格下比较，而是在五个共同经济情景上全部
求解：低/中/高价格且无折扣，以及中等价格下的中等/强折扣；中价无折扣是两组实验的
共同基准。总计为 `20*5*2=200` 次 formulation 求解。

该设计模仿 Dabia et al. 用同一批数据比较 SP1/SP2，但进一步检查 formulation 排名是否
随外包比例和折扣改变。两种 formulation 必须使用同一底层可行方案、内部列和成本；
`columns` 额外接入与该方案等价的外包集合列，`masterVariables` 接入对应显式外包变量。
除通用求解时间、root bound、gap 和节点外，还应分别报告内部/外包 pricing 时间、两类
列数、RMP 迭代、repair、分支类型和列池增长。后续经济分析直接复用这 200 次结果中
表现更好 formulation 的解，不再重复求解同一情景。

### 15.3 外包成本与分段函数

模型中的 `b_j` 解释为任务的未折扣外包货币成本，正式数据使用 `b_j=rho*p_j`。这种
比例规则使任务工作量与基础外包报价相关，同时模型本身仍允许任意异质 `b_j`。主实验
不再叠加独立随机噪声，避免价格效应被额外异质性混淆。价格尺度不能逐实例调节：从不
进入正式样本的 pilot case 上搜索一个全局 `rho*`，要求中等价格、无折扣时大多数实例
出现内外部并存；随后冻结低/中/高三档。初始可用 `0.8rho* / rho* / 1.2rho*`，若 pilot
显示仍退化为全外包或不外包，只能在 pilot 上统一调整档距，正式样本不能再改。

令 `B(O)=sum_{j in O}b_j`，`B_all=sum_j b_j`，采用连续的 incremental rate discount，
而不是达到阈值后追溯降低全部既有金额的 all-units discount。设置
`W1=0.25B_all`、`W2=0.50B_all`，三档边际费率为：无折扣 `(1,1,1)`，中等折扣
`(1,0.85,0.70)`，强折扣 `(1,0.70,0.45)`。因此第三段的实际支付为
`G(B)=W1+q2(W2-W1)+q3(B-W2)`。该函数连续、非递减且凹，直接对应 Lu、Zhang 和 Ou
所称的 incremental rate-based discount，也与当前 PWLF 外包成本结构相容。Dabia et al.
的 200/400/600 和 R/RC/C 绝对费率没有经验校准依据，只用于其运输情景，当前不照搬。

### 15.4 外包管理分析与可复用结果

正式管理分析做两个主问题。第一，把统一校准的中价无折扣外包解与纯调度解配对，分析
允许外包的价值；第二，在相同中等基础费率下比较无/中/强折扣。两部分均由 formulation
面板和纯调度面板直接提供，不新增求解。低/高基础费率若保留，只作为代表子集的稳健性，
不单列管理分析。指标不能只报外包任务数，还应包括外包 workload 比例、`B/B_all`、
折扣节省 `B-G(B)`、总成本及内部 TWET/setup/外包分解、早到/窗内/迟到比例，以及被
外包任务的 processing time、惩罚权重和对 setup 序列的影响。折扣分析还应检查解是否
集中在断点附近，识别是否出现由折扣触发的成组外包。

due-window 是当前问题的核心，建议用最终更好的 formulation 在中价、中等折扣下补充
窄/中/宽窗口比较；中等窗口已在 formulation 面板求解，因此只新增窄、宽两档，共
`20*2=40` 次。机器数 `m=2/3` 已在同一面板中，可直接用于分析内部产能变化，无需另建
实验。价格与折扣默认不做完整 `3*3`；只有五种骨干情景显示明显交互而无法解释时，
才在 `n=40,m=2` 的代表子集上补小型交互面板。family-clustered setup 可作为解释
“整族外包”的补充机制实验，但不是当前必做的 setup 灵敏度，也不能与所有因素全交叉。

管理分析应借鉴 Dabia、Lai 和 Vigo (2019) 的写法，不只报告“外包越便宜、外包越多”，
而要解释外包怎样改变内部方案的结构。允许外包可能优先移除 due window 与其他任务冲突、
或会产生较大 setup time/setup cost 的任务，使剩余内部任务形成更连贯的机器序列，并降低
内部 TWET 或 setup 成本。这个机制在较紧 due window 下尤其值得检查。正式结果应比较同一
实例有无外包时的内部序列、早到/窗内/迟到构成、关键 setup 弧和时间拥挤，而不能只报告
外包任务数量。上述内容是待由最优解验证的机制假设，不能在实验前写成已经成立的结论。

数量折扣分析也应区分“降低既有外包支付”和“真正改变任务去向”。参考论文中，折扣对
随机分散客户的外包集合和私人路线影响很小，代表实例只多外包一个小需求客户；对聚类
客户则会明显改变路线并触发整簇外包。这表明折扣效果取决于是否存在可成组外包的共同
结构。映射到当前调度问题，这种结构可以是相近的 due-window center、同一 job family、
共同造成某一时段产能拥挤，或一起移出后能显著减少 setup/迟到的一组任务。因此应检查：
外包量是否在折扣断点附近跳跃；新增外包是零散任务还是结构相关的一组任务；折扣是否只
降低原外包集合的成本，还是改变了内外部分配；内部序列是否因此更连贯、拥挤程度是否下降。

参考论文还分析了车辆固定成本，但当前调度问题没有机器启用固定成本，也没有自然且独立的
对应决策参数。正式管理分析不复制该实验，也不再把 `m=2/3` 包装成车辆固定成本的替代
灵敏度；机器数只保留为实例规模与内部产能背景，用于必要的分组解释。

从参考论文借鉴实验时应保持边界。SP1/SP2 的同数据公平比较、允许/禁止外包的方案配对和
有无数量折扣的结构比较可以直接借鉴；车辆固定成本不进入当前正式实验。其
cuts/strong-dominance 对照属于算法组件实验，当前论文不设相应消融；R/C/RC 的
空间分布也不直接复制，而以 due-window 的时间拥挤结构作为问题内对应因素。参考论文还让
R/RC/C 同时使用不同外包费率，因此空间结构与价格效应并未完全分离；当前实验必须对同一
结构面板使用统一校准后的价格档位，分别识别价格、折扣和任务结构效应。

补充检索调度与外包文献后，正式管理分析进一步收口为两项：允许/禁止外包，以及固定基础
费率下的数量折扣变化。文献中还常见外包基础价格或预算、拖期惩罚、承包商产能和外包
提前期；其中承包商产能与提前期会改变当前模型，拖期权重会改变 TWET 目标口径，均不新增
为正式灵敏度。基础外包价格是唯一可保留的稳健性候选：先在独立 pilot 上校准统一中价，
如需回应价格任意性，只在代表子集补低/中/高费率，而不单设第三个管理分析小节。正式结果
的 insight 主要来自两项实验内部的任务选择、序列变化、成本分解和折扣断点行为。

文献给出的数据口径支持上述选择。Lee and Sung (2008) 独立生成 outsourcing cost 并
比较多个成本区间，说明外包价格水平本身应单独变化；Safarzadeh and Kianfar (2019)
扩展经典调度实例，并用独立预实验选择使外包率呈低、中、高水平的参数，支持当前全局
pilot 校准；Lu、Zhang 和 Ou (2021) 区分 dollar-based、all-units rate 和 incremental
rate 四类折扣，支持选择连续 incremental 方案；Dabia、Lai 和 Vigo (2019) 则支持在
同一实例与费率面板上比较两种分解，再从代表性最优方案讨论外包和折扣结构。

### 15.5 现有外包与调度研究的灵敏度因素及结论边界

现有文献需要区分两类实验。第一类改变外包价格、延期代价或折扣，研究最优方案如何变化，
属于管理灵敏度；第二类改变任务数、机器数、交期紧度、setup 或整数时间尺度，主要研究
算法难度，不能直接解释为管理规律。同一参数对最优方案和求解难度的影响还可能方向不同，
因此正式论文应分别报告决策指标与计算指标。

| 文献中常见因素 | 已有主要结论 | 对当前研究的含义 |
|---|---|---|
| 外包基础价格或外包成本权重 | 价格下降通常提高外包比例并降低内部负荷；价格上升则保留更多内部任务。Safarzadeh and Kianfar (2019) 还发现，当最优解中的外包率较高时，其 MILP/CP 实例通常更容易求解；真正困难的往往是内外部方案竞争接近的混合区间。 | 中价应通过独立 pilot 校准到“内外部并存”，低/高价只作必要的稳健性，不应把全外包或零外包的退化情景作为主要结论。 |
| 外包预算、容量或数量上下限 | 扩大预算或容量扩大了可外包集合，但并不保证外包量等比例增加；最优使用量仍取决于延期/setup 节省能否覆盖外包成本。Lee and Sung (2008) 改变预算、成本和 lead time，主要报告启发式质量随参数变化，并没有形成可直接迁移的普遍管理定律。 | 当前模型没有承包商容量和 lead time，不应为了增加灵敏度而引入新约束。 |
| 延期惩罚与外包惩罚的相对水平 | 延期惩罚上升会在内部产能拥挤后推动更多外包，使延期成本趋于稳定；外包惩罚上升则抑制外包并把压力留在内部系统。Chen et al. (2023) 的 order-acceptance 实验也显示，提高拒绝代价会接受更多订单，同时增加生产、运输和延期成本。 | 当前可在“允许/禁止外包”结果中解释 TWET 与外包支付的替代关系，但不单独改变 TWET 权重，以免改变论文的基础目标口径。 |
| 数量折扣及断点 | 折扣不只降低支付，还可能改变任务集合。Dabia et al. (2019) 发现，随机分散客户中折扣对外包集合影响很小；聚类客户中折扣会触发成组外包并显著改变内部路线。Lu et al. (2020, 2021) 则从算法和复杂性角度系统区分多种数量/金额折扣。 | 这是当前最有价值的正式灵敏度。应检查断点跳跃、成组外包以及内部序列是否改变，而不能只比较目标值。 |
| 外包 lead time 与承包商能力 | lead time 越长，外包对交期的缓解作用越弱，甚至使外包任务自身迟到；承包商容量越紧，外包从“任务删除”变成需要单独排程的第二生产系统。 | 两者都会改变当前外包语义和 pricing 结构，只能列为模型扩展，不进入本轮实验。 |
| 交期紧度和交期分散度 | 运营上，交期更紧通常提高迟到与外包压力；计算上并不单调。Lee and Sung (2008) 的启发式在中等 tardiness factor 上误差更大，Sen and Bulbul (2015) 则发现“平均交期较松且分布较宽”的实例对其松弛算法更困难。 | due-window 宽度既是问题特征，也是算法比较因素。正文应报告其对外包结构和三种定价方法运行时间的双重影响，不能预设宽窗一定更容易。 |
| 任务数、机器数与负荷 | 任务数增加通常显著加难。增加机器会降低单位机器负荷，很多分解方法因子问题变小而更快；但机器对称性也可能增加等价解，所以求解难度仍依赖模型。Chen et al. (2023) 的 LBBD 在相同任务数下通常随工厂数增加而变快。 | `n` 和 `m` 是规模/产能分组，不作为管理灵敏度。需分别报告最优数、时间、gap、root 和节点，避免只报平均时间。 |
| setup 大小与时间尺度 | setup 增大强化序列依赖并显著增加求解难度。Bulhoes et al. (2020) 的 BCP 中，小 setup 仅 11 个实例未解，而较大 setup 有 101 个未解。时间索引模型的规模还随 horizon 伪多项式增长，处理/setup 时间整体放大时，即使组合结构不变也会显著变慢。 | setup 只保留合理的数据类别；算法比较必须包含整数时间尺度放大，以直接展示 ng-DSSR 相对 time-indexed 的扩展性。 |
| 提前与拖期权重 | 提高拖期相对代价会把内部日程整体前移，增加早到库存以换取较少迟到；权重估计误差可能改变最优顺序。 | 这是 TWET 模型的行为参数，但当前论文不需要再增加一个正式灵敏度。可在任务级结果中按权重解释哪些任务被外包。 |

由此，当前实验边界维持不变。正式管理分析仍只有允许/禁止外包和数量折扣两项；基础费率
只作为校准或小型稳健性。交期宽度、任务数、机器数、setup 和时间尺度用于描述实例结构、
算法适用范围及机制分组，不包装成额外的管理灵敏度。外包 lead time、承包商容量和 TWET
权重变化虽然在文献中常见，但会改变当前模型或核心目标，不纳入本轮实验。

### 15.6 外包率、求解难度与任务级外包画像

外包率还应作为解释 BPC 求解难度的重要结果变量。最优方案外包较多任务时，内部机器上
需要排序和定价的任务集合随之缩小，内部组合结构通常更简单；因此应同时报告外包任务率
`|O|/n`、外包 workload 比例、剩余内部任务数和内部 workload，并将其与 root 时间、总
时间、节点数、pricing 次数及 pricing 时间配对分析。这里不能简单写成“提高外包率必然使
算法更快”：最优外包率是价格、due window、惩罚权重和 setup 共同决定的内生结果。正式
结论应优先来自同一基础实例、仅改变外包情景的配对比较；跨实例分组只能作为相关性证据。
预计高外包率的退化实例较容易，真正困难的可能是内外部方案成本接近、外包比例居中的
混合区域，这一判断必须由最终运行结果验证。

外包结果统一从四个层次报告。成本层面至少分解 earliness、tardiness、outsourcing 三个
原始 component；当前目标中的 setup cost 另列，不能并入 TWET 后隐藏。服务层面报告
due-window 内完成、早到和迟到任务的比例，并补充平均/总提前量和拖期量。决策层面报告
外包任务数与比例、外包 workload、各机器任务数、工作量和负荷不均衡。结构层面回答
“什么样的任务被外包”，而不止给出总体外包率。

任务级画像应为每个 job 保存外包指示及其 processing time、due-window center/width、
earliness/tardiness 权重、未折扣外包成本，以及进入/离开该任务的 setup time/setup cost
摘要。后处理可按这些特征的分位组报告 outsourcing probability，并在同一实例和同一价格
情景内比较被外包与保留任务。若结果需要控制多种特征的共同影响，可再补一个解释性模型，
但分组描述和配对比较应作为主结果。目标不是重复“外包成本上升时外包减少”这种机械规律，
而是检验外包是否由内部 processing burden、due-window 冲突、TWET 权重、setup 影响和
外包价格的组合驱动。例如，只有数据支持时，才能形成“外包并不简单偏向处理时间最长的
任务，而更偏向内部负担较大且外包条件更合适的任务”这一类结论。

当前模型没有承包商排程、外部完工时间或 external lead time，因而不能分析“外部 lead
time 相对 due window 的位置”，也不能把该变量伪装成现有指标。现阶段可分析的是任务被
移出内部系统后的成本与结构效果；若以后显式加入外包交付时间，再将外部完工位置和外包
服务水平纳入同一任务级画像。上述分析所需的现有变量原则上可由实例数据、最终 schedule
和 outsourcing 结果在求解后计算，不应在 pricing/label 热路径中增加统计。

## 16. 2026-08-20 正式实验设计的进一步收口

本轮将关于纯调度规模、外包 formulation、价格响应、产能/due-window 交互、报价机制和
数量折扣的 349 行原始讨论完整保存在
[`2026-08-20-正式实验设计原始讨论与逐项分析.md`](2026-08-20-正式实验设计原始讨论与逐项分析.md)，
并在原文后逐项分析。核心调整是避免把所有因素做成一个全因子矩阵：纯调度算法扩展性、
两种外包 formulation 的效率、价格与生产环境的联合管理分析、有无数量折扣分别形成四层
证据；报价机制和 tariff 段数只作可选稳健性。

正式矩阵目前仍不能直接冻结。需要先完成两项不进入正式样本的 pilot：用
`n=20/40/60/80/100` 的代表 `(n,m)` 组合确认四种纯调度方法的共同可计算边界；用跨
setup、due-window 和产能环境的代表实例校准全局 `rho*` 与折扣强度。setup 强度与
setup 聚类结构必须分开定义，禁止外包作为独立配对基准而非数值上的无穷价格，基于
due-date 的 rush premium 报价在当前没有外部 lead time 的模型中不进入主实验。
